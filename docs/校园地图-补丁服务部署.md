## 3. 接口

### POST /map/api/patches
```jsonc
{
  "schema": 1,
  "mapVersion": "2026.11.14-1",
  "client": { "sid": "<学号，登录后才有>", "did": "<设备随机UUID>", "model": "V2301A", "appVer": "0.3.0" },
  "patches": [
    { "featureId": "f19", "field": "层数", "value": "3", "op": "set", "ts": "2026-11-14T15:40:00+08:00" }
  ]
}
```
- 头：`X-Api-Key: <CMAP_API_KEY>`（缺失 → 403）
- 单次 ≤200 条、≤256KB；单值 ≤200 字
- `featureId` 必须 `^f\d+(_\d+)?$`；`op` ∈ `set|delete|addField`
- 返回：`{accepted, rejected, reasons:[{featureId, field, reasons:[…]}], keys}`
- 限流：每贡献者 400 条/小时

### GET /map/api/snapshot?mv=<版本>
需 `X-Admin-Key`。只返回 `rev=1`（已人工审核）的合并结果：
`{mapVersion, fields:[…], features:{"f19":{"层数":"3"}}}`

### GET /map/api/health
`{ok, keys, ts}` —— keys 是内存里生效的 (mv,fid,field) 条数。

## 4. 身份与「可追溯但不泄露」（主人要求）

请求里带学号与设备 ID，**服务端只落两种派生值，明文一个字节都不存**：

| 字段 | 算法 | 用途 |
|---|---|---|
| `ch` | `HMAC-SHA256(CMAP_SECRET, sid|did)` | 判断「是不是同一个人」、限流、聚合贡献 |
| `sid_enc` | `AES-256-GCM(CMAP_SECRET, sid)`，带 `v1:` 前缀与随机 IV | **只有持 CMAP_SECRET 才能解回学号** → 可追溯 |
| `did_h` | `HMAC-SHA256(CMAP_SECRET, "did|"+did)` 前 16 位 | 同设备归并，不可反推 |

**实测验证**：提交带 `sid=SELFTEST-SID`、`did=probe-device-aaa` 的补丁后，
`grep -c 'SELFTEST-SID' patches.jsonl` 与 `grep -c 'probe-device-aaa'` **均为 0**。

**反查某个学号的记录**（只有服务器上能跑）：
```bash
cd /opt/campusmap/api
set -a; . ./env; set +a
# 用 sid 与疑似 did 组合算 ch，再到 jsonl 里 grep
python3 - <<'PY'
import hmac,hashlib,os
sec=os.environ['CMAP_SECRET'].encode()
for sid,did in [("2024xxxxxx","<设备UUID>")]:
    print(hmac.new(sec,f"{sid}|{did}".encode(),hashlib.sha256).hexdigest())
PY
```

## 6. 两个踩过的坑（Bun）

1. Bun 的 handler 收到的是**标准 `Request`**，没有 `req.on('data')` —— 必须 `await req.text()`。
2. 必须**返回 `Response` 对象**，不能用 Node 的 `res.writeHead/res.end`
   （症状：500 + `null is not an object (evaluating 'res.writeHead')`）。
