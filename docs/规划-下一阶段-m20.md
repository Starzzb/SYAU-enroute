## 0. 核查结论：三条与直觉不一致的事实

这三条会改变工作量估计，先说。

**① 地图捏合其实已经按捏合点缩放，不是中心。**
`CampusMapScreen.kt:364-365` 已经在算 `ax = centroid.x - cw/2f`，即以双指重心为锚。
所以「放大默认还是中心放大」这个体感，来源大概率是另外三处之一：

- **双击放大**走的是 `zoom *= 2`（无锚点，等价于以中心放大）
- **「重置视图」和缩放后的边界 clamp** 会把人拽回居中
- `panLimit` / `applyOverdrag` 把可拖范围收得太紧，让人以为"只能居中看"

**先定位再改**。如果是双击无锚点，那是几行的事；如果是 clamp 太紧，要改的是数值不是手势。
**不先定位就重写手势，很可能改完还是别扭。**

**② 缓存不是"完全没做"，是"只做了两处"。**
已经有两套 TTL：`UpdateManifest.shouldAutoCheck`（24 小时窗口）、`FacultyStore`（30 天 / 500 条 / 5MB）。
但**身份、成绩、考试、培养方案进度都没有分层** —— 每次冷启动全量重抓，这就是你感觉到的"每次都得重新读取"。

**③ 「关于」已经是独立页了。**
`UserScreen.kt:165` → `UserPage.About` → `ui/about/AboutScreen.kt`（含 GitHub、MIT、依赖、数据来源卡片）。
缺的是**入口位置**：设置页里还内嵌着一段「关于」文字。所以这条的工作量是"把入口挪到最后一行 + 设计收口"，不是从零做页面。

## 1. 分批

### P0-A 地图手势：按行业共识重做交互

目标行为（对齐高德/Google Maps/Apple Maps 的通行做法）：

| 操作 | 期望 | 现状 |
|---|---|---|
| 双指捏合 | 以**双指重心**为锚缩放 | 已是（364-365） |
| 双击 | 以**点击点**为锚放大一档 | 疑似无锚点（以中心） |
| 双指拖动 | 平移视图 | 待查 |
| 单指拖动 | 自由平移，到边界有**橡皮筋**，松手回弹 | 有 overdrag，但范围偏紧 |
| 惯性甩动 | 松手后按速度滑行并减速 | **没有**（这条是"别扭"的主因之一） |
| 缩小到最小 | 整图可见，不再继续缩 | 待查 |

**验收**：
- 在 4 角/中心各双击一次，放大后的锚点必须落在点击处（误差 < 40dp）
- 捏合缩放过程中，双指重心下的地块**不移动**
- 甩动后滑行距离与手势速度正相关，且 1.2 秒内停住
- 边界回弹有阻尼感，松手 250ms 内归位
- **不引入 panLimit 通配放宽**：能拖出去看空白是另一种别扭

### P0-B 缓存分层：永久 / 每日 / 每次

明确三档，写进 `docs/` 并在设置页「数据」区可见：

| 档 | 数据 | 策略 |
|---|---|---|
| **永久（读一次）** | 学号、姓名、院系、层次、入学年月、培养方案结构 | 首次成功后落盘，之后**永不自动重抓**；只在「清空数据」时失效 |
| **每日（静默一次）** | 「下一场考试」、成绩与绩点、空闲教室 | 冷启动时若距上次成功 > 24h 才抓，否则直读缓存；**失败不覆盖旧值** |
| **每次** | 资讯流、地图补丁、更新检查 | 保持现状 |

关键设计：**「下一场考试」不能只靠缓存时间判断**。它有时效性 —— 考完就该消失。
所以判据是「缓存时间 + 事件时间双条件」：距上次抓取 > 24h **或** 已缓存的下一场考试时间已过，才重抓。
手动刷新入口必须有（下拉 + 卡片上一点）。

**验收**：
- 冷启动且全部缓存新鲜时，网络请求数 = 资讯 + 地图 + 更新检查，**不含**身份/成绩/考试
- 断网冷启动，身份信息照常显示（不能因为抓不到就清空）
- 考试已过时间点的场景：缓存里那条不再显示「下一场考试」，而是触发一次重抓
- 「刷新」按钮单独可用，不强制全量

### P0-C 「帮助完善地图」开关搬到地图页

现在埋在 设置 → 最底部（在「关于」之后），要滚 5 屏。而它的作用对象就在地图页。

- 地图页导出栏加一个入口：未开启时显示「参与共建」，点了就地开（复用同一个确认弹窗）
- 设置页保留，作为"管理"入口（上传、预览、重置身份）
- **同一份状态，两处入口**，不能出现两个开关各存一份

**验收**：地图页开启后，设置页显示为已开启；反之亦然。

### P1-D 滚动记忆：进子页返回不回到顶部

现在每个列表各自 `rememberLazyListState`，进详情再返回就重建。

- 用 `rememberSaveable` + 把 state 提升到导航层，按 **route + key** 存档
- 只在**同级回退**时恢复；「切换学期/换筛选条件」应回到顶部（那是新内容，不是回退）
- 列表数据变化导致的 item 位移，用 key 稳定，不靠 index

**验收**：资讯流滚到第 30 条 → 进详情 → 返回，停在原处；改筛选条件 → 回顶部。

### P1-E 主题：开放调色板

现状 `ColorSource` 只有 `FIXED` / `WALLPAPER` 两值，`DynamicColors.override(base, primary, accent)` 已经能替换主色与强调色 —— **能力已经在了，缺的是入口**。

- 加第三档 `CUSTOM`：主色 + 强调色各一个取色器
- 给一组**预设色板**（从现有 `InkTokenSet` 的色阶里取，保证对比度达标），再允许微调
- **必须守住可读性**：选中色要实时算对比度，正文 < 4.5:1 时给出提示并禁止保存到该组合
  （这条不是审美洁癖 —— 之前 `primaryInk` 就是按 5.63:1 选出来的）
- 深色模式要各自独立保存，不能共用一组值

**验收**：任选一个色，重启后保持；选一个低对比色组合时**保存按钮禁用并说明原因**。

### P2-F 「关于」独立化并设计

- 设置页最后一行只留一行「关于沈农在途 ›」，点了进 `AboutScreen`
- 设置页里那段长文字删掉（现在同一句话在两处，改一处会忘另一处）
- `AboutScreen` 补：版本号 + commit + 构建日期（已有 buildConfig 字段）、更新检查入口、开源许可、数据来源、隐私说明

**验收**：设置页「关于」只有一行且可点；页面内能看到 commit 短码与构建日期。

## 3. 全局 agent 约定（写进 AGENTS.md）

> **功能按钮不自带长说明。**
> 一个按钮/开关只需要：它的名字 + 当前状态。凡是要解释"这个功能做什么、会传什么、有什么后果"的长文字，
> 一律挪到**点开后的弹窗或说明页**里，不在列表里堆 tip。
>
> 判断标准：一行文案超过 20 个字，就该考虑挪走。
>
> 理由：设置页现在有 6 处小字说明，用户得读完整页才知道哪个开关是干什么的 —— 那是文档，不是界面。
> **例外**：涉及隐私、付费、不可撤销操作时，**必须在操作前就近说明**（如共建上传的"会传什么"弹窗）。
> 这类说明允许长，但要放在**决策点上**，不是平时就铺在那。
