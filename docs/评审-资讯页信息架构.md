**不编造数据铁律（全文适用）**：界面只允许出现 `FeedItem` 真实字段可推导的内容——标题、摘要、来源、分类、`publishedAt`、`deadline`（解析成功才显示）、`readAt`、`starred`、`bodyFetched`、条数/未读数（可数）。**禁止**出现阅读量、点赞数、评论数、热度、「推荐」评分等任何无源数据。优先级只能由「真实截止日 + 频道固有顺序 + 用户已读/收藏状态」推导，不得引入算法重要性分。

## 2. 设计红线（继承 + 资讯页专项裁定）

继承 `HardTokens.kt` 三条红线，任何规格项违反即回退：

1. **圆角一律 0**。唯一例外：6dp 未读状态圆点（红线原文允许）。本规格所有卡片、菜单、对话框、按钮、输入框、提醒条均为直角。
2. **无渐变、无 elevation 阴影**。浮层立体感只允许 `Modifier.hardShadow`（2dp 实心偏移投影）；加载骨架**禁止 shimmer 渐变扫光**，用静态色块。
3. **数字全部 `NumericFont`（IBM Plex Mono，tnum/lnum）**：条数、未读数、日期、倒计时天数、菜单序号、徽标数。

补充裁定（资讯页专项）：

| 项 | 裁定 |
|---|---|
| 间距 | 只允许 `Space` 既有档位（2/4/8/12/16/20/24/32）。现有卡片内 5dp 间隙一律归一到 `Space.xs = 4dp` |
| 描边 | 四级制不跳级：网格线 1dp `rule`；卡片 1dp `outline`；浮层（菜单/对话框）1.5dp `outline`（`Stroke.strong`）；当前/紧急 2dp（`Stroke.emphasis`）或 3dp 色条（`Stroke.accentBar`） |
| 动效 | 只允许 `Motion.fast = 120ms` / `base = 180ms` / `slow = 240ms`，无回弹。列表内**不做逐条动画**；浮层滑入 180ms（与 `CourseQuick` 一致） |
| 字重 | 400/500/700/800，禁 300 及以下 |
| 主色面积 | 农械橘 `t.primary` 只做小面积：色条、点、选中填充、文字按钮；大面积永远是 `t.paper` / `t.card` |
| 主色文字对比 | `t.primary`（亮 #C74E17）对 `t.card` 实测约 4.36:1，**作为文字色时最小 14sp/700**（AA 大字号档 3:1）；小于 14sp 的强调文字改用 `t.brick`（7.4:1）或 `t.ink` + 主色图形前缀 |
| 图标语言 | 不用 emoji。沿用既有「方角字块」语言：⌕、✕、清、附、藏、⋯、▸/▾、› |
| 触区 | 一切可点元素触区 ≥ `Space.minTouch = 48dp`；视觉尺寸可小于 48dp，用透明 padding 补足触区 |

## 3. 信息层级方案

### 3.1 层级总纲（从「平铺」到「三层漏斗」）

```
第一层  待办层（有没有要误事的？）   → 截止提醒条（真实 deadline ≤ 3 天才出现）
第二层  分流层（去哪个频道处理？）   → 频道 chips（未读数驱动）+ 频道 meta 行
第三层  阅读层（读哪一条？）         → 分组 + 卡片流（已读退后、密度分级、渲染分页）
```

「全部」频道**保持时间倒序**，不做算法重排（时间线心智模型不可破坏，且无重要性数据源）。优先级通过第一层提醒条 + 第二层未读分流表达，而不是把列表打乱。

### 3.2 首屏纵向预算（360 × 800 dp 基准）

| 序 | 区块 | 高度 | 出现条件 | 规格要点 |
|---|---|---|---|---|
| 1 | 页头 | 52dp（上 padding `Space.s` 8 + 内容 36 + 下 8） | 常驻 | 见 §3.3 |
| 2 | 搜索行 | 48dp 触区行高（视觉 34dp 居中）+ 上间距 `Space.xs` 4 | 常驻 | 见 §3.4 |
| 3 | 截止提醒条 | 40dp + 上间距 `Space.s` 8 | 仅「全部」频道且存在 0 ≤ 剩余天数 ≤ 3 的竞赛 | 见 §8.4 |
| 4 | 结果/错误横幅 | 36dp + 上间距 4 | 刷新成功 4s 内 / 刷新失败常驻 | 见 §9.3 |
| 5 | 频道 chips 行 | 48dp 触区行高（chip 视觉 30dp 居中）+ 上间距 4 | 常驻 | 见 §4.1 |
| 6 | 频道 meta 行 | 28dp | 常驻 | 见 §4.2 |
| 7 | 列表 | 剩余 ≈ 512dp（无提醒条/横幅时） | 常驻 | 首屏约 3–4 张标准卡或 6–8 张紧凑卡 |

常驻 chrome 合计 ≈ 184dp（52 + 52 + 52 + 28）；提醒条（48）+ 横幅（40）全出现时 ≈ 272dp，列表仍 ≥ 424dp（≥ 2 张标准卡）。**首屏必须同时可见**：页头未读数、当前频道未读数、至少 2 张卡片、竞赛频道时至少 1 个分组头。

### 3.3 页头（改造现有 L124–158）

```
┌────────────────────────────────────────────┐
│ 资讯                          [刷新] [⋯]   │  20sp/800 ink
│ ● 86 未读 · 342 条 · 14:32 更新            │  11sp/15sp
└────────────────────────────────────────────┘
```

- 标题「资讯」：20sp / 800 / `t.ink`（沿用 `headlineSmall` 档）。
- 副标题一行，11sp / `labelSmall` 行高 15sp：
  - 未读段：前置 6dp `t.primary` 圆点 + 「86 未读」，文字 `t.ink` / 700，数字 `NumericFont`。**未读 = 0 时整段（含点）消失**。
  - 总数段：「342 条」`t.inkFaint`，数字 `NumericFont`。
  - 更新段：「14:32 更新」`t.inkFaint`，`NumericFont`，取 `SyncReport.at`（真实时间戳，VM 新增暴露，见 §10）；从未成功刷新则不显示该段。
  - 段间分隔「·」`t.rule`。
- 右侧按钮簇（间距 `Space.xs` 4）：
  - 「刷新」文字按钮：**14sp / 700 / `t.primary`**（从 12sp 升档满足对比裁定）；加载中文案「刷新中…」`t.inkFaint` 且禁用（沿用现有逻辑）。触区 48 × 48dp。
  - 「⋯」更多按钮（**P0 新增**）：视觉 32 × 32dp 方角，1dp `t.outline` 边，字符「⋯」14sp `t.inkSoft`，触区 48 × 48dp。打开页头菜单（§7.4）。

### 3.4 搜索行（改造现有 SearchRow）

```
┌──────────────────────────────┐ ┌────┐ ┌──┐ ┌──┐
│ ⌕  搜标题 / 关键词        ✕ │ │未读│ │藏│ │清│
└──────────────────────────────┘ └────┘ └──┘ └──┘
```

- 行高 48dp（触区），输入框与开关视觉高 34dp 垂直居中；水平 margin `Space.l` 16。
- 输入框：`t.card` 底，1dp 边（空词 `t.outline` / 有词 `t.primary`），文字 12.5sp `t.ink`，占位「搜标题 / 关键词」12.5sp `t.inkFaint`，⌕ 符号位 32dp，清除 ✕ 触区 32dp 视觉 / 48dp 行高。输入即筛本地，不发网络（保持现有契约）。
- 「未读」开关：视觉高 34dp、水平 padding `Space.m` 12，文字 12sp；选中 = `t.primary` 实底 + 700，文字亮色 White / **暗色 `Soil.n950`**（修复 D11）；未选中 = 透明底 + 1dp `t.outline` + `t.inkSoft` 400。
- 「藏」开关（**P1 新增**，surface 现有 `starred` 字段）：34 × 34dp 方角单字块，语言同「清」。选中 = `t.amber` 实底，文字 White / 暗色 `Soil.n950`；未选中 = 1dp `t.outline` + `t.inkSoft`。语义：只看 `starred == true`。与「未读」是 **AND** 关系。
- 「清」按钮：仅在 query / 未读 / 藏 任一生效时出现（扩展现有 `hasFilter`），34 × 34dp，一键清三个筛选。
- 360dp 宽度校验：输入框 weight(1f) ≈ 146dp + 未读 52 + 藏 34 + 清 34 + 间隙 4×3 + 边距 32 = 310dp ✓。

### 3.5 折叠与下沉清单（什么不占首屏）

| 内容 | 处置 | 理由 |
|---|---|---|
| 竞赛「已截止」组 | 默认折叠为一行组头（§8.2） | 死截止不占首屏 |
| 正文 | 维持点开才抓、详情页承载 | 既有契约 |
| 刷新成功报告 | 横幅 4s 自动收起，页头保留「HH:mm 更新」 | 成功是瞬态，不是状态 |
| 失败源明细 | 收进错误横幅「详情」浮层 | 首屏只给结论 + 动作 |
| 收藏列表 | 不做独立频道，用「藏」筛选 | 避免第 8 个频道稀释分流 |
| 正文缓存数 `bodyCount` | 不显示在资讯页（调试页已有） | 实现细节，用户无动作可做 |

## 4. 频道导航层

### 4.1 频道 chips（P0 改造）

- 顺序沿用 `FeedSources.CATEGORIES`：全部 / 竞赛 / 教务 / 就业 / 通知 / 学工 / 新闻（7 页，竞赛第 2 位保持）。
- **数字语义改为未读数**：
  - 「全部」chip = 全局未读；其余 chip = 该频道未读（`readAt == null` 计数）。
  - 未读 > 0：显示数字，9.5sp `NumericFont`；未选中时 `t.primary` / 700，选中时 White@75%（暗色 `Soil.n950`@75%）。
  - 未读 = 0：**不显示数字**（不显示 0，也不回退显示总数——同一位置只允许一种语义）。总条数下沉到 meta 行。
- 视觉：高 30dp，水平 padding `Space.m` 12，标签 12sp（选中 700 / 未选中 400），chip 间距 `Space.xs` 4，行内容水平 padding `Space.l` 16。
- 选中态：实底 = 该频道色（全部 = `t.primary`，其余 = 现有 `categoryColor` 映射），文字亮色 White / **暗色 `Soil.n950`**；未选中 = 透明底 + 1dp `t.outline` + `t.inkSoft`。
- 触区：chips 行高 48dp，chip 视觉 30dp 垂直居中，点击区撑满 48dp 行高。
- 交互：点 chip → `animateScrollToPage`（180ms，沿用）；左右滑页 ↔ chip 双向同步（沿用）。**长按 chip = 该频道全部已读**（P1 快捷路径，触发 §7.3 的频道级操作 + 撤销条；长按先给一次触感反馈，与课表一致）。
- 实现约束：`items` → `itemsIndexed` 消除 `indexOf`（D11）；保留 `LazyRow`（源会增长，不做定长 Row）。

### 4.2 频道 meta 行（P0 新增，chips 与列表之间）

```
竞赛 · 15 条 · 12 未读 · 按截止排序        [全部已读]
```

- 高 28dp，水平 padding `Space.l` 16。
- 左段 10sp / `t.inkFaint`，数字 `NumericFont`：`{频道} · {总条数} 条`；未读 > 0 追加 `· {未读} 未读`（未读数 `t.ink` / 700）；竞赛频道追加 `· 按截止排序`（解释排序心智，仅竞赛）。
- 右段「全部已读」文字按钮（**P0**）：**14sp / 700 / `t.primary`**，触区 48dp 高 × 内容宽 + 16dp。仅当前频道未读 > 0 时出现；点击立即执行频道级已读（§7.3），无确认框，出撤销条。
- 「全部」频道下右段按钮文案为「全部已读」，但语义 = **全局**，走确认框（§7.5）——文案相同、语义随频道，确认框兜底防误触。
- 筛选生效时左段替换为：`筛选中 · 命中 {N} 条`（真实过滤结果数），右段追加「清空筛选」12sp/700 `t.inkSoft`（与搜索行「清」等价，双入口）。

### 4.3 频道懒加载（P0，详见 §6.2）

- `beyondViewportPageCount` 1 → **0**：只组合当前页；切页才组合目标页。
- 每频道滚动位置 `rememberSaveable`（按频道 key 存 `LazyListState` 位置），切回不丢位置。
- 每频道渲染窗口独立（§6.1），互不影响。

## 5. 卡片规格：密度分级

### 5.1 分级策略

| 密度 | 默认频道 | 信息含量 | 目标 |
|---|---|---|---|
| **标准卡** | 全部、竞赛、教务、通知、学工 | 身份块 + 元信息 + 标题 + 摘要 + 底栏 | 高价值频道，读摘要即可决策 |
| **紧凑卡** | 就业、新闻 | 色条 + 标题 + 单行元信息 | 高频低价值频道，一屏 6–9 条快速扫过 |

- 密度是**频道级偏好**：初始默认如上表；用户在页头菜单（§7.4）切换只影响当前频道；持久化到 Prefs（§10.3）。
- 切换即时整列表重建（contentType 变化），不做逐卡高度动画；切换后出瞬态横幅「已切换为紧凑密度」（4s）。
- 两种密度共用同一数据行模型，`contentType` 区分（§11）。

### 5.2 标准卡（P0 精修，基于现有 FeedCard）

```
┌──────────────────────────────────────────┐
│ ┌────┐  教务通知 · 11-10          [藏] ● │  元信息行
│ │教务│  关于下学期选课的通知              │  标题 15sp/700
│ └────┘  各学院：现将下学期选课安排…       │  摘要 12sp，2 行
│ ──────────────────────────────────────── │  1dp 通栏线
│ 教务 · 剩 2 天                        › │  底栏 28dp
└──────────────────────────────────────────┘
```

| 部位 | 规格 |
|---|---|
| 容器 | `t.card` 底 + 1dp `t.outline` 边，0 圆角，无阴影；整卡可点（点开详情）+ 可长按（§7.3） |
| 体内 padding | `Space.m` 12 四边（紧凑卡除外，见 §5.3） |
| 身份块 | **32 × 32dp**（从 38 缩，省横向空间给标题）；底 = 频道色 @10%（暗色 @22%），边 1dp 频道色 @45%；字 = 分类前两字 10sp / 700 频道色 |
| 身份块→右列间距 | `Space.m` 12 |
| 元信息行 | 来源 10.5sp / 500 `t.inkSoft` maxLines 1；「·」10sp `t.rule`；日期 MM-DD 9.5sp `NumericFont` `t.inkFaint`；行尾右对齐依次：收藏标（§5.4）、6dp 未读点（§7.1） |
| 元信息→标题间距 | `Space.xs` 4（修复现有 5dp） |
| 标题 | 15sp / 行高 21sp / maxLines 2；**未读 700 `t.ink`，已读 500 `t.inkSoft`**（§5.3）；截断标题沿用现有 `titleTruncated` 补「…」逻辑 |
| 标题→摘要间距 | `Space.xs` 4 |
| 摘要 | 12sp / 行高 18sp / `t.inkFaint` / **maxLines 2**（从 3 降；100 字上限沿用，`sanitizeSummary` 沿用）；摘要为空不占位 |
| 通栏线 | 1dp `t.outline` @70% |

## 6. 按需加载交互

### 6.1 列表渲染分页（P0）

**事实前提**：数据层一次刷新已把各源列表页全量合并入库（本地上限 800 条，`items.json` 全量在内存）；源站翻页语义不一致（竞赛平台分页倒序，`FeedModels.kt` L161–162 注释），网络翻页本期不做（§14）。因此「列表分页」= **本地渲染窗口分页**，解决的是组合开销，不是流量。

| 项 | 规格 |
|---|---|
| 初始窗口 | 每频道 30 条（按可见行计：折叠组内条目不计入） |
| 触发 | 列表最后一个可见 item 索引 ≥ 已渲染数 − 5 时，窗口 +30；用 `remember { derivedStateOf { ... } }` 观察 `LazyListState`（禁 `produceState + snapshotFlow`，见 §11） |
| 追加性质 | 纯本地同步操作，**无网络、无 spinner**；追加不改变滚动位置 |
| 窗口重置 | 搜索词 / 未读 / 藏 筛选变化 → 重置为 30；刷新成功 → 窗口保持（不塌缩用户正在读的位置）；切频道 → 各频道窗口独立保持 |
| 分页脚·还有更多 | 高 48dp，居中「上滑加载 · 已显示 {X}/{N}」10sp `t.inkFaint`，数字 `NumericFont`，顶部 1dp `t.rule` 线 |
| 分页脚·到底 | 高 48dp，居中「已到底 · 共 {N} 条」10sp `t.inkFaint`，数字 `NumericFont` |
| 分页脚·加载中 | 仅未来网络分页启用：48dp 行内静态骨架条（§6.4）+「加载中…」12sp；本期本地追加不出现此态 |
| 筛选结果为 0 | 不显示分页脚，走 §9 空态 |

### 6.2 频道懒加载（P0）

- `HorizontalPager` `beyondViewportPageCount = 0`：相邻频道不再预组合。
- **派生列表上移到 VM**：每频道的「过滤 + 排序 + 分组 + 折叠展开 + 窗口切片」结果由 VM 按 `(items 版本, 频道, query, onlyUnread, starredOnly)` 缓存计算，UI 只读结果列表。现状在 pager 页组合体内裸 `filter`（D3）废除。
- 首次进入某频道才触发该频道派生计算；计算在 `Dispatchers.Default`（800 条排序分组 < 5ms 量级，但不得在主线程组合体内做）。
- 频道数据本身不做网络懒加载：刷新仍是全源合并（既有契约「单源失败不影响其他源」保持）。「按频道刷新」列 P2（§14），避免刷新语义分裂。
- 每频道 `LazyListState` 位置 `rememberSaveable`；进程重建后恢复频道 + 位置。

### 6.3 正文按需抓取（保持契约，修加载态）

- 契约不变：点开才抓 → 永久缓存（`feed/bodies/`）→ 二次打开 0 请求。
- **缓存命中不闪加载态**（修 D8）：VM 先同步查 `hasBody`，命中则直接以 `loading = false` + 缓存 payload 发布详情态；只有未命中才进入加载态。
- 详情页加载态规格见 §6.4；失败态见 §9.4。
- 详情页顶栏新增「藏」开关（§5.4）；「浏览器打开」保持。

### 6.4 加载态视觉规格（P0，统一骨架语言）

**红线：静态骨架，无 shimmer、无渐变、无循环动画。** 用 `t.rule` / `t.cardAlt` 实心块 + 一句真实状态文案。可选 `Modifier.furrows`（田垄线，既有 token）做空态底纹。

| 场景 | 规格 |
|---|---|
| 列表首抓（无缓存冷启动） | 3 张骨架标准卡：32dp 身份块（`t.cardAlt`）+ 标题条 2 根（高 12dp，宽 100% / 64%，`t.rule`）+ 摘要条 2 根（高 10dp，宽 100% / 80%）；卡间 8dp；骨架区上方居中「正在抓取…」12sp `t.inkFaint`。骨架卡不可点 |
| 刷新中（有旧数据） | **列表保持旧数据可滚动可点**；仅页头「刷新中…」+ 禁用刷新按钮；不遮挡、不插骨架 |
| 频道首次组合 | 派生计算为同步快操作，直接出结果，无中间态；若未来耗时 > 16ms 再引入单行「整理中…」12sp |
| 正文未命中缓存 | 详情页标题/身份行立即渲染（来自 item 真实字段）；正文区 3 根骨架条（高 12dp，宽 100% / 100% / 64%，间距 12dp，`t.rule`）+ 下方「正在读取正文…」12sp `t.inkFaint`；附件/链接区不渲染骨架（未知数量不编造） |
| 分页追加 | 无加载态（本地同步） |

### 6.5 刷新策略（P1）

| 触发 | 行为 |
|---|---|
| 冷启动 | 首帧不发网络（保持 `refreshIfEmpty` 契约）；仅空缓存时首帧后补抓 |
| 手动 | 页头「刷新」；进行中禁用重入（保持） |
| 回到前台 | 当前在资讯 tab 且距上次成功刷新 > 30 分钟 → 静默刷新一次（旧数据可见，无阻塞提示）；`lastSyncAt` 持久化 |
| 下拉刷新 | **不做**：HorizontalPager 横滑与下拉手势冲突，且硬朗体系无 Material 下拉指示器语言；刷新入口已常驻页头 |
| 刷新结果 | 成功 → 瞬态横幅「新增 {N} 条」（4s，§9.3）+ 页头更新时间；部分源失败 → 琥珀横幅「新增 {N} 条 · {M} 个源失败 [详情]」；全失败 → 锈红横幅「刷新失败 · 网络不可用 [重试]」，旧数据保留 |

## 7. 红点语义与消除操作

### 7.1 三级红点语义表（P0）

| 级 | 载体 | 语义 | 视觉 | 消失条件 |
|---|---|---|---|---|
| 条目 | 卡片元信息行尾 | `readAt == null` | **6dp 圆点 `t.primary`**（红线唯一圆角例外；从现有 5dp 归一） | 点开详情 / 长按标已读 / 频道级 / 全局级 |
| 频道 | chip 数字 + meta 行 | 该频道未读条数 | chip 9.5sp `NumericFont`；meta 行 10sp | 该频道未读 = 0 → chip 数字消失、meta 未读段消失、「全部已读」按钮隐藏 |
| 全局 | 底部 tab 徽标 + 页头未读段 | 全部频道未读总数 | 徽标（§7.6）；页头 6dp 点 + 11sp/700 | 全局未读 = 0 → 徽标消失、页头未读段消失 |

语义统一原则：**数字 = 未读，无数字 = 无未读**；任何位置不再用同一数字位表达总数。红点颜色一律 `t.primary`（关注），**不用 error 红**（未读不是错误）。

### 7.2 消除操作矩阵（P0）

| 操作 | 入口位置 | 文案 | 确认 | 反馈 | 撤销 |
|---|---|---|---|---|---|
| 单条已读 | 点开卡片（既有） | — | 无 | 点消失 + 标题降级 | 长按「标为未读」 |
| 单条已读/未读切换 | **长按卡片** → 底部菜单 row 01 | 「标为已读」/「标为未读」 | 无 | 菜单收起 + 卡即时变化 | 反向操作 |
| 频道级全部已读 | ① meta 行右「全部已读」按钮（当前频道未读 > 0 时）② **长按 chip** ③ 页头⋯菜单 row 01 | 按钮「全部已读」；菜单「本频道全部已读」 | **无确认**（可撤销） | 撤销条「已把「{频道}」{N} 条标为已读 [撤销]」5s | ✓ 撤销恢复该批 `readAt = null` |

联动规则：

- 「未读」筛选开启时执行频道/全局已读 → 列表清空 → 空态走 §9.2「都读完了」分支（**不是**「没有内容」）。

- 已读操作只改 `readAt`，**不动 `starred`、不动正文缓存**；确认框与撤销条文案必须明示「收藏不受影响」。
- 批量已读 = 一次状态发布 + 一次 `items.json` 写盘（§10.2），禁止逐条循环写盘。

## 8. 竞赛频道专项

### 8.1 分组与排序规则表（P0，修 D7）

分组依据 = 真实 `deadline` 解析结果 + 今天日期差 `d`（屏幕级取一次 `LocalDate.now()`，见 §11）：

| 组序 | 组名 | 判定 | 组内排序 | 默认状态 |
|---|---|---|---|---|
| 1 | 即将截止 | 0 ≤ d ≤ 7 | `deadline` 正序（最急最前）；同日按 `publishedAt` 倒序 | 展开 |
| 2 | 报名中 | d > 7 | `deadline` 正序 | 展开 |
| 3 | 时间待定 | `deadline` 空或解析失败 | `publishedAt` 倒序 | 展开 |
| 4 | 已截止 | d < 0 | **`deadline` 倒序（最近截止的最前，修复现有正序）** | **折叠** |

- 「时间待定」提到「已截止」之前（未知 ≠ 已死，仍可能可报名）。
- 「全部」频道中的竞赛条目不重新分组（时间线保持），但卡片底栏倒计时照常显示。
- 搜索/未读/藏筛选作用于分组前；过滤后空组不渲染组头。

### 8.2 分组头与折叠（P0）

- 组头规格同 §5.5（sticky、28dp 视觉 / 48dp 触区、计数）。
- 四个组头均可折叠；「已截止」默认折叠，其余默认展开。
- 折叠态组头：「已截止 · 12 ▸」；展开态：「已截止 · 12 ▾」。点整头切换，180ms 高度过渡可选（列表重建即时生效为默认，动画为 P2 润色）。
- 折叠状态 `rememberSaveable`（进程内记忆）；跨启动重置为默认。
- 折叠组内条目不计入渲染分页窗口（§6.1）。
- 组头计数 = 过滤后真实条数。

### 8.3 倒计时展示色阶（P0，细化现有 `deadlineText`）

位置：标准卡底栏分类之后（「·」分隔）；紧凑卡元信息行尾追加；详情页身份行下新增一行截止信息（12sp/700）。数字一律 `NumericFont`。**只有解析出真实日期才显示；解析不到 = 不显示倒计时，由「时间待定」组头表达，绝不编造日期。**

| d（剩余天数） | 文案 | 颜色 | 字重 | 语义档 |
|---|---|---|---|---|
| d < 0 | 已截止 {MM-DD} | `t.inkFaint` | 500 | 失效 |
| d = 0 | 今天截止 | `t.brick` | 700 | 紧急 |
| 1 ≤ d ≤ 3 | 剩 {d} 天 | `t.brick` | 700 | 紧急 |
| 4 ≤ d ≤ 7 | 剩 {d} 天 | `t.amber` | 700 | 警告（现有 ≤7 全砖红，改为阶梯） |
| d > 7 | 截止 {MM-DD} | `t.inkFaint` | 500 | 常规 |
| 空/解析失败 | 不显示 | — | — | 待定 |

- 紧急档（d ≤ 3）卡片**左边框升级**：标准卡/紧凑卡左侧追加 3dp `t.brick` 色条（紧凑卡替换原频道色条），这是「当前/紧急」描边档的合法使用；其余卡片不变。
- 倒计时不做逐秒/逐分 ticking：日期粒度为天，屏幕级今天基准在「刷新成功 / 回到前台 / 跨天（前台期间日期变化检测）」时重算一次；列表内禁止逐卡时钟（§11）。
- 详情页截止行完整格式：「报名截止：{yyyy-MM-dd}（剩 {d} 天）」，色阶同上；已截止显示「报名已于 {yyyy-MM-dd} 截止」`t.inkFaint`。

### 8.4 截止提醒条（P0，「全部」频道首屏第一层）

- **出现条件**：当前在「全部」频道，且存在 0 ≤ d ≤ 3 的竞赛条目（**与已读无关**——读过通知 ≠ 报过名）；且未被用户按「今日 + 条目集合」规则关闭。
- **位置**：搜索行与 chips 之间（首屏预算 §3.2 序 3）。
- **视觉**：高 40dp，水平 margin 16；`t.card` 底 + 1dp `t.brick` 边 + 左侧 3dp `t.brick` 实心条；0 圆角。
- **内容**（12sp，maxLines 1，ellipsis）：
  - 单条紧急：「{标题截 20 字}… 剩 {d} 天」——标题段 500 `t.ink`，倒计时段 700 `t.brick` `NumericFont`。
  - 多条紧急：「{N} 项竞赛 3 天内截止 · 最急剩 {d} 天」——N/d `NumericFont` 700 `t.brick`，其余 500 `t.ink`。
- **交互**：点条体 → 跳竞赛频道；单条时滚动定位到该卡（`requestScrollToItem`），多条时定位频道顶部。右侧 ✕ 关闭钮：视觉 28dp / 触区 48dp，12sp `t.inkFaint`。
- **关闭语义**：记录「当日日期 + 当前紧急条目 key 集合」到 Prefs；同日同集合不再出现；出现**新的**紧急条目或跨天 → 重新出现。关闭不是永久屏蔽。
- 竞赛频道内不重复显示提醒条（分组本身已表达）。

位置：搜索行与 chips 之间（与提醒条同槽位，二者并存时提醒条在上）；高 36dp，水平 margin 16；`t.card` 底 + 1dp 边 + 左侧 3dp 色条；文字 12sp maxLines 1。

| 态 | 边/色条 | 文案 | 动作 | 生命周期 |
|---|---|---|---|---|
| 成功 | `t.olive` | 新增 {N} 条（N=0 时「已是最新」） | 无 | 4s 自动收起（180ms 高度动画） |
| 部分失败 | `t.amber` | 新增 {N} 条 · {M} 个源失败 | [详情] 12sp/700 `t.amber` → §7.4 row 04 浮层 | 常驻至下次刷新或 ✕ |
| 全失败 | `t.brick` | 刷新失败 · {首条真实错误摘要，截 30 字} | [重试] 12sp/700 `t.brick` | 常驻至重试成功或 ✕ |

- 错误摘要只用 `SourceResult.error` 真实消息，不编造「服务器繁忙」之类无源文案；网络异常统一映射「网络不可用」（这是真实异常类别，不是编造）。
- 横幅出现时旧列表数据保持可见可交互（stale-while-error）。

### 9.4 详情页错误态（P1，修 D10）

| 场景 | 文案 | 动作 |
|---|---|---|
| 正文抓取失败（保持现有判断） | 「这篇取不到正文，可能是个 PDF。」12sp/19sp `t.brick`（沿用） | 按钮行：[重试] [浏览器打开]，各视觉高 34dp / 触区 48dp，1dp `t.outline` 边，文字 14sp/700 `t.primary`，间距 8dp |
| 重试中 | 按钮禁用 + §6.4 正文骨架 | — |
| payload 全空 | 「没有可显示的内容。」11sp `t.brick`（沿用）+ 同上按钮行 | — |
| 附件/链接 | 保持现有规格（附字块 20dp、下载 10.5sp/700 `t.primary`） | — |

### 9.5 分页与骨架的错误边界

- 本地分页不存在失败态（纯内存操作）。
- 骨架只在真实 loading 期间出现；loading 结束必须移除，禁止「永久骨架」。
- 刷新超时遵循 `FeedHttp` 既有 15s 连接 / 30s 读超时；超时按全失败横幅处理，不新增 UI 计时器。

### 10.1 FeedUiState 新增字段

| 字段 | 类型语义 | 说明 |
|---|---|---|
| `lastSyncAt` | 时间戳，可空 | 上次成功刷新时间（`SyncReport.at`），页头「HH:mm 更新」与前台 30min 策略用 |

### 10.2 VM / Repository 新增能力

| 能力 | 契约 |
|---|---|
| `markChannelRead(category)` | 批量置该频道未读条目 `readAt = now`；**一次状态发布 + 一次写盘**；返回受影响 key 集合供撤销 |
| `markAllRead()`（已有，接线） | 同上，全局；UI 接确认框 |
| `markUnread(keys)` / `undoRead(batch)` | 批量恢复 `readAt = null`；一次写盘 |
| `toggleStar(key)`（已有，接线） | 长按菜单 + 详情顶栏调用 |
| `setDensity(channel, density)` | 更新偏好 + 持久化 + 重建该频道派生行 |
| `loadMore(channel)` | 窗口 +30，重切派生行 |
| `setStarredOnly(bool)` | 筛选 + 窗口重置 30 |
| 派生列表计算 | 输入 (items, 频道, query, onlyUnread, starredOnly, 折叠态, 窗口, 今天日期)；在 Default 调度器计算；items 未变不重算 |
| `refreshIfStale()` | 前台回来且 > 30min 触发静默刷新 |
| 详情打开 | 先同步查缓存命中 → 直接发布内容态；未命中才发布加载态（修 D8） |

Repository 批量已读/撤销必须合并为单次 `saveItems`（现有 `updateItem` 逐条全量写盘，批量场景禁止复用 N 次）。

### 10.3 持久化（Prefs 键）

| 键 | 内容 | 重置时机 |
|---|---|---|
| `feed_density_{channel}` | 标准/紧凑 | 用户切换 |
| `feed_last_sync_at` | 时间戳 | 每次成功刷新 |
| `feed_deadline_dismiss_{yyyyMMdd}` | 当日已关闭提醒条的紧急 key 集合 | 跨天自然失效 |
| 折叠态 / 滚动位置 / 窗口 | `rememberSaveable`（进程内） | 进程重建恢复，跨启动重置默认 |

### 10.4 数据真实性审查点

- 所有数字（条数、未读、倒计时、失败源数、新增数）必须可从 `items` / `SyncReport` 直接计算。
- `deadline` 显示前必须解析成功；「时间待定」是状态陈述不是日期猜测。
- 更新时间来自真实刷新时间戳；无刷新记录不显示。
- 不新增任何无源字段（阅读量/点赞/热度/推荐分）。

## 11. 性能实现约束（Compose 规格，验收必查）

依据 jetpack-compose-performance 审计规则，本规格的实现必须满足：

1. **派生上移**：过滤/排序/分组/窗口切片全部在 VM 缓存计算；pager 页组合体内禁止裸 `filter`（修 D3）。`remember` 必须带全输入 key。
2. **Pager**：`beyondViewportPageCount = 0`；页 key 用频道字符串。
3. **Lazy 行**：全部行带稳定 key（`item.key` 字符串，Bundle-saveable）+ contentType（§5.5 五类）；密度不同的卡必须不同 contentType 以正确回收。
4. **chips**：`itemsIndexed` 替代 `items + indexOf`（修 D11）。
5. **分页触发**：`remember { derivedStateOf { 最后可见索引 ≥ 渲染数 − 5 } }`；禁止 `produceState + snapshotFlow` 包装同步派生；禁止对 `list.size` 包 derivedStateOf。
6. **批量已读**：单次状态发布 + 单次写盘；UI 乐观更新，撤销快照只存 key 集合（不存整条副本）。
7. **时钟**：今天日期在屏幕级取一次并作为参数下传；禁止逐卡 `LocalDate.now()` 循环/定时器；跨天重算由刷新/前台事件驱动。
8. **列表内无逐条动画、无逐 item LaunchedEffect/DisposableEffect**；骨架静态；浮层动画只在菜单级（180ms）。
9. **大列表模型用标准 `List`**（Strong Skipping 下 `===` 比较）；禁止给 feed 列表模型加 `@Immutable/@Stable` 或换 `ImmutableList`。
10. **Flow 收集**：Root 层 `collectAsStateWithLifecycle` 保持；详情 StateFlow 为轻量内存流，`collectAsState` 可接受；禁止在 lazy item 内收集共享 Flow。
11. **CompositionLocal**：`InkTokens` 在列表容器层读一次下传，禁止每卡重复查询。
12. **写盘**：`items.json` 沿用 tmp + rename 原子写（既有）；批量操作不得触发 N 次重写。

### 12.2 对比度与触区审查（验收必查）

- 亮色关键对：`t.ink`/card ≈ 15:1；`t.inkSoft`/card ≈ 9.45:1；`t.inkFaint`/card ≈ 6.36:1（Theme.kt 注释实测值）；`t.brick`/card ≈ 7.4:1；`t.amber`/card ≈ 4.8:1；White/`t.primary` ≈ 4.65:1（12sp 选中 chip 可用）。
- **`t.primary` 文字对 card ≈ 4.36:1 < 4.5** → 主色文字一律 ≥ 14sp/700（AA 大字号 3:1 档）；本规格所有主色文字按钮已按 14sp/700 标注。
- 暗色 `t.inkFaint`（#7E7468）对 card ≈ 3.9:1：暗色下 9.5sp 元信息为可接受边缘档，但**倒计时/错误/警告等关键信息暗色一律用语义亮色**（brick/amber dark，≥ 7:1），不得用 inkFaint 承载紧急语义。
- 暗色 chip 选中底为浅色系（primary #EA8F5E / amber #DDB84D / slate #A0B6BB / olive #BCC79B），文字一律 `Soil.n950`（对比 ≥ 7:1）；亮色 chip 选中底为深色系，White 对比 ≥ 4.5:1（最浅的 olive #3F5A2E 对白 ≈ 7.6:1）。
- 触区 ≥ 48dp 全量清单：chips 行、搜索行开关、页头按钮、meta 行按钮、组头（可折叠）、菜单行、横幅动作、提醒条 ✕、撤销、详情按钮。卡片整卡天然 ≥ 48dp。
- 语义无障碍：未读点 contentDescription「未读」；「藏」开关状态朗读「只看收藏，已开启/关闭」；倒计时朗读完整「距报名截止还有 N 天」；菜单行朗读动作名 + 副文案；撤销条为可聚焦动作。
- 字体缩放 200%：首屏预算区块高度按 sp 自适应，卡片 maxLines 不变（ ellipsis 兜底），chips 行横向滚动兜底，禁止固定高度裁切文字（页头/meta 行用最小高度而非固定高度）。
