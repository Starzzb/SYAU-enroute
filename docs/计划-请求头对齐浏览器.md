# 计划：把请求头做成与真浏览器一致

状态：**未执行**（2026-11-17 立项，等主人点头）
目标一句话：让 `10.2.0.47` 与 `pass.syau.edu.cn` 收到的请求头，和一台真机上的 Chrome 发出来的**没有可区分的差别**；业务语义、请求体、URL、请求数量、只读边界一律不动。

---

## 0. 为什么做、做到什么程度算完

现在请求头缺 `Accept-Language`、`Sec-Fetch-*`、`Origin`（POST）、`Connection`，且 `Referer` 几乎一律写死 `http://10.2.0.47/`。这些不是"会不会被封"的问题，是"如果哪天对方上了识别，我们连解释的余地都没有"。

**验收标准（唯一口径）**：抓一张对照表，同一批接口分别由「真机 Chrome 手动点一遍」与「App 发一次」发出，比对两边的请求头，**除 h2/多路复用与 `Cookie` 值本身之外，逐项一致**。

**明确不做**（越做越假，反而更容易被认出来）：

- 不伪造 `Sec-CH-UA` / `Sec-CH-UA-Platform` / `Sec-CH-UA-Mobile`（与 UA 稍有不符就是强指纹，宁可不发）
- 不改明文 HTTP 为 HTTPS（对方没开 TLS，改了直接 502）
- 不引入第三方 HTTP 库（OkHttp 会自己加一套头，反而更难对齐）
- 不改请求体、不加 `_t` 时间戳、不做 JS 执行模拟
- 不碰 `UpdateCenter`（它打的是 GitHub，UA 明确写 `SYAU-Enroute (personal student test build; update check)`，保持可识别）

## 1. 现状盘点（改动的确切落点）

发往校内服务的 HTTP 写手一共 **5 处**，各自独立设头，重复且不一致：

| # | 位置 | 用途 | 现有头 |
|---|---|---|---|
| 1 | `app/src/main/java/cn/dkarbon/enroute/data/UrpClient.kt:496-514` | 主通路（登录、课表、会话校验，自己跟 302，最多 8 跳） | UA / Cookie / `extraHeaders` / POST 时 Content-Type |
| 2 | `app/src/main/java/cn/dkarbon/enroute/data/UrpHomeApi.kt:982-1005` | 首页那批 GET | UA / Cookie / Cookie 手写 |
| 3 | `app/src/main/java/cn/dkarbon/enroute/data/UrpHomeApi.kt:1015-1035` | `postForm` 统一 POST | UA / Accept / X-Requested-With / Referer=`$URP/` / Content-Type |
| 4 | `app/src/main/java/cn/dkarbon/enroute/data/Academic.kt:491-516` | 诊断用 GET | UA / Accept / X-Requested-With / Referer=`$URP/` |
| 5 | `app/src/main/java/cn/dkarbon/enroute/data/Academic.kt:519-546` | 诊断用 POST | 同 4 + Content-Type |

UA 字符串**三份副本**：`UrpClient.kt:66`、`Academic.kt:148`、`UrpHomeApi.kt:32`，值都是
`Mozilla/5.0 (Linux; Android 13) AppleWebKit/537.36 (KHTML, like Gecko) Chrome/120.0 Mobile Safari/537.36`。

现有 `Referer` 取值只有四种：`$URP/`（三处）、`thisSemesterCurriculum/index`（`UrpClient.kt:275`）、`calendarSemesterCurriculum/index`（`UrpClient.kt:300`）、`$URP/index`（`UrpClient.kt:315`）、登录页 URL（`UrpClient.kt:155`）。

**缺项清单**（以真机 Chrome 的对齐目标）：

| 头 | 现状 | 目标值 |
|---|---|---|
| `Accept-Language` | 无 | `zh-CN,zh;q=0.9,en;q=0.8` |
| `Sec-Fetch-Site` | 无 | 同源 `same-origin`；登录页跳 CAS 那次 `same-site` |
| `Sec-Fetch-Mode` | 无 | XHR 类 `cors`；顶层导航 `navigate` |
| `Sec-Fetch-Dest` | 无 | XHR 类 `empty`；页面 `document` |
| `Sec-Fetch-User` | 无 | 仅顶层导航加 `?1` |
| `Origin` | 无 | POST 时 `http://10.2.0.47`（跨到 CAS 时 `https://pass.syau.edu.cn`） |
| `Connection` | 由 HttpURLConnection 决定 | 显式 `keep-alive` |
| `Accept` | 只有部分接口有 | 全接口统一 `application/json, text/javascript, */*; q=0.01` |
| `Referer` | 大部分是 `$URP/` | **按目标路径反推真实来源页**（见 §3） |

## 2. 实施步骤

### 步骤 A：建单一真源（不改任何调用点，先立规矩）

新建 `app/src/main/java/cn/dkarbon/enroute/data/UrpHeaders.kt`：

```kotlin
internal object UrpHeaders {
    val UA: String                        // 唯一 UA，删掉三份副本
    fun apply(
        conn: HttpURLConnection,
        path: String,                     // 目标路径，如 /student/rollManagement/rollInfo/index
        method: String,
        accept: String = JSON_XHR,
        hasBody: Boolean = method == "POST",
        nav: Boolean = false,             // true = 顶层页面导航（登录页、首页），false = XHR
    )
}
```

要点：

- `apply()` 一次把头都设上；`Cookie` **不在这里设**，仍由调用方传 —— 避免"统一入口顺手把 cookie 发给别的域"。
- 断言：`apply()` 只对 `10.2.0.47` 与 `pass.syau.edu.cn` 调用，其他 host 直接 `require(...)` 失败（防未来误用）。
- UA 里的 Android 版本改为运行时读 `Build.VERSION.RELEASE`（本机是 16），Chrome 版本保持常量 `120.0.0.0`。**决策点**：如果觉得设备差异会让问题难复现，就继续写死 `Android 13`——这一项**两种都合格**，默认选运行时读取，因为"全校几千台不同机型"才更像真的。

### 步骤 B：接入主通路（`UrpClient.kt`，风险最低、收益最大）

- `:502-506` 换成 `UrpHeaders.apply(conn, pathOf(currentUrl), currentMethod, hasBody = currentBody != null)`。
- `:226-228`、`:274-275`、`:299-301`、`:315`、`:155` 这几处 `extraHeaders` 里手写的 `Accept` / `X-Requested-With` / `Referer` 全部删掉，改由 `apply()` 按路径反推。
- `instanceFollowRedirects = false` + 手跟 8 跳这段逻辑**不动**（它要拿 302 的 Location 才能判断被踢回 CAS）。

### 步骤 C：接入其余四处

`UrpHomeApi.kt:982-1005` / `:1015-1035`、`Academic.kt:491-516` / `:519-546` —— 每处把 5–6 行 `setRequestProperty` 换成一行 `UrpHeaders.apply(...)`，其余逻辑不动。这一步只是替换，不新增行为。

### 步骤 D：`Referer` 按真实来源页反推

浏览器点"考试页 → 明细"时，`Referer` 是考试页；我们现在一律给首页，等于告诉对方"所有请求都从首页发出"。新增：

```kotlin
internal fun refererFor(path: String): String
```

映射（**只列已实测过的路径**，遇到没见过的路径退回 `$URP/`，不猜）：

| 目标路径前缀 | Referer |
|---|---|
| `/student/rollManagement/rollInfo/` | `/student/rollManagement/index` |
| `/student/courseSelect/thisSemesterCurriculum/` | `/student/courseSelect/index` |
| `/student/courseSelect/calendarSemesterCurriculum/` | `/student/courseSelect/calendarSemesterCurriculum/index` |
| `/student/examinationManagement/` | `/student/examinationManagement/index` |
| `/student/integratedQuery/scoreQuery/` | `/student/integratedQuery/scoreQuery/index` |
| `/student/integratedQuery/instructionPlanQuery/` | `/student/integratedQuery/instructionPlanQuery/index` |
| `/student/teachingResources/freeClassroom/` | `/student/teachingResources/freeClassroom/index` |
| `/student/curriculum/teacherCurriculum/` | `/student/curriculum/teacherCurriculum/index` |

映射表落成常量 + 单测，路径覆盖不到的**不臆造**——宁可给 `$URP/`。

### 步骤 E：频率与拒绝识别（唯一改行为的项，单独开关）

- 新增 `app/src/main/java/cn/dkarbon/enroute/data/UrpThrottle.kt`：同一 host 两次请求之间最小间隔 **150ms**（`Mutex` + `lastAt`），只包在 `UrpClient` 的发送点上。总请求数不变，最坏让一次全量刷新慢 ~1s（诊断 14 条慢 ~2s）。
- `403 / 412 / 429` 从"笼统失败"里拆出来：`ProbeCatalog.metaLine` 继续照实打状态码，另给界面一句「服务器拒绝了这次请求（403）」，不写"可能被风控"这类猜测。

### 步骤 F：发版

走开发通道 `0.6.1-dev.2` / `versionCode 272`（按 `docs/版本控制与发版流程.md` §2.1），不占 m27 的号。

## 3. 验证方案（不靠肉眼"感觉更像了"）

1. **JVM 单测抓头**：`app/src/test/java/cn/dkarbon/enroute/UrpHeadersTest.kt`，用 `com.sun.net.httpserver.HttpServer` 起在 `127.0.0.1`，把 `apply()` 的产物真发一次，断言收到的头集合：
   - 必含 `Accept-Language` / `Sec-Fetch-Site` / `Sec-Fetch-Mode` / `Sec-Fetch-Dest` / `Connection`
   - POST 必含 `Origin`，GET 不含
   - **不含**任何 `Sec-CH-*`（防止后人好心加回来）
   - `refererFor()` 八条映射 + 一条未知路径退回 `$URP/`
   - host 守卫：对 `example.com` 调 `apply()` 抛异常
2. **PC 对照**：`curl` 用同一套头发 `/student/rollManagement/rollInfo/index`，在校园网下对比 App 与 curl 的响应码与字节数（应同为 302 或同为 200）。
3. **真机**：诊断 14 条跑一遍，`DebugLog` 里新增一行"本次请求头名集合"（**只打头名，不打 cookie 值与密文**），与 §1 的目标表逐项核对。
4. **不回退业务**：`build-verify.bat` 全绿（现有 590+ 条测试 + 新增约 12 条），且装机后真机登录、课表、考试、成绩、培养方案、空闲教室六个场景各点一次，结果与改前一致。

## 4. 风险与红线

| 风险 | 处理 |
|---|---|
| 顺手把 `Cookie` 发到外部域 | `apply()` 不设 Cookie；host 守卫 `require` |
| 头设多了反而与 UA 冲突（如自己加 `Sec-CH-UA`） | 明确不做，单测断言"不含 `Sec-CH-*`" |
| `Referer` 反推错，导致接口 403/校验不过 | 未实测路径一律退回 `$URP/`；单测锁八条映射 |
| 节流把刷新拖慢 | 150ms 是最小间隔，只在同 host 连续请求时生效；先量一次改前后耗时写进 CHANGELOG |
| 日志泄密 | 新日志只打头名；`Cookie` 值与 RSA 密文继续不进日志（现有红线） |
