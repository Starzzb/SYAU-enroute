# 05: 研究 —— 学院官网的教师公开信息源与缓存方案（只出文档，不改代码）

**What to build:** 一份可直接开工的调研结论，回答三个问题：
1. 各学院官网上**教师个人公开信息**（职称、研究方向、邮箱、办公地点、指导研究生、开课情况）
   在哪些站点、哪些栏目、URL 规则是什么；
2. 这些页面能不能稳定解析（VSB 站群模板是否统一、有没有列表页/详情页两套、正文里字段是否规整）；
3. App 侧该怎么缓存（缓存什么、放哪、失效策略、体积上限、离线可见范围），
   以及**合规边界**（哪些算公开信息可缓存，哪些属于个人信息不该落地）。

**Blocked by:** None (can start immediately)

**Status:** resolved

## 已知线索（起点，不是结论）

  URL 规则 `info/{栏目ID}/{文章ID}.htm` 与 `list.jsp?...wbtreeid=XXXX` —— **写一个解析器能吃下几乎所有院系站**
- `docs/URP-学生端接口清单.md`：教务侧只有教师条目（姓名/工号/院系/职称），
  且「查看某教师课表」的路由尚未探明；官网正好能补上研究方向与联系方式
- 学生本人所在学院：土地资源管理属**土地与环境学院**，可作为第一个样本学院
- 校内站只在校内网或公网部分可达，需实测哪些域名对外公开

## Answer

**结论**：全校院系站同一套 VSB 站群，正文容器统一为 `vsb_content` / `v_news_content`
（变体 `WspDetailContent`），**一个解析器可通吃**；但 12 个实测详情页里 **3 个朴素提取失败**
（林学、牧医只拿到姓名；经管另一入口容器全未命中），必须「多模板兜底 + 失败就说失败」。

- 站点与栏目清单（17 个学院，路径各院自定义、需一院一配）：见调研文档 §1
- URL 规则：`info/{栏目ID}/{文章ID}.htm` 与 `content.jsp?...wbtreeid=&wbnewsid=`，见 §2
- 字段可得性（职称/学位/导师资格/研究方向 稳定；办公电话/邮箱/办公地点 常缺失）：见 §4
- 缓存：**按教师存结构化 JSON**（键=工号，退化 `姓名@学院域名` 哈希），TTL 30 天，
  失败保留旧缓存并标注时间，上限 500 条 / 5MB，见 §5
- 合规：robots 为 `Disallow: /`，仅个人测试构建；**个人手机号/QQ/私人邮箱不落地**，见 §6

详见 `docs/学院官网-教师公开信息源调研.md`（含 13 个样本与 7 个可复用探针脚本）。
