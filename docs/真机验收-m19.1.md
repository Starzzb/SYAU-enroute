## A. 主人提问的三件事

### A1 「课程没和网格对齐」——**确实是 bug，已修**

像素测量（567×1260 缩放图，对应 411dp 宽）：

| 项 | 修复前 | 修复后 |
|---|---|---|
| 横格线 y | 229, **366**, 523, **660**, 817, **953**, 1110 | 229, **387**, 523, **680**, 817, **974**, 1110 |
| 卡片 y 跨度 | 390–521（落在 S2） | 390–521（落在 S2） |
| 行底偏差 | 第一/三/五条线比实际行底**高 20–21px（≈14dp）** | 全部与行底重合 |

**根因**：`GridMetrics.yOfRow(i)` 只累加了「本行之前」的时段条数量
（`BigSession.entries.take(i)`），但版面里时段条是渲染在**该行前面**的 Column 子项，
第一条大节「上午」顶上也有条。于是 Canvas 画格线时整体上移了一个 `bandH`，
卡片（按 Column 真实布局走）自然和格线错开；错开量正好 = 14dp。

**修复**：抽出纯函数 `gridRowTop(i)`（`TimetableTokens.kt`），返回
`(行数, 时段条数)`，第一条大节返回 `(0, 1)`；`yOfRow` 用它，横格线统一走
`yOfRowBottom(i)`。小幽灵/推进条的坐标同源，一并修正。

**回归测试**：`GridGeometryTest`（6 条）钉死：每行都含本行所属时段条、行顶严格递增且
间距只能是 `rowH` 或 `rowH+bandH`、首行必须给「上午」条让位、最后一行行底 = 网格总高。

### A2 「日期侵蚀效果是否移植了」

**移植了，而且就是 CET6 那套语义**，但今天看不到：

- 侵蚀 = `eatProgress(大节, 现在分钟, 夏季/冬季)`，`nowMin` 走 **30s ticker**，
  同一门课从上课到下课，卡片从上往下被「吃掉」（掉色 + 圆形咬痕 + 裂纹），
  吃完留一道残痕 `EatenResidue`。
- **只在「今天」那一列生效**（与 CET6 一致：只有正在上的课才有「吃到哪儿」）。
- 今天（第 12 周 周五）课表是空的 → 今天列没有卡片 → 自然看不到侵蚀。
- 验证方式：`GridGeometryTest` 里 `侵蚀进度按时段起止线性推进`（0 → 0.5 → 1）
  与 `夏季作息下午整体推迟三十分钟`；真机想现场看，找一天今天列有课的时候看，
  或用调试参数冻住时间：
  ```
  adb shell am start -n cn.dkarbon.enroute/.MainActivity --ei debugMin 600
  ```
  （600 = 10:00，落在 3-4 节中间，今天有课时卡片会缺一半）

### A3 「有个显示当前时刻的推进条吗」

**原来没有——CET6 也没有。** `Tt.nowTick()` 在 CET6 里只定义了颜色函数，
**全工程 0 处调用**，等于「现在几点进行到哪」只能靠小幽灵的站位猜。

**这次补上了**（`TimetableScreen.kt`，画在卡片**之上**）：
- 今天那一列一条 1.5dp 主色横线，位置 = 与小幽灵同一个 `walkerY(nowMin)`
- 左端 3×6dp 方块起点 + 右端小圆点终点，不靠箭头
- 20:00 实测：线落在 9-10 节（18:30–20:10）靠下位置；
  像素测 `now-line y = 960`，理论值 `837 + 0.9×137 = 960`（20:00 在 1110→1210 分钟的 90% 处）——**一致**

## B. 真机另外抓到的两个 bug（也已修）

### B1 撤销条文案把 key 集合全打出来了（P1）
- 现象：点「全部已读」后，撤销条显示
  `已把全部 [news|1010|24386, news|1010|24385, …65 个 key…].size 条 标为已读`
- 根因：Kotlin 字符串模板写成 `"全部 $keys.size 条"` —— `$keys` 直接插值成集合，
  `.size` 变成字面量。应为 `"全部 ${keys.size} 条"`
- 修复：改花括号；全仓扫了一遍同类写法，**只有这一处**
- 复测：`已把全部 1 条 标为已读` + `撤销` ✓

### B2 我爱竞赛网正文抓成了侧栏推荐（P1）
- 现象：打开 NCIECC 那条，正文是一串别的比赛链接
  （「【数学竞赛】…华教杯…」「快来报名！2026 温暖中国…」）
- 根因：`GENERIC_BODY_MARKERS` 里没有 Discuz 的正文容器 `id="article_content"`，
  匹配落到了后面的 `class="content"` —— 那是侧栏推荐块
- 修复：`parseBodyJingsai()` 精确切 `<td id="article_content">` → 评论区/表格结束；
  顺手从 `.s zhaiyao` 取干净摘要、从 `.xg1` 取真实发布时间（列表无日期）
- 复测：`NewSourcesParseTest` 新增 3 条（正文含「大赛背景/主办单位」、不含「温暖中国/华教杯」；
  摘要与 2026-10-15 发布时间；无容器时回退不抛异常）——**全绿**
- 注意：修复前的错误正文会被「永久缓存」，已清应用数据重抓，旧脏缓存不再存在
