## 0. 结论（先看这段）

**主人对上一轮的判断是对的，而且是技术上可证的**：

`ScholarTokens.kt` 的文件头自述写着「这一套只改**色、线、面**，字族与字号阶梯原样沿用 `EnRouteTypography`」，`Theme.kt` 的 `EnRouteTheme` 在风格切换时只做两件事 —— 换 `InkTokenSet`、换 M3 `ColorScheme`；`HardShapes`（全 0 圆角）、`EnRouteTypography`、所有页面的 `Column`/`LazyColumn` 骨架**一动不动**。所以「学院纸本」必然是同一个 App 换配色，这不是执行不到位，是机制决定的：**`StyleSet` 这个开关的物理能力只到 token 值**。

这一轮给 **3 个方向**，每个方向都同时在票里写死的 6 层（布局骨架 / 组件形态 / 层级与强调 / 动效与反馈 / 字体排版 / 色板）上与现状不同，其中两个还改了**导航形态**（底部 3 tab 之一被替换）。

| 方向 | 一句话 | 骨架 | 导航 | 差异幅度 |
|---|---|---|---|---|
| **A 仪表舱（Bento Console）** | 单列卡片 → **2 列不等高磁贴网格**，大数字当家 | 2 列网格 + tile span | 底部 3 tab → **左侧 56dp 竖排 rail** | 6/6 层全改 |
| **B 校报头版（Editorial）** | 卡片 → **没有卡片**，只有版面线、分栏与字号阶梯 | 单栏报纸版式 + 2 栏数据区 + 表格行 | 底部 3 tab → **顶部三段式文字导航，无底栏** | 6/6 层全改 |
| **C 黏土校园（Clay）** | 卡片 → **凸起的软塑块 + 粉彩色块**，底部浮起胶囊 dock | 单列大块（96dp 起） | 底部 3 tab → **浮起胶囊 + 中央凸起按钮** | 6/6 层全改 |

**推荐：A 为主推，B 为备选，C 只保留为「差异化上限样板」**（理由与代价见 §9、§10）。
**A 真的和现状不同**，因为它改的是**信息密度节奏与导航占位**，不是颜色：一屏从「4 张等高卡片顺排」变成「6 个不同尺寸磁贴 + 左侧常驻 rail」，用户手指落点和视线路径都变了 —— 这是换色永远做不到的。
**不改的**：资讯页三层漏斗（票 05 已验收）、全部业务字段、`HomeModel`/`ExamRows`/`FeedViewModel` 派生层、数据诚实条款（空态/暂缺/不编数字）。

## 1. 为什么「换 token」这条路已经走到尽头

| 现状机制（证据） | 后果 |
|---|---|
| `Theme.kt` L165–177：`styleSet` 只决定 `InkTokenSet` 与 `ColorScheme` | 风格差异**上限 = 颜色差** |
| `Theme.kt` L182：`shapes = HardShapes` 硬编码，两套风格共用全 0 圆角 | 圆角、阴影、动效曲线**无法随风格变** |
| `Theme.kt` L181：`typography = EnRouteTypography` 硬编码 | 字号阶梯、字族**无法随风格变** |
| `HomeCards.kt` / `FeedScreen.kt` / `ExamScreen.kt`：布局写死在 Composable 里，无布局变体分支 | 哪怕加第三套 token，骨架仍然一样 |
| `StyleSet` 只有两个值（`HARD` / `SCHOLAR`）且语义是「语汇」 | 加第三种「语汇」不会带来第三种「结构」 |

**结论**：要「一眼看出是另一个 App」，必须把**布局、组件几何、动效参数、排版阶梯**从 `Theme.kt` 的硬编码里拆出来，变成与颜色并列的可切换轴（§11 给出落地路径）。这一轮的设计方案就是按「未来可切换的轴」来写规格的，而不是按「一次换色」写。

### 4.3 层级与强调规则

1. **数字是第一层级**：一屏里最大的字永远是数字（40sp/28sp），文字标签不超过 11sp。这与现状（标题 15sp/700 是最大字）完全相反。
2. **4 个语义色相分区**，颜色回答「这是什么区」而不是「这严重不严重」：
   - 学分/培养方案 → 绿 `#0F6B4F`（tint `#E7F0E9`）
   - 绩点/成绩 → 蓝 `#1E4E79`（tint `#E6EBF1`）
   - 考试/倒计时 → 橙 `#8F5F0B`（tint `#F7EEDA`）
   - 教室/资源 → 紫 `#5B3E7A`（tint `#EEE9F4`）
3. **紧迫度只允许用「色块加深 + 数字前加 ▍」表达**，不允许改成第三套颜色（避免「红=一切警告」把眼睛烧掉）。
4. **主强调色 `#0F6B4F` 只出现在**：进度条填充、rail 选中底、胶囊选中、可点数字。信息密度再高也不做整屏底色。
5. 层级顺序固定为：**数字(40/28) > 区域标签(11 宽字距) > 单位/底注(12/11) > 时间戳(11 灰)**。

### 4.4 动效与反馈

| 场景 | 规格 |
|---|---|
| 首次进入 | tile 按阅读顺序 stagger：**60ms/张**，`opacity 0→1 + translateY 8dp→0`，单张 **200ms** `cubic-bezier(.2,.7,.3,1)`；总时长 = 60×(n−1)+200 ≤ **480ms**（6 tile） |
| 按压 | `scale 1→0.97`，**120ms** `cubic-bezier(.2,.7,.3,1)`；抬起 160ms 回 1；**不做涟漪**（Compose 关 `indication = null`，改自绘 scale） |
| rail 切换 | 选中底块用 `animateDpAsState(180ms)` 位移，不用淡入淡出 |
| 页切换 | 240ms：旧页 `opacity→0 + translateX −8dp`，新页反向；**不做共享元素** |
| 加载（真实等待） | 骨架 = 同尺寸淡斑块（**尺寸与真内容逐像素等高**，满足 Content Jumping 约束）；**仅当等待 > 300ms 才切 shimmer**：`1250ms linear infinite`，高光带 `rgba(255,255,255,.55)` 宽 30% 斜 20° |
| 刷新成功 | 磁贴数字 `count-up` 320ms（仅数字变化时），无横幅 |
| 触感 | 长按磁贴 8ms 轻触（沿用现有 `HapticFeedbackType.LongPress`） |
| reduced-motion | 系统开启时：全部时长 → **0ms**（直接终态），保留按压的亮度变化（不位移） |

### 4.8 A 的代价（不许只写优点）

| 代价 | 量化 / 说明 | 缓解 |
|---|---|---|
| **信息密度下降** | 304dp 内容区下，135dp 宽的 tile 里 11sp 中文一行约 **11 字**。长课程名（「毛泽东思想和中国特色社会主义理论体系概论」= 22 字）必须 2 行 + 省略号，可读性比现状 15sp 单卡差 | 长文本 tile 强制跨 2 列（280dp → 约 23 字/行）；短标签档位只放能 ≤ 10 字的字段 |
| **阴影成本** | 每 tile 一层 `shadow` + `clip`，一屏 6 层。中端机（vivo V2301A）滚动 60fps 需实测；Compose `Modifier.shadow` 会额外生成 layer | 阴影只在**静态屏**用；列表滚动时用 1dp 透明边替代（视觉上近乎无差），滚动停止 200ms 后恢复 —— 或干脆用「1 层 `drawBehind` 画 3 段渐变条」的假阴影（成本 ≈ 0） |
| **双列 + 不等高在 Compose 的实现成本** | `LazyVerticalGrid` 需要 `GridItemSpan(maxLineSpan)` 手动跨列；瀑布流（1 列高度不同）Compose 原生**不支持 masonry**，需自己算列高（`StaggeredGrid` 是第三方库，本项目不引依赖） | 资讯页的「瀑布」降级为**等列不等高的两列分桶**：把条目按顺序交替塞进两个 `Column`，各自独立滚动高度自然不同 —— 不需要 masonry 库，也不需要 `LazyVerticalGrid`。这是本项目能做到的最接近瀑布的形态（代价：无单列回收复用，条目 > 200 时需分页，沿用票 05 的渲染分页即可） |
| **侧 rail 占掉 15.5% 屏宽** | 360 → 304dp；现状底部栏占高度，A 改占宽度。横屏/大屏（≥ 600dp）时 rail 很值，360dp 上是净损失 | 宽度 < 400dp 时 rail 降为 **44dp**（只剩图标，标签隐藏），内容区 316dp |
| **与「农学工具」调性的冲突** | 「仪表舱」是 SaaS/汽车仪表语言，比现状的「田间纪录本」更冷、更企业 | 保留农业色相（深农绿 + 土黄 + 陶紫），不做蓝白科技感；图标继续用「方角字块」语言（课/资/我/刷），不换线性图标集 |
| **动效预算上升** | 上限从 240ms → 480ms 编排 + 1250ms shimmer，对「快速扫一眼」不利 | 所有编排只在**首次进入**播一次（`rememberSaveable` 记已播），切 tab 回来不重播 |

### 4.9 A 最适合 / 不适合

- **最适合**：学业主页（核心）、空闲教室（房号 + 座位数天然是「数字 tile」）、成绩概览、考试倒计时。
- **不适合**：课表页（本身已是 5×7 网格，再套 bento 会变成网格套网格，且课表格子高度必须等分）、资讯长列表（双列读长标题吃亏，A 的资讯页是妥协形态）。

### 5.3 层级与强调规则

1. **字号阶梯是唯一层级工具**：26（刊名）/ 22（导语）/ 17（条目标题）/ 14（导航）/ 12（正文）/ 11（标签）/ 10（表头）。**颜色不参与层级**。
2. **颜色只表达极性**：`#8C1D18` 红 = 「需要你注意」（截止、未读、不及格）；`#1F5140` 绿 = 「已完成/通过」；其余全灰阶。**没有「区块色」概念** —— 与 A 的 4 色相正相反。
3. **结构性强调靠线与栏**：竖线分栏、横线分段、双线做刊头。眼睛靠**线**定位，不靠色块。
4. 数字**不主导**版面（与 A 正相反）：数字与正文同族同时（tabular 但那不是等宽族），只在导语里以「词」的身份出现（「106 / 165」读起来像句子的一部分）。

**两个刻意的、与现状相反的决策**：

1. **衬线标题**。库里的 Magazine Style / News Editorial 都把衬线放在标题上。但 —— **本项目的中文衬线不可靠**：`FontFamily.Serif` 在国产 ROM 上可能没有 Noto Serif CJK，一旦回退到黑体，「报纸感」就假（这正是 `docs/评审-考试与成绩页-v2.md` §8.4 已经踩过的判断，这里继承）。所以 B 的字族策略是**承压设计**：即使全部回退成黑体，B 仍靠「字号阶梯 + 版面线 + 分栏 + 表格」成立 —— **字族是增益，不是支柱**。验收时必须用「强制 sans 回退」跑一遍（§12 验收项 6）。
2. **数字取消等宽**（`tnum` 保留、`lnum` 关闭）。现状红线是「数字全部 IBM Plex Mono」，B 有意违反：报刊数字是比例的，等宽数字会让表格看起来像终端。**代价**：表格列宽不再自动对齐，必须靠固定列宽（§5.1 已给 62/66/加权/74dp）—— 这是用「布局成本」换「排版气质」。

| success / warn | `#8FBF9C` / `#D6B26A` |

### 5.7 三页在 B 里的样子

| 页 | B 的形态 |
|---|---|
| **学业主页** | 刊头（「沈农在途」+ 日期）→ 双线 → 顶部导航 → 导语（「学分 106 / 165，还差 59」）→ 2 栏数据（现加权绩点 3.42 / 通过 55 门）→ 红竖条「下一场考试」+ 课程 + 时间地点 → hairline → 「空闲教室」小节（第二教学楼 · 47 间，逐行房号+座位） |

### 5.8 B 的代价

| 代价 | 量化 / 说明 | 缓解 |
|---|---|---|
| **「可点」缺乏视觉暗示** | 没有容器，用户不知道一行是不是按钮。现状靠卡片边界天然表达 | ①整行触区 52dp + 按压变色 90ms（必须有）；②条目末尾统一 1 个 `›` 10sp 灰；③验收时用「三秒内说出这一行能不能点」做可用性抽测 |
| **表格 4 列在 360dp 会挤** | 62 + 66 + 加权 + 74 + 3×8 间隙 + 32 边距 = 258dp 固定列 → 课程列只剩 **70dp ≈ 5 个中文字**。「马克思主义基本原理」必然折 2 行，行高从 52 变 64dp | 定义双行模式：课程列允许 2 行 + 地点折到第二行第 2 列；或 < 380dp 时砍「座位」列（座位进详情浮层） |
| **中文衬线不可得（最大风险）** | 若 ROM 无 Noto Serif CJK，全部回退黑体，B 的「报纸感」掉一半。自备中文衬线字体 = 4–8MB APK 体积 + 许可审查 | 承压设计（§5.5）；如果主人接受 +6MB，可打包 1 个字重（思源宋体 Regular，约 5.6MB subset 后可到 ~2.8MB）作为可选字体包 |
| **数字取消等宽 → 表格对齐靠固定列宽** | 违反现状红线 3；列宽写死，字段超长即溢出（需要 `ellipsis`） | 表格列宽用 `TableColumnWidth` 固定值 + `maxLines=1` + 省略号；超出内容进详情 |
| **长文语境 vs 手机碎片时间** | 12sp/20sp 行高 1.65 的正文在 360dp 下每屏约 22 行；学生在地铁上刷资讯其实不吃「长读」 | 正文只给 2 行摘要（与票 05 一致），正文仍在详情页 —— B 只改变「摘要的排版」，不改变「点开才读正文」的契约 |
| **没有色块 = 扫读定位变慢** | A 靠 4 色相分区，眼睛 0.2s 就定位到「考试区」；B 必须靠标题文字读出来 | 只对 **3 处**保留红竖条（下一场/未读/截止），让「红 = 现在要处理」成为肌肉记忆 |
| **实现工作量** | 分栏、表格、双线刊头、pull quote 都要自己 `drawBehind`/`Row` 手搭，没有现成 Material 组件；资讯条目要重写（`FeedCard` 无法复用） | 工作量估计 ×1.4 于 A（见 §10.2） |
| **与「农学工具」调性的冲突** | 校报是「阅读」语汇，不是「操作」语汇。查空闲教室这种「立刻要答案」的动作在 B 里显得慢 | 主页不放 B；B 只用于资讯/考试/成绩三页（B 是**分页级**风格，A 是**App 级**风格 —— 这一点决定了推荐顺序，见 §9） |

### 5.9 B 最适合 / 不适合

- **最适合**：资讯流（最佳）、考试安排（表格天然合适）、成绩明细（一行一门，tabular 对齐）、学期成绩单。
- **不适合**：学业主页（缺「一眼看数字」的效率）、课表（格线太密，报纸线会和课表格线打架）、空闲教室（用户要的是 3 秒拿到房号）。

| 组件 | 规格 |

### 6.3 层级与强调规则

1. **尺寸与色块承担层级**：主数据块最大（116dp）、次级双块（108dp）、辅助信息小块。字号跨度比 A 小（12.5–34），因为「块的大小」已经在说话。
2. **粉彩回答「这是哪一类信息」**，与 A 的 4 色相同构，但**用实色块而非淡斑**：杏 `#FFE0CC`（学分）、鼠尾草 `#DCEBDA`（成绩）、雾蓝 `#E3E7F5`（考试）、奶油 `#FBEFC9`（资讯）。
3. **文字永远是暖深褐 `#2A2320`，永不纯黑**（黏土的软感来自「没有硬黑」）。
4. **强调 = 描边加粗 + 色块加深**，不用第三种颜色。危险/不及格才用红 `#B3261E`，且只做**文字色**，不做块底。
5. 层级顺序：**块尺寸 > 数字泡 > 标题(17sp/700) > 数值(34sp/800) > 正文(14sp) > 标签(12.5sp/+0.6sp)**。

### 6.4 动效与反馈

| 场景 | 规格 |
|---|---|
| 入场 | 块从 `translateY 12dp` → 0，**320ms** `cubic-bezier(.34,1.56,.64,1)`（回弹）；stagger **45ms/块** |
| 按压 | 见 §6.2，**90ms 下沉 + 220ms 弹回** |
| dock 切换 | 选中项图标 `scale 1→1.12`，**240ms** spring；中央钮按下时 `scale 0.92` + 旋转 90°（240ms） |
| 页切换 | 320ms：新页 `scale .96→1 + opacity` |
| 加载 | **三泡跳动**：3 个 12dp 圆点依次 `translateY −6dp`，每点 900ms 循环（`cubic-bezier(.34,1.56,.64,1)`）；**仅在 > 400ms 真实等待时出现** |
| 空态 | **绝对静止**：一块粉彩空块 + 一行说明 + 一个按钮，**不跳动、不呼吸**。理由见 §8.3 —— 空态跳动会让人以为「还在加载」，从而以为数据会自己出来 |
| reduced-motion | 全部回弹改 linear 或 0ms；三泡跳动 → 静态三点 |

**字族决策（诚实说明）**：黏土风格的教科书配方是圆体（如 Nunito、郑庆科黄油体）。但**中文圆体没有任何免费、体积可接受、跨 ROM 可靠的方案**：「幼圆」在国产 ROM 上时有时无，自带要 5MB+ 且授权复杂。所以 C **不承诺圆体**，改用「系统默认字族 + 大字号 + 宽字距 + 大行高 + 圆角几何」营造软感。**代价**：软感大约损失 30%，C 的「黏土」更多靠阴影与色块成立，而不是靠笔形。这一条必须写进验收：如果主人要真圆体，需先接受 +5MB APK。

### 6.8 C 的代价

| 代价 | 量化 / 说明 | 缓解 |
|---|---|---|
| **卡片边界对比度只有 1.25:1** | 亮边 `#FFFFFF` vs 粉彩 `#FFE0CC` = **1.25:1**（§7.4 实测），远低于 WCAG 1.4.11 的 3:1。若「块边界可辨」被视为必要信息，C 不合格 | 块边界**不承载语义**：块之间靠 **12dp 留白 + 相邻块不同色相**区分（色相差异 ΔE 明显）。若确实需要可辨边界，改用 accent `#8A3B0E`（在粉彩上 6.19:1 ✅）做 1dp 内描边 |
| **阴影层数最多** | 每块 = 3dp 亮边 + 内阴影 + 外阴影 + 圆角裁剪 = 4 层绘制；一屏 5 块。Compose 里内阴影必须自己 `drawBehind`（Material 无 inset shadow），每块 2 次 `Path` 操作 | 内阴影**只在静态块**用；列表滚动中降级为纯色块 + 外阴影（视觉差 < 5%，肉眼几乎看不出）；或预渲染 9-patch 背景（`ImageBitmap`），成本降到 0 |
| **粉彩在强光下失效** | 户外 90k lux 时，`#FFE0CC` 与 `#FFFFFF` 的感知差急剧缩小，块会「溶成一团白」 | 粉彩明度统一压到 **L\* ≈ 88**（当前 `#FFE0CC` L\*≈89，`#DCEBDA` L\*≈90，已较接近），并对每块加 1dp 深色内描边（`#8A3B0E` @12%）兜底 |
| **暗色模式黏土感难成立** | 内阴影在深色上看起来像「凹陷的按钮」（视觉上是「可按」还是「已按下」会反转认知） | C 的暗色降级为「**软平面**」：去掉内阴影，只留外阴影 + 色块；暗色下黏土隐喻主动放弃（诚实说明，而不是假装两套都成立） |
| **与「农学工具」调性冲突最大** | 玩具感 vs 田间工具。主人要的是「另一个 App」没错，但 C 会让「查空闲教室」像玩游戏 | 只在**引导页/空态/竞赛活动页**用满 C；主体页面建议只借 C 的「粉彩色块 + 大圆角」，不借泡泡与弹跳 |
| **实现工作量最大** | 内阴影自定义绘制 + dock 浮起 + 中央钮 + 弹簧动效 ≈ A 的 1.8 倍 | 见 §10.2 |
| **信息密度最低** | 首屏 4 块（现状 4 卡），但每块信息更少（大留白换软感）→ 学生要多滚 1.5 屏才看到空闲教室 | 只把「必须一屏看完」的 4 项放首屏（学分/绩点/考试/教室），其余下沉 |

### 6.9 C 最适合 / 不适合

- **最适合**：引导/登录页、空态、竞赛活动页、成绩「通过/未通过」这种情绪化呈现、低年级学生。
- **不适合**：成绩明细（粉彩干扰分数判读）、考试安排表（块状排不下 9 场）、课表（格子必须严谨）、任何「一眼要答案」的查询页。

## 7. 对比度实测值（自己算的，附计算依据）

### 7.0 计算依据

WCAG 2.1 相对亮度与对比度：

```
c_srgb = c8/255
c_lin  = c_srgb/12.92                     若 c_srgb ≤ 0.03928
       = ((c_srgb+0.055)/1.055)^2.4       否则
L      = 0.2126·R_lin + 0.7152·G_lin + 0.0722·B_lin
CR     = (L_light + 0.05) / (L_dark + 0.05)
```

门槛：正文（< 18pt / < 14pt·bold）**≥ 4.5:1**；大字（≥ 18pt 或 ≥ 14pt 粗体）**≥ 3:1**；承载信息的非文本图形（边框、状态点、图标）**≥ 3:1**。
本机用 bundled python 现算，同一脚本输出下文所有数字（可复现：`python -` + §7.0 公式）。**纯装饰性线条不适用 3:1**（WCAG 1.4.11 只管「识别组件/状态所必需」的图形），本文对每个 1.2–1.7:1 的线都标注了「装饰性」。

## 8. 数据诚实：三个方向各自怎么保证

数据诚实的**实现位置**不在 UI 层，而在 `HomeModel` / `ExamRows` / `FeedRepository` 这些纯函数里 —— 三个方向都**不改数据层**，所以 `countdownLabel()` 返回 `null` 时 UI 说「暂缺」、`creditLabel()` 在 `requiredXf = 0` 时不编分母、`gpaLabel()` 在 `weightedGpa == null` 时返回「暂缺」这些规则**天然继承**。下面只写**每个方向新增的表现层风险**与对应的硬规定。

### 8.1 通用铁律（三方向共用，不可协商）

| # | 规则 |
|---|---|
| D1 | 任何数字必须有真实来源。**没有来源的位置显示 `—`，不显示 `0`**。 |
| D2 | 空态必须**说出原因 + 给出下一步动作**（UX 库 Empty States：不许空白屏）。 |
| D3 | **空态绝不做「加载中」的视觉**（不跳动、不 shimmer、不呼吸）。空是结论，不是过程。 |
| D4 | 加载骨架的尺寸必须与真实内容一致（UX 库 Content Jumping）；骨架里**不放任何具体数字**（不放 `106`，只放灰块）。 |
| D5 | 「暂缺」用灰字（tertiary）+ 不加图标装饰；**不用感叹号、不用警告色**（缺数据不是错误）。 |
| D6 | 倒计时只有日期解析成功才出现；`daysUntil() == null` → 整块倒计时消失，不留「0 天」。 |
| D7 | 竞赛 `publishedAt` 本来就允许为空 → 界面显示「日期暂缺」，**不许用报名起始日顶替**。 |
| D8 | 绩点缺失显示「暂缺」，**不显示 0.00**；学分分母缺失时不画进度条（`HomeCards.kt` 现有逻辑，三方向都保留）。 |

### 8.2 A 的专项：大数字最容易说谎

| 风险 | A 特有表现 | 硬规定 |
|---|---|---|
| 40sp 的巨大数字**抢注意力**，读者默认它精确 | 「106」占了 1/4 屏 | 当数字是 `—`/`暂缺` 时，**字号必须降到 28sp 且用 tertiary 灰**，不允许「大号灰字」装作占位（大号灰字仍会被读成「有个数」）。规范：`missing → 24sp / 500 / tertiary`，与「有值 → 40sp / 800 / ink」形成明显落差 |
| 淡斑磁贴让人以为「已加载完成」 | 骨架块也是淡斑 → 与真实磁贴太像 | 骨架磁贴 = **无淡斑**、纯 `cardAlt` 底 + 3 条灰线；只有真实磁贴带语义淡斑。视觉差异 ≥ 明显 |
| 进度条 8dp 很显眼，64% 会被读成「64% 已确定」 | 分母缺失时若还画条 = 说谎 | 分母为 0 → **不画条**，只显示「已得 106 学分」+ 「需修学分暂缺」。条的位置留空（不占位），避免假条 |
| 色斑暗示「有数据」 | 空磁贴也有色 | 空态磁贴 = **无色斑**（`cardAlt` 底）+ 一句原因 + 一个动作按钮 |

### 8.3 B 的专项：没有容器 = 没有「空卡」可以解释

| 风险 | B 特有表现 | 硬规定 |
|---|---|---|
| 卡片能承载「空态文案」，版面线不能 | 一个空列表 = 一片空白 + 一条线，读者以为「App 坏了」 | 空态必须是**一条带框的内嵌区块**（B 里唯一允许有边框的元素）：1dp `#8A8375` 边、无底色、内边距 16dp、文案 14sp、「重试」按钮 14sp/700 红。**容器在这一个场景破例** |
| 表格行空 → 表头孤零零 | 考试表 0 行时，表头 + 空白很恐怖 | 表头下方直接显示「本学期暂无考试安排（需登录且在校内网）」+ 「接口诊断 ›」行（沿用 v2 评审的失败态要求） |
| 衬线标题 + 灰字容易读成「已经加载好的正文」 | 「暂缺」如果也用 17sp 衬线，会被当成正常条目 | 「暂缺」不用衬线：**12sp / 400 / 系统 sans / tertiary**，永远比正文小一档 |
| pull quote 里放截止日 → 显得权威 | 解析失败的日期放进去就成了假新闻 | pull quote 只在 `deadline` 解析成功时渲染；失败时整块不出现（不留空引号） |

### 8.4 C 的专项：可爱的空态等于「还在转圈」

| 风险 | C 特有表现 | 硬规定 |
|---|---|---|
| 泡泡、跳动、弹跳都像「加载中」 | 空态若用泡泡 = 用户等一个不会来的数据 | **空态零动效**（§6.4）。空态块 = 粉彩实色 + 静态图标 + 一句原因 + 一个实心按钮 |
| 粉彩色块天然「有内容感」 | 空白块看起来像「已经填了东西」 | 空态块**去粉彩**，用 `#F2ECE2`（中性暖灰）+ 1dp `#8A3B0E`@20% 内描边；只有真实数据块用粉彩 |
| 数字泡 76dp 直径太大，容不下「—」 | 大圆里一个破折号会很怪 | 「—」时**不画泡**：块内直接显示「学分暂缺」12.5sp + 「重新登录 ›」按钮。泡只属于真实数字 |
| 透明度表达已读（`opacity .72`） | 低透明度会被误读为「禁用/不可点」 | 已读卡 `opacity .78` **只作用于文字与摘要**，卡底色与阴影保持 100%；卡始终可点（不受 opacity 影响） |
| 弹跳动效会掩盖「刷新失败」 | 失败也弹一下，用户以为成功了 | **失败态永不使用弹跳/spring**，只用 90ms 直切 + 静止的红字；弹跳只属于「成功拿到新数据」 |

### 8.5 三方向的空态文案对照（同一个数据缺失，三种说法）

| 场景 | A（磁贴） | B（版面） | C（黏土） |
|---|---|---|---|
| 培养方案未取到 | `—` + 「需修学分暂缺 · 回课表页重新登录」+ 胶囊「去登录」 | 数据栏内：`—` / 标签「已得学分」/ 一行 12sp 灰「需修学分暂缺，需登录且在校内网」 | 块内无泡：「学分暂缺」+ 「连接校园网后刷新」实心按钮 |
| 本学期无考试 | 1×1 磁贴「暂无考试安排」+ ▼「接口诊断」 | 表头下一行 + 「接口诊断 ›」 | 96dp 空块 + 「查看已结束的 2 场」 |
| 资讯某频道 0 条 | 空网格区 + 「这个频道还没有内容 · 换个频道看看」 | 带框区块 + 同上 + 「全部频道」链接 | 空块 + 胶囊「去『全部』」 |

**三条文案都必须与 `HomeModel.freeRoomsEmptyHint()` 的写法同构**：说清「为什么空」+「下一步做什么」，且**区分三种原因**（真没有 / 会话失效 / 没生效）—— 这是票 02 已经定下的规矩，三方向不许简化成一句「暂无数据」。

## 9. 推荐结论

### 9.1 主推：A 仪表舱（Bento Console）

**为什么是 A**：

1. **它改的是结构，而且是最容易被「一眼看出」的那一层 —— 骨架和导航。** 用户打开 App 的第一个 200ms 感受是「左边多了一条竖栏、内容变成格子了」，这跟颜色无关。上一轮被判「只换配色」正是因为在骨架层面零变化；A 把 60% 的面积重新分配了。
2. **它顺手修掉了现状的对比度老债**（主色文字 4.37 → 6.49）。
3. **它可落地、可回退、可度量**：磁贴网格 = `LazyVerticalGrid` + `GridItemSpan`；双列瀑布 = 两个 `Column` 交替填（不需要第三方库）；阴影可降级为假阴影（`drawBehind` 3 段）→ 性能风险可控并可在真机实测。
4. **它与「农学工具」的调性冲突最小**（仪表盘语言 vs 田间纪录本，仍在「工具」范围内），不像 C 那样把工具做成玩具。
5. **它覆盖最多页面**：主页 / 空闲教室 / 成绩概览 / 考试倒计时 —— 这四页正好是「数字密集」页，bento 是天配。

### 9.2 备选：B 校报头版（Editorial）

**为什么 B 值得留**：

1. **它是与 A 唯一真正正交的路线**：A 让数字变小块，B 让文字变版面。二者不能用「同一个方向的深浅版本」互相替代。
2. **它在资讯页与考试表上比 A 更好**：票 05 的资讯页 IA 是「漏斗 + 分组 + 长标题」，本质上就是**编辑内容**，B 的版面线 + 字号阶梯正是为长标题设计的；考试表的 4 列对齐也是 B 的强项。
3. **它的实现风险集中在字族，而字族是可降级的**（承压设计，§5.5）—— 即使衬线回退，B 仍成立。

**为什么不全推 B**：B 是「阅读」语汇，不适合「3 秒拿答案」的主页（空闲教室、下一场考试）；且「可点性缺乏暗示」是它最硬的可用性弱点。

### 9.3 不推荐 C（但保留为差异上限样板）

- 粉彩 + 圆角 + 泡泡是**差异化最强的方向**，但它**把工具变成了玩具**，与「沈农在途」的定位冲突最大。
- 技术代价最高（内阴影自绘、暗色隐喻失效、强光下粉彩失效）。
- 唯一硬伤：卡片边界对比度 1.25:1，若「块边界可辨」被认定为必要信息，C 直接不达标。
- **建议**：C 的局部元素（大圆角 + 粉彩色块 + 中央凸起按钮）可以「借」给 A 的**空态/引导页/竞赛活动页**，但不作为全 App 风格。

### 9.4 如果主人想「一条路线全覆盖」

推荐组合：**A 为骨架（全局）+ B 为资讯与成绩两页的排版层**。这两者可以共存：A 定「网格与导航」，B 定「长文本页的字号阶梯与版面线」。这在实现上是两个独立的轴（布局轴 + 排版轴），§11 的 `LookSpec` 正好支持。

## 10. 落地路径（怎么和现有 `StyleSet` 共存）

### 10.1 核心判断：不能只加 token，必须加「布局变体」

现状 `StyleSet` 的物理能力只到颜色（§1）。要支持 A/B/C，必须新增**三个正交的轴**，并且**在屏幕级分发**（不在 item 级）：

```kotlin
// 新增：与颜色并列的「外观规格」
@Immutable
data class LookSpec(
    val layout: LayoutVariant,        // HARD / BENTO / EDITORIAL / CLAY
    val radius: RadiusScale,          // card/md/sm/pill
    val elevation: ElevationScale,    // none / soft / clay
    val stroke: StrokeScale,          // hairline / none / glow
    val type: TypeScale,              // 字号阶梯 + 字族
    val motion: MotionSpec,           // 时长 + 曲线 + stagger
)
val LocalLook = staticCompositionLocalOf { LookSpec.Hard }
```

- **`InkTokenSet` 保持字段不变**（1792 行课表代码零改动），三套新色板都实现同一个 `InkTokenSet` 形状 → 颜色仍然「换 token 就行」。
- **差异部分（圆角/阴影/字阶/动效/布局）走 `LookSpec`**，页面改读 `LocalLook.current`。
- **布局分发在屏幕级**：
  ```kotlin
  when (look.layout) {
      HARD      -> HomeScreenHard(ui)
      BENTO     -> HomeScreenBento(ui)      // 新文件
      EDITORIAL -> HomeScreenEdit(ui)       // 新文件
      CLAY      -> HomeScreenClay(ui)       // 可选
  }
  ```
  屏幕内部**不查 `LocalLook`**，`LookSpec` 作为 `@Immutable` 值参数下传（沿用 v2 评审 §10.4 的既有纪律）。
- **数据层、VM、派生纯函数一行不改**：`HomeModel` / `ExamRows` / `ScoreRows` / `FeedViewModel` 完全复用 → 数据诚实条款自动继承（这是本方案最重要的工程性质）。

### 10.2 工作量与顺序（每步可独立回退）

| 步 | 内容 | 估算 | 风险 |
|---|---|---|---|
| 0 | 抽 `LookSpec` + `LocalLook`，写 `LookSpec.Hard` 复刻现状（**零视觉变化**），跑全量单测 + 真机比对 | 1 人日 | 低（纯重构） |
| 1 | **A 学业主页**（`HomeScreenBento` + 6 个磁贴组件） | 2.5 人日 | 中（阴影性能需真机实测） |
| 2 | **A 空闲教室 / 考试倒计时**（复用磁贴） | 1.5 人日 | 低 |
| 3 | **A 资讯页**（三层漏斗行为不变，改双列分桶渲染） | 2 人日 | 中（分桶后需保 key/contentType 稳定，沿用票 05 的缓存策略） |

## 12. 明确不做

1. **不推翻资讯页三层漏斗**（票 05 结论仍有效）：三层结构、未读驱动 chips、截止提醒条、红点可消、渲染分页 30 条、频道懒加载 —— 三方向都只是换皮。
2. **不设计拿不到的数据**：阅读量、点赞、评论、热度、推荐评分、算法重要性分 —— 一个都不出现（`FeedItem` 无此字段）。
3. **不加新第三方依赖**（不做 masonry 库、不引字体档、不引 blur 库）。
4. **不改任何 app 源码、不跑 Gradle**（本票边界）。
5. **不做玻璃拟态**（理由见 §2.1）与**不做手绘风**（中文字族不可得）。
6. **不在暗色模式强推黏土隐喻**（C 暗色降级为软平面，诚实说明）。
