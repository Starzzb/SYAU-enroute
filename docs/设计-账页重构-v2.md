> 版本：v2　日期：2026-11-14

## 1. 设计立场（半页）

账页是什么：**一本带编号的账**。行有节次，列有抬头，每门课是一张贴在账页上的条目；
资讯、设置、我的三页沿用同一套纸墨语汇，只是把「课」换成「条目」。

它凭什么比 Material 默认更好读：
Material 默认靠卡片阴影把内容抬起来，制造的是「一堆浮在空中的板子」；账页把层级全部压进二维平面
——**纸底、色带、边线、留白、字重五样东西**，不模拟立体。读者要处理的只有「对齐关系」，
没有影子抢视线，也没有大渐变制造纵深。一句话：**账页让眼睛只做一件事：在纸面上找到下一行。**

由此推出四条硬约束，全文不重复解释：
1. 层级只用「面 / 线 / 字」表达，**禁用阴影与渐变**（§6）。
2. 所有视觉数值走 token，**禁裸值**（§2、§3、§4）。
3. 一切文字对比度 ≥4.5:1，大字标题 ≥3:1，分隔线 ≥3:1（§5）。
4. 主题切换只发生在启动时，**运行中不热切**（§8）。

## 2. 形状规范

### 2.1 圆角阶：六档语义 token，值由主题定

全仓圆角只有六个语义档，每个组件类固定读一档。档位值放进 `FormSpec`（已存在，加字段），
业务代码永远不写数字。

| 语义档（新 FormSpec 字段） | 用在哪类组件 | HARD 值 | LEDGER 值 | 理由 |
|---|---|---|---|---|
| `radiusNone` | 页面、通栏列表、表格行、分割区 | 0 | 0 | 表格与通栏是「账页本体」，不许弯 |
| `radiusMicro` | 徽标、状态点、缩略图 | 0 | 6 | 账页小徽 6dp 与旧 `EditorialShapes.small` 一致 |
| `radiusControl` | 按钮、输入框、筛选 chips、地图「帮助完善」按钮 | 0 | 6 | **按钮统一走这一档**——主人点名的「帮助地图按钮变圆角」即此类；HARD=0 即方钮 |
| `radiusCard` | 通用卡片 | 0 | 10 | 账页便签 10dp，与旧 `FormSpec.radiusCard` 一致 |
| `radiusCourseCard` | 课卡（已有字段） | 4 | 10 | HARD 4dp 是主人点名保留的局部例外，不动 |
| `radiusSheet` | 对话框、底单、浮层 | 0 | 14 | 账页浮层 14dp，与旧值一致 |
| `pillSize` | 胶囊、头像、轴牌（已有字段，直径） | 999 | 999 | 整圆，唯一允许的 999 |

规则：
- `999.dp` 只允许出现在 `pillSize` 与头像，**禁止**用于按钮、卡片、输入框。审计里 7 处 `999.dp` 全部收回。
- `2.dp`、`12.dp`、`13.dp` 这类散值不再作为圆角出现（2dp 是审计里 `LedgerTimetable.kt:317` 的裸值，删除）。
- 圆角不参与层级表达（§6）：它只描述「容器边界弯不弯」，层级靠面/线/字。

### 2.2 禁裸值：强制规则与可检查形式

**规则**：`RoundedCornerShape(`、`CircleShape`、`cutCorner`、`999.dp` 只允许出现在
`ui/theme/` 包内；`ui/` 其余文件一律读 `Form.current.radiusX` / `Form.current.pillSize`。

**检查形式 A（快速 gate，PowerShell）**：

```powershell
# 圆角裸值：期望输出为空
Get-ChildItem O:\dev\enroute-android\app\src\main\java\cn\dkarbon\enroute\ui -Recurse -Filter *.kt |
  Where-Object { $_.FullName -notmatch '\\ui\\theme\\' } |
  Select-String -Pattern 'RoundedCornerShape\(|CircleShape|cutCorner\(' |
  Select-Object Path, LineNumber, Line
```

**检查形式 B（JVM 单测，进 CI）**：新增 `ShapeTokenTest`，扫描
`src/main/java/cn/dkarbon/enroute/ui` 源文件（排除 `ui/theme/`），正则
`\b\d+(\.\d+)?\.dp` 出现在 `RoundedCornerShape(...)` 调用内即失败；并对 `FormSpec.Hard` /
`FormSpec.Ledger` 断言六个档位值 ∈ 上表。B 是最终裁决，A 是本地快查。

## 3. 字阶与行高

### 3.1 账页完整字阶表（唯一出口：`EditorialTypography` + 账页专用样式）

| 角色 | 样式名 | fontSize | lineHeight | 倍数 | 字重 | 字族/数字 | 用在哪 |
|---|---|---|---|---|---|---|---|
| 页头大数字 | `LedgerDisplay` | 28sp | 34sp | 1.21 | 700 | Serif + tnum | 「第 12 周」 |
| 标题 | `headlineMedium` | 22sp | 30sp | 1.36 | 700 | Serif | 页面主标题 |
| 小标题 | `titleLarge` | 17sp | 24sp | 1.41 | 700 | Serif | 条目/标准卡标题 |
| 次标题 | 新增 `subtitle` | 15sp | 22sp | 1.47 | 500 | Sans | 紧凑卡标题、分组头 |
| 正文 | `bodyLarge` | 15sp | 24sp | 1.60 | 400 | Sans + tnum | 长文正文、详情正文 |
| 次要 | `bodyMedium` | 13sp | 20sp | 1.54 | 400 | Sans | 摘要、列表副行 |
| 说明 | `labelMedium` | 12sp | 18sp | 1.50 | 500 | Sans + tnum | 元信息、日期、频道、截止 |
| 提示 | `labelSmall` | 11sp | 16sp | 1.45 | 500 | Sans | 脚注、抬头微标签 |
| 数字 | `LedgerNumeric` | 13sp | 20sp | 1.54 | 400 | Serif + tnum | 表/轴/成绩数字 |
| 课表格内 | 新增 `gridCell` | 10sp | 14sp | 1.40 | 500 | Sans | 课表格内文字**下限** |

### 3.2 为什么这样分档

- **正文 15/24 = 1.60**：审计把舒适带定为 1.5–1.8，现状 body 是 1.43–1.46，低于下限。
  取 1.60 是带内中点偏上；15sp 比 16sp 每屏多约一行，保住列表信息密度。
- **数字 13/20**：与「次要」同字号同高，只换字族（Serif + tnum），保证时间列/成绩列竖向对齐，
  又不制造第二套字号。
- **提示 11/16 = 1.45**：微标签允许贴 1.4 下沿（审计把 1.37 判「略挤」、1.4 作界）；
  **删除 9sp `LedgerMicro`**——9/12=1.33 低于界。
- **课表格内 10/14 = 1.40**：直接落实审计 S3 的「最小字号 ≥10sp、行高 ≥1.4」。
  现行 7.5/8/8.5/9.5sp 全部作废。
- **标题系 1.21–1.47**：审计 P5 判标题 1.2–1.4 属设计选择，放宽到 1.47 是给「次标题」两级跳留位。
- **分级逻辑不变**：同屏最多出现 3 级字号，跨级才换尺寸；字重只允许 400/500/700。

### 3.3 课表格内几何与字号的冲突（诚实的约束）

课表列宽 51.9dp（411dp 屏，7 列），10sp 中文 ≈ 4 字/行。**10sp 下限与「课名+教室+教师三行」不可兼得。**
第一版取：**两行制**——第 1 行课名 `gridCell` 10sp，第 2 行「教室·教师」合并为一行 `gridCell` 10sp（inkSoft）；
放不下就省略号，完整信息进 `CourseDetail`。是否够放待真机实测；
若实测仍挤，接受「只显示课名 + 省略号」，不再降字号。

### 3.4 禁裸值检查

`fontSize = xx.sp` / `lineHeight = xx.sp` 只允许出现在 `ui/theme/`。JVM 测试 `TypographyTokenTest`
扫描 `ui/` 非 theme 源文件，命中 `fontSize` / `lineHeight` 裸值即失败；
同测试断言 `EditorialTypography` 各档 = 3.1 表。改造期先允许白名单逐批清（§9）。

## 4. 间距节奏

### 4.1 基数与阶梯

基数 **4dp**，节奏 **8dp**。全仓间距取值只有：
`{ 0, 2, 4, 8, 12, 16, 20, 24, 32, 44, 48, 56, 80 }`
（`2` 只用于图标-文字微距与 1dp 线的补偿；`44/48/56/80` 是既有 `timeColumn/minTouch/appBar/bottomBar`）。
审计里的 `3/5/6/7/9/10/11/13/14/18/22/26/27/28/30/34` 全部收敛或删。

### 4.2 各档用在哪

| 档 | token | 用在哪 |
|---|---|---|
| 2dp | `Space.xxs` | 图标-文字微距、线旁补偿 |
| 4dp | `Space.xs` | 色帽、状态点内距 |
| 8dp | `Space.s` | 行内元素间距、字段标签-输入框 |
| 12dp | `Space.m` / `cardGap` | 卡片间距、输入框内边距 |
| 16dp | `Space.l` / `gutter` / `cardPad` | **页面左右边距、卡片内边距** |
| 20dp | `Space.xl` | 表单字段间、块内大间隔 |
| 24dp | `Space.xxl` | 内容区块间距、次要正文段间距 |
| 32dp | `Space.huge` | **正文段间距**、页尾收束 |
| 48dp | `minTouch` | 列表项最小高、触区下限 |
| 56dp | `appBar` | 带说明的设置行高 |
| 64dp | 新增 `rowTall` | 双行卡列表项高 |

### 4.3 段间距 > 行距（硬规则）

**段间距 = 行高 × 1.2–1.5，取最近的 8 档。**
- 正文行高 24sp → 段间距 32dp（1.33×，修复审计 S1 的 0.56×）。
- 次要正文行高 20sp → 段间距 24dp（1.20×）。
- 规则并入 `TypographyTokenTest`：对 3.1 表每档断言「同屏段落 spacing ≥ 行高 × 1.2」。

### 4.4 禁裸值检查

JVM 测试 `SpaceTokenTest` 扫描 `ui/` 非 theme 源文件，提取所有 `.dp` 数字，
断言 ∈ 4.1 允许集（`Space.*` 之外的字面量仍算裸值，逐批清）。

## 5. 色彩与对比度

### 5.1 下限表（账页亮/暗，实算值来自审计 §1.3）

| 角色 | 门槛 | 账页亮色实测 | 账页暗色实测 |
|---|---|---|---|
| 正文 `ink` | ≥4.5 | 15.49 ✅ | 15.33 ✅ |
| 次要 `inkSoft` | ≥4.5 | 8.73 ✅ | 10.88 ✅ |
| 说明/提示 `inkFaint` | ≥4.5 | 5.36 ✅ | 6.99 ✅ |
| 大字标题（≥18sp 或 ≥14sp bold） | ≥3.0 | — ✅ | — ✅ |
| 分隔线 `outline`（非文字） | ≥3.0 | 3.21 ✅ | 3.98 ✅ |
| 主色当文字 `primaryInk` | ≥4.5 | 9.33 ✅ | 8.55 ✅ |

### 5.2 与 CustomPalette 共存：换色后下限怎么保证

事实：用户只能换 `primary` / `accent`（`ColorSource.CUSTOM` 走预设+微调，`WALLPAPER` 走系统取色），
`ink / inkSoft / inkFaint / rule / brick / olive / amber` **永远不动**（`DynamicColorRules.override` 只 copy 两个字段）。
所以 5.1 表里除「主色当文字」外，全部下限由主题出厂色板保证，与用户换色无关。

「主色当文字」这一格，按三档来源分别保证：
1. **固定**：账页 `Pine` 9.33 / 8.55，出厂即达标。
2. **自定义**：`PaletteGate` 保存前校验。现有五对（主色/纸底、主色/卡片、按钮字/主色、强调/纸底、强调/卡片）
   **扩为七对**：新增「主色/cardAlt ≥4.5」「强调色/cardAlt ≥3.0」——账页多出 `cardAlt`（分节色带底）与
   `bandTint`（交错行带）两种底；bandTint 与纸底明度差 ≈1.5%，是否可辨待真机实测，
   若不可辨则删 `rowZebra` 或把 bandTint 调深，故闸门以 cardAlt 为代表，bandTint 不单列。
3. **壁纸**：无闸门，运行时 `PaletteGate.inkVariant` 按色相不动、明度每步 3% 朝远离纸底方向推，
   直到 paper 与 card 两底都 ≥4.5（现有实现已做，保留）。

验收单测：`PaletteGateTest` 锁七对关系、`PrimaryInkContrastTest` 锁「主色当文字 ≥4.5」、
暗色用暗色底校验（现有 `base.isDark` 分支保留）。

### 5.3 已确认的对比度缺陷，本规范直接修（审计 S2 / M1 / M2）

| 缺陷 | 现测 | 修法 |
|---|---|---|
| 课表进行中课程被 92% 纸色侵蚀遮罩压文字 | 1.17:1 | 遮罩不压文字区（只压色帽/背景），或 alpha ≤0.35；最终以文字区 ≥4.5 为准 |
| 已上完便签课名 `inkFaint@55%` | 2.19:1 | 改全不透明 `inkFaint`，划掉语义改「删除线」表达，不降 alpha |
| 暗色新闻/就业分类徽（22% 混色底） | 3.90 / 4.28 | 混色底 alpha 22% → ≥32%，或徽文字换暗色对应变体 |

## 6. 层级手段（不用阴影、不用大渐变）

账页只有四个层级，每个层级固定一种手段，不混用：

| 层级（底→高） | 手段 | 具体 token | 备注 |
|---|---|---|---|
| L0 页面底 | 纸色 | `paper` | 永远最弱 |
| L1 分区（上午/下午/晚上、分组头） | **填充色带** | `cardAlt` 14dp 高 `bandRule` | 面积区分，不是线；宽度占满 |
| L2 条目/卡片 | **1dp 边线 + 色差** | `outline` 描边 + `card` 面 | 卡比底亮一档，靠边线咬合，不靠影子 |
| L3 强调（今天、进行中、选中） | **主色短边线/色条 + 字重** | `primary` 2–3dp 左边线、`accentBar` | 只占一条边，不整块填充 |

补充规则：
- 行与行之间**不画横贯横线**（`noRowRules`），靠留白 8dp + 交错行带（可选）。
- 文字层级只允许三级：`ink / inkSoft / inkFaint`，外加字重两级（400 / 700）。同屏 ≤3 级字号。
- **删除 `cardFloat` 对账页的调用**（`EditorialTokens` 里两处 feed + `LedgerTimetable` 一处）：
  审计已证明阴影是「浮在纸上」的唯一线索，而本规范把层级交给边线与色带后，这层线索多余，
  且与「统一」冲突（HARD 无阴影、账页有阴影）。`FormSpec.cardShadow` 账页改 false，函数保留不删。
- 禁止清单：`shadowElevation`、`tonalElevation`、`Brush.*Gradient`、大面积主色填充、
  半透明遮罩压文字（§5.3）。
- 「哪都有点圆角、哪都没层级」的解法：圆角只描述容器边界，层级只由 L0–L3 四行决定；
  一个组件先定它是哪层，再定它的圆角，两者不互相替代。

## 7. 搜索（全局）

### 7.1 入口与视觉位置

首页顶部（`HomeCards` 上方）放一条全宽搜索条：高 44dp，左对齐占位文字
「搜教师 / 教室 / 地点 / 设置」，圆角走 `radiusControl`。不做只露放大镜的紧凑入口——搜索是本规范的点名功能，
要给足面积。

### 7.2 交互

1. 点击搜索条 → 进全屏搜索页。
2. 输入 1 个字符即出结果（本地小数据，不节流）。
3. 结果按四类分组：**教师 / 教室 / 地点 / 设置**，组头用 `labelSmall` 抬头样式，
   结果行高 56dp，主行显示名称、副行显示归属（如「教师 · 信电学院」「教室 · 第一教学楼 302」）。
4. 点击结果跳转：教师 → `TeacherDetailScreen`；教室 → `RoomsScreen` 对应项；地点 → `CampusMapScreen`
   定位到 POI；设置 → 对应设置分组（滚动定位，不新开页）。
5. 空态：显示「没有匹配的 X」；无输入态显示提示「输入教师名 / 教室号 / 地点名 / 设置项」。

### 7.3 最少实现程度

- 数据源 = 本地已有列表：教师列表、教室列表、地图 POI 名称、设置项标题表（静态清单，不进网络）。
- 匹配 = 大小写不敏感的子串匹配（中文按字符包含），先不做拼音、不做模糊纠错。
- 设置项搜索只匹配「设置项标题」，不匹配说明文字（说明已按 AGENTS.md 移出列表）。
- 不做历史记录、不做热门搜索。这两项留待搜索页上线后看使用数据再加。

## 8. 主题切换可重启

### 8.1 实现路线

1. **启动时一次性构建**：`Application` / `MainActivity` 启动阶段从设置仓库读出
   `styleSet / themeMode / colorSource / customPalette` 四个值，作为 `EnRouteTheme` 的入参传入。
   token、typography、shapes、FormSpec 全部在 `setContent` 之前定死，不进任何 Compose state。
2. **运行中不热切**：设置页点选主题后，只写设置仓库 + 置 `pendingRestart` 标记，**不**触发
   `EnRouteTheme` 重入、不重建 CompositionLocal。
3. **退出重载**：保存后弹一行提示（文案见 8.2），并给「立即重启」按钮。
   立即重启 = `startActivity(launchIntent)` + `finishAffinity()` + `Process.killProcess(Process.myPid())`
   （不引第三方库；这就是「允许退出程序重新加载」的最小实现）。
4. 主题构建逻辑保持纯函数（`baseTokenSet` / `FormSpec.of` / `PaletteGate`），单测直接调用验证，
   不依赖 Activity 生命周期。

### 8.2 用户感知

一句提示文案：**「主题已保存，重启后生效」**（配「立即重启」按钮）。
不写「可能会闪一下」之类的解释——重启本身已是明确反馈。

### 8.3 收益（为什么值得）

- **避免全量 recompose**：切主题要同时换 colorScheme + typography + shapes + FormSpec，
  热切等于整棵树重组，中端机掉帧；一次重启把成本挪到启动。
- **允许更重的排版差异**：账页换字族、行高、圆角这些结构性差异，只有「冷启动重建」才不必
  考虑运行中迁移（如已渲染列表的 measure 缓存）。
- **消除一类 bug**：审计 M3「改主题字阶不生效」的根因之一就是「定义在、消费散」；启动时一次性构建
  让「当前主题 = 一组不可变对象」成为不变量，不存在半途状态。
