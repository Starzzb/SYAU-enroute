# 规划 · 静默使用数据采集

> 2026-11-20。面向「沈农在途」0.8.0+m32 之后的版本。
> 一句话立场，只回答「功能有没有人用、在哪儿断」，不回答「谁在用」。

---

## 0. 先把话说明白

静默采集这件事，最容易走歪成两头。一头是采太多，把用户的行为拼成一个人；另一头是采太少，出事时两眼一抹黑。这份规划划的线是

**采「发生了什么」，不采「是谁发生的」。**

具体到数据上就是三句话。事件只带枚举值和计数，不带任何自由文本；身份只有一个安装期随机数，且每日换盐，跨天不可拼；位置、课程、成绩、搜索词这些一概不进管道。

---

## 1. 「静默」到底指什么

| 维度 | 要求 |
|---|---|
| 交互 | 不弹窗、不请求权限、不影响任何操作的响应时间 |
| 线程 | 采集走内存队列，落盘和上传全在后台，主线程零 IO |
| 失败 | 网络失败、磁盘满、服务端 500，一律静默丢弃，不打扰用户，只在调试日志里留一行 |
| 电量 | 只在自然时机批量发（App 启动后 30 秒、进入后台、充电且 Wi-Fi），不常驻唤醒 |
| 可见性 | 设置里有开关，关于页有一句说明，首启不弹同意框 |

「静默」不等于「瞒着」。开关默认打开、说明写在关于页、代码开源，这就是透明。

## 2. 采什么（事件清单）

事件名一律 `域.动作`，全小写，值一律枚举，字段缺省就不写（不写 null、不写 0 占位）。

### 2.1 生命周期

| 事件 | 字段 | 回答什么问题 |
|---|---|---|
| `app.start` | `cold`(bool)、`ms_since_install`(天档位)、`ver`、`abi` | 有多少人在用、版本分布 |

## 3. 不采什么（否清单）

| 不采 | 理由 |
|---|---|
| 学号、姓名、学院、专业、班级 | 能直接定位到人 |
| 课程表、成绩、考试安排、绩点 | 敏感，且与「只缓存自己的数据」规矩冲突 |
| 搜索关键词原文、导入的 JSON 内容 | 自由文本等于不可控，一条就能泄漏 |
| 设备 ID（IMEI / AndroidID / OAID / 广告 ID / 序列号） | 跨应用可关联 |
| 精确型号、MAC、手机号、运营商 | 组合起来可指纹化，最多留 API 级别和一档屏幕宽度 |
| 地理位置、IP 明文 | IP 只在服务端内存里用于限速，不落库不写日志 |
| 前台应用列表、通讯录、剪贴板 | 与本 App 无关的采集一律不碰 |
| 崩溃堆栈全文 | 只取 `where` 枚举和版本号，堆栈可能带路径与课程名 |

## 4. 数据模型

一条事件就是一行 JSON，行内自包含，服务端按行入库。

```json
{"v":1,"e":"syllabus.open","t":1732089600,"p":{"from":"timetable","hit":true},"d":"a3f1c9e2","s":"7d3b"}
```

| 字段 | 含义 |
|---|---|
| `v` | schema 版本，改结构就加一 |
| `e` | 事件名，必须在白名单里 |
| `t` | 客户端时间，秒；服务端另记 `t_srv`，两者差超过 1 天就信服务端 |
| `p` | props，键值都必须在白名单里 |
| `i` | 安装标识 = `SHA-256(install_id)[:16]`（16 位 hex / 64 bit），**一辈子不变**，用于去重、总设备数、留存、用龄 |
| `d` | 当日标识 = `SHA-256(install_id + ":" + 日期)[:8]`，每天变；只服务 ≤m40 已发出去的老包，新包两条都发 |
| `s` | 本次会话随机 4 位十六进制，只用于把同一次使用里的事件串起来 |

安装期随机 `install_id` 是 128 位 `SecureRandom`，存在 `Prefs` 里，**只在本机参与哈希，永不上传**；
用户清数据即消失。原规划里「服务端盐 + HMAC」那一版做不出来（盐在客户端没有），
落地口径见 `docs/实现-使用数据采集-m40.md` §2.1。

> 为什么必须有 `i`：只有 `d` 时服务端每天看到的是一批互不相干的 8 位串，
> 总用户数、留存、用龄一条也算不出，只剩「今天多少台设备」。`i` 只与它自己关联，
> 不与学号、姓名、设备号、任何系统标识关联；隐私边界仍是不传内容、不传身份。

## 5. 端上实现

现有代码里已经有的可用件，`androidx.work`（`ReminderWorker` 在用）、`kotlinx-serialization`、`Prefs`（SharedPreferences）、`EnRouteApp.onCreate`。不引入任何第三方统计 SDK，一是不放心，二是 34 MB 的教训还在。

### 5.1 结构

```
data/telemetry/Telemetry.kt        对外只有一个 record(event, props)，非阻塞
data/telemetry/TelemetrySchema.kt  事件与字段白名单、取值域、版本
data/telemetry/TelemetryQueue.kt   JSONL 环形文件，上限 512 KB，超了丢最旧
data/telemetry/TelemetryUploader.kt 批量 POST，指数退避，失败丢弃
data/telemetry/TelemetryWorker.kt  WorkManager 定时/约束触发
```

### 5.2 关键约束

- `record()` 只往 `ArrayDeque` 里塞，主线程开销 < 1 µs；队列满（200 条）就丢最旧
- 落盘在应用协程里做，一次 append 一行，文件到 512 KB 就截断到后一半
- 上传条件，20 条以上或距上次 30 分钟，且网络可用；优先 Wi-Fi，移动数据下只在充电时发
- 一批最多 100 条，body gzip，实测一条约 110 字节，gzip 后约 25 字节
- 重试 3 次（1/4/16 分钟退避），仍失败就整批丢弃，**不无限重试、不攒出隐私库**
- 单条事件超过 2 KB 直接丢（正常不可能，出现就说明有人往 props 里塞了东西）
- 服务端返回 400 说明 schema 不认，整批丢弃并降级为只发 `v` 与 `e`，避免死循环

### 5.3 触发时机

| 时机 | 动作 |
|---|---|
| `EnRouteApp.onCreate` | 只初始化，不上传 |
| App 启动后 30 秒 | 若满足条件，一次 flush |
| 进入后台（`ON_STOP`） | 落盘 + 尝试 flush |
| `TelemetryWorker` 每 6 小时 | 兜底 flush |

### 5.4 开关

`Prefs.telemetryEnabled`，**默认 `true`**（2026-11-20 主人定：不涉隐私，静默开），设置页放一行「匿名使用统计」，关于页写一句「会收集功能使用次数、服务可用性与错误类型，不含课程、成绩与个人信息」。关掉之后 `record()` 直接返回，同时清空队列，不发任何请求。不弹同意框。

## 6. 服务端

不新增机器。两条现实选择，都不贵。

| 方案 | 做法 | 代价 |
|---|---|---|
| A 自建（推荐先做） | `47.95.12.198` 上加 `POST /api/telemetry`，写 `events.jsonl` 按日切分，配 `cron` 日聚合到 `daily` 表 | 出口 148 KB/s 足够，日活 200 人×20 事件×25 字节 ≈ 100 KB/天 |
| B CloudBase | 云函数收 + 文档数据库，日聚合函数 | 省运维，但要配置密钥与域名 |

服务端只做四件事。校验 `v`/`e`/`p` 白名单（复用同一份 schema，生成一份 JSON 供两端读）；
按 `i`（退回 `d`）滚出日活、总设备数、用龄与 D1/D7 留存；原始记录保留 180 天，超期删；
`IP` 只进内存限速桶（每 IP 每分钟 60 条），不写盘不进日志 —— 注意反代后面必须读 `X-Forwarded-For`，
否则限流桶只有「nginx 那一个 IP」。

> **m41 已上线（2026-11-21）**：`POST /api/telemetry`、`GET /api/telemetry/health`；
> `GET /api/telemetry/stats` 与 `stats.txt`（要 `X-Admin-Key`）给总设备数/用龄/留存表。
> 运维口径见 `docs/实现-使用数据采集-m40.md` §5。

限速与防刷，一个固定 `User-Agent` 前缀 + 单批 100 条上限 + 载荷 64 KB 上限，够挡脚本瞎灌。

## 7. 这份数据要回答什么

先定问题，再定事件，不然采了一堆没人看。当前最值得回答的五个

1. **大纲有多少人真的在查**，从课表进还是从搜索进，命中率多少（2066 门是不是白压的）
2. **培养方案到大纲这条链路**有没有人走通（课程行点进去能开大纲）
3. **地图共建**是不是只有开发者自己在用（保存、导出、导入的真实分布）
4. **失败面在哪**（教务 10.2.0.47 连不上、资讯源解析失败、地图包下载失败各自占比）
5. **更新通道**在国内网络下的成功率（manifest 五条候选谁最常胜出）

对应 north star 就一个指标，**周活里用过「查大纲」的比例**。其余都是解释它的。

## 8. 测试与验收

- JVM 单测，白名单拒绝未知事件名与未知 props 键；塞中文/长串/控制字符必须被替换成 `invalid`
- 环形队列溢出丢最旧、断网重试后整批丢弃、400 降级，各一条
- 单测里禁止真发网络请求，uploader 抽成接口，测试用假实现
- 端上体积增量目标 < 20 KB，体积对表写进 `docs/规划-课程大纲内嵌压缩.md` 那张表旁边
- 验收口径，装机跑一天，看 `/api/telemetry` 落盘的 `events.jsonl` 行数与自己操作次数是否对得上，且文件里搜不到任何课程名、学号、IP

## 10. 风险表

| 风险 | 应对 |
|---|---|
| 白名单被绕过，自由文本进管道 | 白名单在 `record()` 入口做，不做「事后清洗」；单测锁死 |
| 服务端被灌数据 | 载荷与条数上限、UA 前缀、每分钟限速 |
| 用户觉得被监视 | 开关 + 关于页一句 + 代码开源；不弹框，也不偷偷开 |
| 存储膨胀 | 端上 512 KB 硬上限、服务端 90 天保留 |
| 换盐导致日活断层 | 盐按年固定，只有 `d` 的日期部分每日变，服务端自己算 HMAC，不需要下发盐 |
| 上传影响冷启动 | 启动后 30 秒才 flush，且首帧之后才初始化队列 |

## 11. 服务观测（第二类数据）

前面 §2 那批叫**产品使用数据**，回答「功能有没有人用」。这一节是**服务健康数据**，回答另一个问题：**我们的上游今天还活着吗。**

这一类的价值在维护上。教务改了个页面结构、资讯某个源悄悄换了域名、更新通道里某条候选被墙，都是「没人报障、但功能已经废了」的场景。靠用户反馈要等一周，靠这批数据当天就能看见。

### 11.1 上游矩阵

| 上游 | 地址 | 谁在用 | 挂了会怎样 |
|---|---|---|---|
| 教务学生端 | `10.2.0.47` | 课表、成绩、考试、空教室 | 主功能全废 |
| 教务教师端 | `10.2.0.48` | 教师公开信息 | 教师卡片空白 |
| CAS 登录 | `pass.syau.edu.cn` | 所有教务请求前跳 | 登录转圈 |
| 资讯源 21 个 | 教务处 / 双创 / 各学院站 | 资讯页 | 某一频道一直空 |
| 校园地图包 | 打包资源 | 地图页 | 底图与色块不出来 |
| 更新通道 5 候选 | GitHub 五条 | 检查更新 | 收不到新版 |

### 11.2 共同指标（每个上游一套）

| 指标 | 采集形式 | 说明 |
|---|---|---|
| 请求次数 | 计数 | 分母 |
| 成功率 | `ok` 布尔 | 分母分子都在端上算 |
| 失败类别 | 枚举 `dns / tcp / tls / timeout / http4xx / http5xx / parse / empty` | 一眼看出是网断了还是站改了 |
| 延迟 | 桶计数 `<200ms / 200-500 / 500-1000 / 1-2s / 2-5s / >5s` | 只发桶，不发毫秒原值 |
| 解析失败特征 | 枚举 `no_node / encoding / empty_list / field_renamed / shape_changed` | **站点改版的早期信号** |
| 恢复 | 由事件序列推 | 连续失败后第一次成功的时间差 |

延迟只发桶这件事很关键。分位数不需要原始值，服务端把当天的桶计数加起来算近似 p50/p95 就够，误差在半个桶内，但省掉了「记录每次请求花了多少毫秒」这种指纹级细节。

### 11.3 教务链路（最需要看的一块）

| 事件 | 字段 |
|---|---|
| `urp.login` | `ok`、`ms`（桶）、`stage`（枚举 `cas / redirect / session / captcha`）、`err` |
| `urp.session` | `state`（枚举 `fresh / reused / expired`）、`ms_since_login`（档位） |
| `urp.throttle` | `hit`(bool)、`wait_ms`（桶）—— `UrpThrottle` 已在跑，接一行就有 |
| `urp.request` | `api`（枚举，如 `schedule / score / exam / free_room`）、`ok`、`ms`（桶）、`err` |

「登录成功率」和「会话过期率」这两条决定了新手在第一分钟会不会放弃。`stage` 那个枚举尤其有用，能区分是 CAS 挂了、还是我们跳转拼错了、还是教务把 session 踢了。

### 11.4 资讯源健康

| 事件 | 字段 |
|---|---|
| `feed.source` | `src`（源的稳定 id，不是域名全串）、`ok`、`items`（桶 0/1-5/6-20/20+）、`age_days`（最新条目距今天数桶 0/1-3/4-7/7+）、`err` |

`age_days` 是这套里最灵的一个。源能返回 200、能解析出条目，但最新一条是三个月前的，说明它已经停止更新，页面看起来正常、实际是死的。这条指标抓的就是这种「假活」。

### 11.5 更新通道

| 事件 | 字段 |
|---|---|
| `update.manifest` | `channel`（枚举 `gh_proxy / raw / githack / jsdelivr / fastly`）、`index`（第几条命中 0-4）、`ms`（桶）、`ok` |
| `update.download` | `ok`、`sha_ok`、`ms`（桶）、`bytes`（档位）、`retry`（次数） |

统计五天候选的「胜出率」，就能决定要不要把最慢的那两条从 `MANIFEST_URLS` 里删掉，以及国内到底哪条稳。

### 11.6 地图包与资产

| 事件 | 字段 |
|---|---|
| `map.pack.load` | `version`、`ok`、`ms`（桶）、`faces`（桶）、`err`（枚举 `bad_geometry / version_mismatch / missing_field / empty`） |
| `asset.read` | `name`（枚举 `syllabus_index / syllabus_pack / plan_index / plan_year / pool`）、`ms`（桶）、`bytes`（档位） |

地图包这次从 90 面换到 173 面，`bad_geometry` 的比例就是用户侧的真实校验结果，比自己在本机跑测试更有说服力。

### 11.7 运行环境（粗档，不进隐私区）

| 维度 | 为什么采 | 形态 |
|---|---|---|
| API 级别 | 兼容判断，`minSdk 26` 上还有多少老系统 | 整数，如 29 / 33 / 35 |
| ABI | so 与 dex 相关 | 枚举 `arm64-v8a / armeabi-v7a` |
| 屏幕宽度 | 版面适配 | 桶 `<360 / 360-411 / 412-599 / 600+` |
| 深色模式 / 字体缩放 / 减少动画 | 三套设计分支各自的使用比例 | 布尔 / 枚举 |
| 内存档 | OOM 前兆 | `ActivityManager.memoryClass` 档位 |
| 网络类型 | 判断失败是否因移动数据 | 枚举 `wifi / cellular / ethernet / other` |
| 是否走 VPN | 校内 vs 校外通路 | 布尔（粗判，不记隧道信息） |
| 电量与充电 | 判断上传时机是否合理 | 档位 5 档 / 布尔 |

这些都停在「档」和「枚举」，加起来也不构成指纹，因为它们全是粗档，同一档里几千人。

### 11.8 体验与性能

| 事件 | 字段 |
|---|---|
| `perf.cold_start` | `ms`（桶）、`launch`（`warm / cold`） |
| `perf.page_first_frame` | `page`（枚举 `feed / timetable / map / exam / curriculum`）、`ms`（桶） |
| `perf.jank` | `page`、`frames`（本次页面渲染帧数桶）、`janky`（掉帧比例桶 0-2%/2-5%/5-10%/10%+） |
| `perf.traffic` | `rx`（档位）、`tx`（档位）、`foreground_min`（档位）—— 取自 `TrafficStats` 差值 |

掉帧用 `Choreographer` 计一页面的长短帧比例，不发逐帧时间。流量用 `TrafficStats` 取整段使用的前后差，只发档位。

### 11.9 服务端侧

端上采的是「用户视角」，服务端还能补一半，两边分开存、按天对齐就行。

| 指标 | 来源 |
|---|---|
| 请求量与状态码分布 | nginx / 应用日志按天聚合 |
| UA 分布 | 区分真实客户端与脚本 |
| 上报条数、被拒条数、被限速条数 | `/api/telemetry` 自身埋点 |
| 上报体积 | 每日 jsonl 字节数 |
| 地理粗档 | **不记 IP**，如需分布只记到 ASN 或省份，取自 CF/CDN 头 |

### 11.10 反例，这批不做

| 不做 | 理由 |
|---|---|
| 主动探测（定时 ping 教务） | 端上是用户的电和流量，不该替我们做巡检；真实请求里的数据已经够用。唯一例外是启动后的一次 500 ms 超时 `HEAD`，且只在检查更新时顺带 |
| 心跳 | 每 5 分钟一条「我还活着」既费电又没有信息量，会话起止已经能推出来 |
| 逐请求毫秒原值 | 指纹风险大于分析价值，桶够用 |
| 完整 URL 与查询串 | 教务 URL 里可能带学号 |
| 崩溃堆栈全文 | 可能带路径与课程名，只取枚举与版本 |

### 11.11 代价核算

一条事件约 110 字节，gzip 后约 25 字节。把 §2 与 §11 全开，一次前台会话大致 20–40 条，压缩后 0.5–1 KB。日活 200 人的话，端上一天上传不到 200 KB，服务端一年不到 70 MB。这点量在 `47.95.12.198` 的 148 KB/s 出口上完全不当回事。

端上电耗也可以忽略，因为 flush 只在启动后 30 秒、进后台、Worker 每 6 小时这三个点发生，没有常驻定时器。
