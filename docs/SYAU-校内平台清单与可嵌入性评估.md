> 探测时间：2026-11-11 09:55–10:10（主机当时在校园网内，能直连 `10.x` 内网段）
> 方法：① DNS 枚举 171 个常见服务名 → 45 个解析成功；② 官方「校园网址导航」`net.syau.edu.cn` 73 条；
> ③ 对候选逐个发 HTTP 请求看标题/状态/是否跳统一认证。**全程串行，单站请求 ≤3 次，间隔 ≥500ms。**

## 1. 结论摘要

1. **学校有一套统一身份认证**（`pass.syau.edu.cn/tpass`，天财 tpass），教务、OA、财务、科研、学工全部挂在它后面。**这意味着「一次登录换来所有系统」是可行的**，不需要为每个平台记一套密码。
2. **`cxcy.syau.edu.cn` 是最有价值的发现**：创新创业管理平台的**比赛列表和详情页都免登录**，而且详情页有**结构化字段**——`报名时间：2026-08-01 00:00 至 2027-10-31 23:59`、`比赛时间`、`已报名组数`。这是唯一能真正支撑「竞赛倒计时」的数据源，比抓通知公告强一个数量级。
3. **`net.syau.edu.cn` 是官方维护的服务导航页**，73 条链接，等于学校自己把清单整理好了。以后再要加平台，先看这里。
4. 真正需要登录才有意义的只有四类：**教务（已接）、学工系统（综测/奖助）、图书馆（借阅/座位）、上网自助（流量/在线设备）**。其余要么本来就公开，要么是给老师用的（OA、科研、财务）。
5. 校外访问内网靠 **WebVPN `webvpn.syau.edu.cn`**（公网 IP `210.47.175.22`）——App 若要做「校外也能用」，这是唯一正路。

## 3. `cxcy` 竞赛平台接入方案（推荐先做）

### 3.1 它为什么值得接

其它竞赛源只能给「一条通知」，看完还得自己找入口报名。这个平台直接给：

```
比赛时间：2026-08-01 00:00 至 2027-10-31 23:59
报名时间：2026-08-01 00:00 至 2027-10-31 23:59
已报名组数：…
```

**报名窗口是结构化字段**，可以算「还剩几天」「已截止」，也能区分「校园选拔赛 / 省赛 / 国赛」——这是竞赛日历的基础。

### 3.2 页面结构（实测）

| 用途 | 地址 | 结构 |
|---|---|---|
| 科技竞赛列表 | `/comp/front/comp/list?page=N` | `<a href="../comp/info?id=1542" title="全标题">`，服务端渲染，翻页 `?page=` |
| 竞赛详情 | `/comp/info?id=NNNN` | 正文含 `报名时间：`/`比赛时间：` 行，`已报名组数` |
| 竞赛成果公示 | `/comp/articlelist?cid=12` | 同类列表 |
| 大创项目申报 | `/dcplan/front/dcplan/list` | 同类列表 |

### 3.3 建议的解析规则

- 列表：正则 `<a href="\.\./comp/info\?id=(\d+)"[^>]*title="([^"]+)"` → key = `cxcy|comp|{id}`
- 详情：`报名时间[：:]\s*(\d{4}-\d{2}-\d{2})[^\n]*至\s*(\d{4}-\d{2}-\d{2})` → `startAt` / `deadline`
- 状态：按 `deadline` 与今天比，得出「报名中 / 剩 N 天 / 已截止」
- ⚠️ 列表页**没有日期**，日期只能从详情页拿 → 属于「点进去才抓」的那一类，和现有正文缓存机制天然吻合

## 4. 登录架构（重要）

```
学号+密码 ──POST──> pass.syau.edu.cn/tpass/login?service=<目标系统>
                          │
                          └─ 302 + ticket ──> 目标系统建立自己的会话 Cookie
```

也就是说：**登录一次 tpass，可以拿去换教务、学工、图书馆、财务各系统的会话**。
App 现在的教务登录已经走了这条路（`UrpClient`），要做「学工 / 图书馆 / 上网自助」不需要另写登录，
复用同一套 tpass 流程 + 各系统自己的 cookie 即可。

**安全红线（不变）**：密码只在内存里用，不落盘、不进日志、不写 SharePreferences；抓取只用 GET。

## 5. 频控与合规

- 内网服务是学校生产环境，不是给我压测的。本轮探测定为：**串行、单站 ≤3 次、间隔 ≥500ms**。
- `*.syau.edu.cn` 的 robots 是 `Allow: /$` + `Disallow: /`，除首页全站禁爬。当前是**个人测试包**，
  未对外分发；若要给同学用，以下站点需要学校授权：`cxcy`、`job`、`jwc`、`xsc`、`jobsyau`。
- 不碰：成绩单/获奖名单里带「姓名 + 学号」的公示附件；不做批量下载；不绕过权限，看不到的就是看不到。

## 6. 登录实测结果（m14，2026-11-11 10:00）

用主人账号在真浏览器（Edge headless + CDP）里登录 `pass.syau.edu.cn` 实测，**登录成功**：

- 登录页默认停在「扫码登录」tab，要点 `#password_login` 切到账号密码
- 提交后跳 `portal.syau.edu.cn/tp_up/view?m=up#act=up/appstore/applist`
- 门户叫**「智慧沈农」**，业务系统区里**只挂了 2 个应用**：`科大讯飞题库考试系统`、`易尔思教学平台`
  → 说明学校并没有把所有系统都塞进门户单点登录，很多还是各自独立登录页
- 学工系统 `210.47.163.44` 在 headless 里被 `ERR_BLOCKED_BY_CLIENT` 拦了（浏览器层拦截，不是站点挂了；
  `Invoke-WebRequest` 能正常拿到「沈阳农业大学学工网—系统登录」页）。**它有自己的登录页，不跟 tpass 联动**，需另行确认账号口径
- 上网自助 `a.syau.edu.cn:8800` = **深澜软件 srun** 认证页，**自带图形验证码** → 脚本登录不现实，也不该硬做
- 图书馆 `lib.syau.edu.cn` 首页本来就公开，借阅要另登

**结论修正**：第 4 节「一次登录通吃所有系统」只对**挂了 CAS 的系统**成立（教务、OA、财务、科研、门户）。
学工、上网自助、缴费这类各自独立的登录，不要指望 SSO 复用。

## 8. 还没做的（以及为什么）

以下都需要登录、而且**各有独立登录体系**，目前未做：

1. 学工系统 `210.47.163.44/SyauXG/Sys` —— 综测分数、奖助进度。有自己的登录页，headless 被浏览器拦，
   需要真机/可见窗口再试一次
2. 图书馆 `lib.syau.edu.cn` 借阅 —— 需要读者证号或统一认证，未验证
3. 上网自助 `a.syau.edu.cn:8800` —— 深澜 srun，**自带图形验证码**，脚本化不现实，最多做成 WebView 入口
4. 网上缴费 `pay.syau.edu.cn` —— 涉及支付，**不建议嵌进 App**，给个跳转入口就够
5. 校园门户待办 —— 「智慧沈农」是重 SPA，接口需逆向，暂缓
6. 就业网的「招聘会 / 宣讲会」tab —— 目前只接了文章流；日历化需要再探 ajax

我判断优先级：**学工（综测）> 上网自助（流量）> 图书馆借阅 > 其它**。
前两个是学生日常真正会焦虑的东西，后三个要么低频、要么有合规/安全顾虑。
