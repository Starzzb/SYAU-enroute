# 学院官网 · 教师公开信息源调研

> 实测日期：2026-11-13（探针与样本：`docs/_probe/faculty/`）
> 执行：PC 直连（该机可访问校内网 10.2.0.x，院系站同时公网可达）
> 用途：给「查教师」补上教务系统没有的**研究方向、办公地点、办公电话、邮箱**等信息；实现见票 06

---

## 0. 一句话结论

全校院系站是**同一套西安博达 VSB 站群**，详情页正文容器统一落在 `vsb_content` / `v_news_content`
（部分模板变体叫 `WspDetailContent`）——**一个解析器能吃下绝大多数学院**。
但实测 12 个真实教师详情页里有 **3 个用朴素「抓 vsb_content」是拿不到正文的**，所以必须
「多模板兜底 + 解析失败就说失败」，不能假装抓到了。

字段可得性很好：职称、学历学位、导师资格、研究方向、行政职务、办公地点、学院办公电话、校方邮箱
基本都在正文里；**个人手机号、QQ 这类私人联系方式不该落地**（见 §6）。

## 2. URL 规则（站群级，稳定）

- 列表/栏目页：`https://<子域>.syau.edu.cn/<任意栏目路径>.htm`
- 文章详情页：`info/{栏目ID}/{文章ID}.htm`（栏目 ID 3~5 位，实测有 `info/205156/…`、`info/1234/…`）
- 另有 `content.jsp?urltype=news.NewsContentUrl&wbtreeid=XXXX&wbnewsid=YYYY` 形态（同站群另一种入口）
- 教师姓名超链接标签很短（2~4 字），`scan-columns.ps1` 就是靠「短文本 + info/ 或 content.jsp」筛候选人的

### ⚠️ 2026-11-14 更正（实现票 08 时的复测）

本节「3/13 页朴素提取失败」的结论**范围过窄**：当时只取容器内**第一个 `<p>`**。
改用「5 级容器兜底 + 容器内 `p/div/li/td` 全文本拼接 + 整页兜底」重跑同样 13 个真实样本，
**13/13 都能抽到正文**（最少 382 汉字）：

- `det_lin_luxiujun`（原判 ❌ 9 字）→ 实际 **1144 汉字**，是取法问题，不是页面没内容
- `det_jgxy_zhoumi`（原判 ❌ 无容器）→ 靠整页兜底得 **851 字**
- `det_lxy_1289`（原判 ⚠️ 只抽到荣誉段）→ 补齐后完整

结论：**必须做多级兜底，但正常页面不应再被判成失败**。真正的失败只保留两类：
页面只有图片、或只有姓名；此时 `parseDetail` 返回 null，界面明说「没解析到」。
失败五分类（`NoSource/NotFound/NotParsed/Ambiguous/Network`）与「刷新失败保留旧缓存并标日期」
已按此落地，见 `data/faculty/`。

## 5. 缓存方案

### 结论：**按教师缓存 JSON（结构化字段 + 原文链接 + 抓取时间），不缓存整页 HTML**

理由：整页 HTML 单页 13~43KB，200 位教师就 3~8MB；结构化后单条约 1~3KB，还能直接上屏。

### 目录与键

```
filesDir/faculty/
  <key>.json          # 一条教师公开信息
```

- **键**：优先**工号**（教务侧有，稳定且唯一）；官网抓不到工号时退化为 `姓名@学院域名` 的短哈希。
  用工号的好处是「搜教师 → 点详情」能直接命中，不需要先匹配姓名。
- 每条内容：

```jsonc
{
  "key": "1995500023",
  "name": "董秀茹",
  "college": "土环",
  "sourceUrl": "https://thxy.syau.edu.cn/info/205156/xxxx.htm",
  "fetchedAt": "2026-11-13T23:10:00+08:00",
  "template": "vsb_content",          // 命中的容器，便于将来排障
  "fields": { "职称": "教授", "研究方向": "…", "办公地点": "…", "办公电话": "…" },
  "sections": [ {"title":"教育经历","text":"…"} ],   // 长文本按小节存，前端折叠
  "rawText": "…"                        // 兜底：正文纯文本，限制 ≤ 8KB
}
```

### 失效与刷新

- **TTL 30 天**：教师公开资料变化慢（职称/职务变动按年）。
- 进详情页时：有缓存且未过期 → 直接上屏（带「抓于 X」）；过期 → 后台静默刷新，成功后替换。
- 提供**手动刷新**入口（详情页右上角）。
- 刷新失败：**保留旧缓存**并标注「更新失败，显示 11-13 的缓存」，不清空。

### 体积上限与淘汰

- 单条 `rawText` 截断 8KB；`sections` 每条截断 2KB。
- 目录总量上限 **500 条 / 5MB**，超出按 `fetchedAt` 最旧淘汰（LRU 近似）。
- 「清除所有数据」连带清空 `filesDir/faculty/`。

### 与现有 `feed` 正文缓存的关系

现有 `data/feed/` 的正文缓存是「按资讯条目 key 存正文，永久有效」；本方案**不合并**：
资讯正文随时效失效无所谓，教师资料需要 TTL 与手动刷新，混在一起会让失效策略互相污染。
两者共用同一套「目录 + 单文件 JSON + 原子写」的写法即可（照抄现有 store 的落盘方式）。

## 6. 合规边界

1. **robots**：`*.syau.edu.cn` 是 `Allow: /$` + `Disallow: /` —— 严格说是禁止抓取的。
   本项目定位是**个人测试构建**；若要分发或上架，必须先取得学校授权。这条写进 `AGENTS.md`，实现时不要绕过。
2. **只抓公开的教师职务信息**：职称、研究方向、办公地点、办公电话、校方邮箱 —— 属于教职工公务联系方式。
3. **不落地**：个人手机号、QQ、私人邮箱（163/qq 等）、身份证、家庭住址。
   样本里 `det_zbxy_1808` 有 `电话：13464032492` 与 `QQ:1147888178`，
   `det_swxy_quanbo` 有 `syau_qb@163.com` —— 这三类一律**丢弃**，抽取时就过滤，不进缓存。
4. **必须显示来源**：详情页要写「信息来自 XX 学院官网 · 原文链接 · 抓取于 YYYY-MM-DD」，
   并提供「在浏览器打开原文」。
5. **不做批量爬取**：只在用户点开某位教师时抓那一位，不做全站遍历。
6. **不缓存学生个人信息**（红线，同 `AGENTS.md`）。

## 7. 给票 06 的实现建议

1. 先做**常量表**：17 个学院的 `(显示名, 域名, 师资栏目路径)`，一院一配；院系名与教务侧
   `departmentName`（`土环`/`农学`/`经管`…）建立映射，否则搜到老师也不知道去哪个站找。
2. 解析器分两层：**容器序列兜底**（§3 的 5 级顺序）+ **字段抽取**（§4 的表格）。
   字段抽取写成纯函数，用 `_probe/faculty/` 的 13 个样本做单测夹具（含 3 个失败样本，
   断言「失败时返回空而不是乱码」）。
3. **教师列表页到详情页的匹配**：教务只给姓名+工号，官网列表页给姓名+详情链接。
   建议按姓名在目标学院栏目页里找链接；命中多个同名时**不猜**，把候选列出来让用户选。
4. 抓取失败要**明确说失败**（「学院官网没有解析到这位老师的信息」+ 原文搜索链接），
   不要显示空卡片，也不能把教务字段伪装成官网字段。
5. 缓存按 §5 落地；`fetchedAt` 必须上屏，否则用户无法判断这是不是三年前的信息。

## 5. 翻页与同组栏目自动发现（2026-11-17 实测）

**问题**：土环 `szdw/jsxl/` 下，正高栏（`zgjzc.htm`）与副高栏（`fgjzc.htm`）各自还分页
（`zgjzc/1.htm`、`zgjzc/2.htm`、`fgjzc/1.htm`、`fgjzc/2.htm`）。只按「一个职称一个 URL」配死，
就会漏掉第二页上的人 —— 蒋卓东（`info/1612/4923.htm`）就只在 `fgjzc/2.htm` 里。

**两条通用线索**（不用为每个院猜路径）：

1. **同目录兄弟栏目**：栏目页的导航 HTML 里带着同目录其他栏目的链接
   （正高页上有 `fgjzc.htm | 副高级职称`、`js.htm`）。取 `url.substringBeforeLast('/')` 相同、
   后缀 `.htm`、非 `index.htm`、不含 `?`/`#` 的链接即可。
2. **分页**：页底形如 `fgjzc/1.htm`、`fgjzc/2.htm`，全部以 `listUrl.removeSuffix(".htm") + "/"` 开头。

**落地**（`app/src/main/java/cn/dkarbon/enroute/data/faculty/`）：

- `FacultyParser.siblingColumns(listHtml, listUrl, limit = 6)`、`FacultyParser.pagination(listHtml, listUrl, limit = 8)`
- `FacultyRepository` 由「逐条 for 循环」改为**队列 BFS**：起始栏目入队 → 取出抓取 →
  命中详情即停；没命中就把「翻页」与「兄弟栏目」入队再试。硬上限 `MAX_PAGES = 10`
  （只为一个姓名在用户点开时跑，宁可放弃也不爬站）
- 土环 `FacultySources.kt:44` 补 `/szdw/jsxl/fgjzc.htm`（正高仍排第一，最可能命中）

**实测证据**（`FacultyLiveWalkTest`，`ENROUTE_LIVE=1` 时才打公网）：

```
GET .../szdw/jsxl/fgjzc.htm    → 200 21290B
GET .../szdw/jsxl/fgjzc/1.htm  → 200 20500B
GET .../szdw/jsxl/fgjzc/2.htm  → 200 21561B
detail = https://thxy.syau.edu.cn/info/1612/4923.htm
正文长度 = 2875 字，含「研究方向」「学习及工作经历」「承担科研项目」
```

脱敏核验：手机号与 163 邮箱在入库前被 `FacultyPrivacy.scrub` 去掉，校方邮箱 `jzd@syau.edu.cn` 保留。

**边界**：只用于「用户点开某位教师」这一次请求，不做全量预抓；结果按 `fetchedAt` 缓存，
需要更新时点详情页右上角「刷新」。
