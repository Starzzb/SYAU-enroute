# 阻塞式更新改造 · 设计

原型：`docs/design/阻塞式更新.html`（单文件、自包含，四台 392×812 手机 + 六块规格面板）。
本轮只出原型与设计，尚未改 Kotlin。

---

## 0 已拍板的三个决策

| 决策 | 结论 |
|---|---|
| 阻塞强度 | **轻量档** —— UI 全屏阻塞 + `UpdateCenter` 用 Application scope 托管下载。不加前台服务，不动 `FOREGROUND_SERVICE` 权限。 |
| 失败态 | **放行返回键**，并给「重试 / 稍后」两个出口。阻塞不能变成卡死。 |
| 启动静默检查 | 仍然**只做提醒**（弹窗 / 设置页角标）。用户点「更新」之后才进阻塞下载。 |

---

## 1 交互时序

```
① 检查更新（设置页按钮 / 启动静默检查）
      ↓ 发现新版
② 展示版本信息（UpdateDialog 或设置页 Available 行）   ← 这一步就是「确认」
      ↓ 用户点「更新」
③ 全屏阻塞浮层，开始下载
      │  · 盖住底栏与所有 tab
      │  · 吞掉系统返回键
      │  · 版本 / 体积 / 进度条 / 百分比 / 已下·总量 / 速度
      ↓ 下载完成 + sha256 通过
④ 浮层切完成态：「安装」按钮
      ↓ 点「安装」
⑤ 有权限 → 直接拉系统安装器
   没权限 → 跳「安装未知应用」系统设置页，回来自动拉安装器（复用现有逻辑）
```

关键差别在**作用域**：现在 `state` 与 `Job` 是 `UpdateSection` 的 `remember`，浮层一 unmount 就断。
改造后下载状态与协程都归 `UpdateCenter`，UI 只是订阅者 —— 转屏、切 tab、重组都不影响进度。

## 2 四态视觉

浮层是一个 `Box(fillMaxSize)`：遮罩 `--scrim`（亮 `rgba(25,23,19,.52)` / 暗 `rgba(0,0,0,.66)`）+ 居中卡片。

卡片：`t.card` 底、1px `t.outline`、圆角 10dp、内距 20/18/16/18，
`::before` 铺 12dp 砂点纹（`α .04`，只在卡片内部），四层压印阴影沿用 `inkPress` 口径。

| 态 | 主体 | 动作 |
|---|---|---|
| 下载中 | 2dp 进度条 + 19sp 百分比 + 「5.2 / 8.4 MB · 412 KB/s · 约 8 秒」+ 两格元信息（来源 / 校验） | 无。没有取消按钮。 |
| 完成 | 进度条满 + 「sha256 已校验」+ 两格（签名一致 / 覆盖升级留数据） | 「安装」（墨底纸字） |
| 失败 | 进度条停在已下比例、`t.brick` 色 + 22dp 圆叹号 + 人话原因 | 「稍后」（描边）+「重试」（墨底） |

字号：版本名 16.5sp/800、versionCode 11sp 等宽、百分比 19sp/800、正文 12.5sp/1.8、按钮 13sp/600、按钮高 40dp。

## 3 失败判定（确定规则，不靠猜）

| 条件 | 判定文案 |
|---|---|
| 连接 15 秒未建立 | 连不上 · 服务器无响应 |
| 连上后 20 秒零字节 | 没有数据 · 首包未到 |
| 连续 30 秒平均 < 10 KB/s | 速度过低 · 网络在动但传不动 |
| 总耗时 > 15 分钟未完成 | 超时 · 中断重试 |
| 收到字节数 ≠ Content-Length | 不完整 · 少 n 字节 |
| sha256 与 manifest 不符 | 校验失败 · 文件已丢弃 |
| HTTP 4xx/5xx 且五个镜像全试过 | 源不可用 |

低速与零字节都用**滑动窗口**判：每 5 秒采一次已下字节，累计 30 秒不足 300 KB 即判死。
失败保留 `.part` 与已下字节，重试走 Range 续传。

## 4 退出拦截矩阵

| 方式 | 结果 | 手段 |
|---|---|---|
| 系统返回键 / 手势 | 吞掉 | `BackHandler(enabled = state !is Failed) {}` |
| 点遮罩 | 无效 | 遮罩不设 `clickable` |
| 切 tab / 打开其它页 | 无效 | 浮层挂在 Scaffold 之上，盖住底栏 |

| Home 到桌面 | 放行 | 系统行为 |
| 划掉进程 | 放行 | 轻量档不加前台服务 |
| 失败态返回键 | 放行 | 等同「稍后」 |

## 6 测试

`app/src/test/java/cn/dkarbon/enroute/UpdateFlowTest.kt`（新增）：

- `Downloading → Ready` 与 `Downloading → Failed → Downloading` 两条合法路径；
- `startDownload` 幂等：下载中再点不重复起 job；
- `resetDownload` 只在 `Failed` 态生效（`Downloading` 态调它回到 Idle 也算非法，应被忽略）；
- `Ready` 态点安装必须过 `UpdateInstall.step` 权限判断；
- 失败态「稍后」后 `downloadState == Idle`。

`UpdateInstallTest` 既有用例不动。

真机验收（release 包装机）：

1. 下载中按返回 → 无反应；
2. 点遮罩 → 无反应；
3. 切 tab → 被盖住；
4. 转屏 → 百分比继续走；
5. 断网 30 秒 → 落失败态，「稍后」能退出；
6. 完成点「安装」→ 无权限跳系统设置，回来自动拉安装器。

## 7 顺带的换纹：回纹下线，教务盒换砂点

上一轮给「我的 → 教务」盒用了回纹（MEANDER，方折雷纹）。真机上压到 `α .038` 仍像水印、抢字，
决定整条删掉：绘制函数 `drawMeander`、枚举值 `PaperTex.MEANDER`、`UserScreen` 里的分配关系全部移除。

教务盒改用 **DOTS 砂点**（12dp 步距、0.9dp 点、`α .070`）—— 点状纤维最不像「图案」，
只让纸面有点颗粒，不和行文字抢注意力。

其余四款不动：方格配考试、十字配资讯正文、织配大纲与本机、鳞配校园。

> 原型样张区把纹路放大了约一倍强度（`--tx1 .22` 对实机 `.10`），否则五款在缩略尺寸下分不出来。
> 这一条只影响原型，不影响 App。

### 9.2 失败判据（真值）

`kotlin
private const val FIRST_BYTE_MS = 20_000L        // 连上后 20 秒零字节 → 判死
private const val SPEED_WINDOW_MS = 30_000L      // 每 30 秒看一次增量
private const val MIN_WINDOW_BYTES = 300_000L    // 30 秒不足 300 KB（≈10 KB/s）→ 判死
private const val TOTAL_TIMEOUT_MS = 15 * 60 * 1000L
`
外加原有的：connectTimeout = 15_000、done != total、sha256 不符、HTTP 非 2xx、五个镜像全挂。

eadTimeout 从 60s 收到 20s —— 它和「首包 20 秒」是同一条判据的两面：阻塞式下载不能等一分钟才发现没数据。

### 9.3 两处实现判断

1. **DownloadState 必须写在 class UpdateCenter 的类体内，不能写在 companion object 里**。
   写在 companion 内时，外部写 UpdateCenter.DownloadState 编译器报 Unresolved reference
   （Companion 内的嵌套类型不走外层类名简写解析），而 downloadState 属性本身又能正常解析 ——
   症状很误导。类体内嵌套即可，状态仍由 companion 的 StateFlow 持有，照样是进程级。
2. **下载中的状态不再回写设置页的 Ui**。Ui.Downloading 现在只由「发起瞬间」置一次，
   之后所有进度都走 UpdateCenter.downloadState —— 两份进度源必然对不上。

### 9.4 顺带：教务盒换 EDGE

回纹（MEANDER）整条删掉后，教务盒改用 PaperTex.EDGE：四边向内压暗（上 .105 / 下 .075 / 左右 .055，
暗档黑 .55/.42/.34）+ 上沿 1dp 亮边。没有纹样，就没有会抢字的笔划 —— 它是「纸被压进凹槽」的形，
不是图案。
