给非移动端开发者的解释

别人先「选对组件」再写，我们项目到底是什么情况？

一句话：StyleKit 那页讲的是「挑现成组件」的路线；我们这个项目走的是另一条——只用 Compose 的基础零件，业务组件全部自己画。两条路都能做出好界面，区别在「零件从哪来」，不在「做得好不好」。

一、你看到的那个页面在讲什么

截图是 StyleKit 的「移动端设计」：从一块小屏幕开始，试试常见交互，找到合适的开源组件，再把设计要求带进项目。

它描述的是一条很主流的路线：先去组件库挑一个长得对的组件 → 复制代码 → 改配色和字号 → 装进自己的 App。这条路线在 Web 前端特别常见（Tailwind 组件、Ant Design、Vant 之类），因为浏览器里一套 HTML + CSS 到处都能跑。

这条路线好在哪

  • 快：不用从零画按钮、弹窗、日期选择器
  • 一致：库里组件的间距、状态、无障碍都调好了
  • 团队容易对齐：大家说「用库里那个 Dialog」就完事

它的前提是什么

  • 你的界面需求落在库覆盖的范围内
  • 你接受库长什么样，只在那范围内微调
  • 技术栈匹配：Web 组件进不了 Android，反之亦然
我们项目卡在第三条：uiverse / StyleKit 的组件是 HTML + CSS，Android App 用的是 Kotlin + Compose，两套语言，代码没法直接搬。
所以那些页面对我们的真实价值是设计参考：看形态、配色、动效节奏，然后翻译成 Compose 代码。我们已经这么做了——底部导航、加载动画、登录卡、个人卡都是从 uiverse 取形态，自己写实现。

二、移动端开发的三条路线

用买家具打比方，一眼看懂差别

ROUTE 01

组件库路线

像去宜家买成套家具
  • 代表：Material 3 官方组件、Ant Design Mobile、Vant
  • 做法：import 进来，改主题色，直接用
  • 代价：界面长相似曾相识，特殊需求要跟库较劲
我们用了一半：基础件用 Material 3
ROUTE 02

设计系统路线

像先定色卡和尺寸表，再找木匠
  • 代表：StyleKit 这种 token 体系
  • 做法：先定颜色 / 字号 / 间距的变量，组件按变量拼
  • 代价：前期要先把规范想清楚
我们也在用：InkTokenSet 就是这套变量
ROUTE 03 · 我们走这条

自绘组件路线

像自己画图纸，自己动手打
  • 底层零件用 Compose 基础件（Box / Column / Canvas）
  • 业务组件自己写成 Composable 函数
  • 图标不够就自己画进 AppIcons.kt
主体在这条：底栏 / 卡片 / 加载 / 登录都自绘
三条路线不是非此即彼。我们实际是 02 + 03 为主，01 打底：Material 3 提供 Scaffold、Text、Switch 这些基础件；设计变量自己定义；看得见的特色组件自己画。

四、为什么我们没直接套组件库

四条真实原因，按影响从大到小

1 · 需求形状特殊课表是 7 列 × 12 节的网格，单元格要显示「侵蚀进度」「当前时间线」「实验课标记」。通用组件库里没有这种东西，只能自己画。
2 · 视觉方向几经推翻从硬朗农业改到水墨，差的不只是颜色，还有圆角、线宽、阴影、留白整套语言。通用组件的默认样式反而成了要对抗的东西。
3 · 包体积敏感应用内嵌了 2066 门大纲 + 168 份方案（brotli 压过 4.64 MB）。material-icons-extended 的 34 MB 不能进来，图标缺一个就自己画一个。
4 · 数据诚实红线解析不出来显示「暂缺」，不填 0、不猜日期。这类约束属于业务规则，任何组件库都帮不上，得写进组件自己的逻辑里。
结果就是：我们有的不是「选哪个组件」，而是「这个组件长什么样、怎么动、数据缺失时说什么」。这些决定比选库更花时间，也正是你在原型阶段反复调的东西。

六、术语小抄（看懂对话用）

遇到这些词时，对应的意思

ComposeAndroid 的新一代界面写法：用 Kotlin 描述「界面应该长什么样」，不是拖控件。
Composable一个画界面的函数。我们说「写一个 InkNavBar」，意思就是写这么一个函数。
Modifier贴在组件上的装饰：内边距、背景、圆角、点击、渐变。压印阴影也靠它实现。
token设计变量：把「墨色 #2C2C2C」起名叫 ink，全项目引用这个名字，改一处全改。
ScaffoldMaterial 3 的页面骨架，帮我们摆好顶部栏、底部栏和内容区。
dp / spdp 是尺寸单位，sp 是字号单位（跟随系统字体大小设置）。
原型先行我们的工作法：先在 HTML 里把效果调对，确认后再写 Kotlin，因为编译一次十几分钟。
压印阴影卡片边缘的渐变明暗，让纸片看起来是「压」在纸上而不是贴上去。CSS 用 inset box-shadow；Compose 用 drawBehind + 渐变画出来。
