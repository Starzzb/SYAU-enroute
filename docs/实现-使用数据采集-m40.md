## 2. 与原规划的三处偏离（都是有意的）

### 2.1 两个标识：`i` 跨天可拼，`d` 只管当天

规划 §4 写的是 `d = HMAC(服务端盐, install_id + 日期)[:8]`。真做时发现算不出来：
服务端盐在客户端没有，要么把 `install_id` 明文传上去（「跨天拼不起来」当场变假），
要么让服务端算（客户端仍要先传 `install_id`，同样假）。

m40 先落地的是 `d = SHA-256(installId + ":" + yyyy-MM-dd)[:8]`，全在本机算。
**问题（m40 上线前发现）**：`d` 每天变，服务端就只剩「今天有多少台设备」，
总用户数、留存、用龄全都算不出来 —— 而这些恰恰是决定「哪个功能该留、哪个该砍」的依据。

m41 起加一路 `i = SHA-256(installId)[:16]`：

| | `i`（新增） | `d`（保留） |
|---|---|---|
| 形态 | 16 位 hex，64 bit | 8 位 hex，32 bit |
| 变化 | **一辈子不变** | 每天变 |
| 用途 | 去重、总设备数、留存 D1/D7、用龄分布 | 老版本（≤m40）已经发出去的那批记录 |
| 原像 | `installId` 永不出门，只传哈希 | 同 |

`installId` 仍然是本机随机的 128 bit，**不上传、不与会话标识混用**。
`i` 是它的单向哈希前 64 bit，不与学号、姓名、设备号、任何系统标识相关。
64 bit 是为躲开 32 bit 的生日碰撞（几万台设备规模下 8 位 hex 已经不安全）。

服务端两条线都认：有 `i` 用 `i` 去重（`device_key()` 优先 `"i:"`，退回 `"d:"`），
所以旧包记录不会丢，新包记录能跨天拼。

### 2.2 服务端不信客户端

端上的 `TelemetrySchema` 是善意，不是保证：抓包之后伪造一条 POST 太容易。
所以 `server/telemetry/schema.json` 是**第二道**白名单，`clean_line()` 再筛一遍：
未知事件整条丢、未知字段丢、越域值降级为 `"invalid"`（留痕，不静默）。

### 2.3 端上白名单与服务端 schema 必须逐条一致

两份一旦漂移，事件会**静默消失**（服务端只累加一个 `dropped` 计数）。
`TelemetryTest.端上白名单与服务端_schema_一致` 逐事件逐字段比对，红了就说明两份打架。

## 4. 客户端结构

```
app/src/main/java/cn/dkarbon/enroute/data/telemetry/
├── TelemetrySchema.kt   白名单 + sanitize + 版本号正则（纯函数，可单测）
├── TelemetryId.kt       当日标识 / 会话标识 / 安装标识（全本机）
├── TelemetryQueue.kt    512 KB 环形落盘（trimToCap 从尾部保留最新）
├── Telemetry.kt         内存队列 200 条、record()、flush、崩溃落盘、分档函数
├── TelemetryUploader.kt 批量 ≤100、gzip、1/4/16 分钟退避、降级
└── TelemetryWorker.kt   6 小时兜底
```

- `record()` 只进 `ArrayDeque`（上限 200），**不做任何 IO**；凑够 20 条或到点才 flush。
- flush 走 `Dispatchers.IO` 单 scope + `Mutex` 串行，落盘文件 `filesDir/telemetry/queue.ndjson`；超过 512 KB 从**尾部**保留（旧的先丢）。
- 崩溃处理：`app.crash` → `flushToDiskBlocking(400ms)` → 交回系统默认 handler（不吞崩溃）。
- 开关：`Prefs.telemetryEnabled`（默认 true）。关掉 → `Telemetry.setEnabled(false)` 清空内存队列 + 删落盘文件 + 停止 Worker。

## 5. 服务端运维

部署在 `47.95.12.198`（与地图共建同一台）。**不开新端口**：python 只监听 `127.0.0.1:18090`，
由已有的 18081 / 18082 两个 nginx 站点各挂一段 `/api/telemetry/` 反代出去 ——
阿里云安全组只放行了这两个端口，新端口要人肉放行，不值当。

一条命令装完（幂等，可重复跑）：

```bash
ssh -p 25894 root@47.95.12.198 'mkdir -p /tmp/enroute-web'
scp -P 25894 server/telemetry/server.py server/telemetry/schema.json server/telemetry/deploy.sh \
    root@47.95.12.198:/tmp/
scp -P 25894 server/telemetry/web/index.html root@47.95.12.198:/tmp/enroute-web/index.html
ssh -p 25894 root@47.95.12.198 'bash /tmp/deploy.sh'
```

`deploy.sh` 依次做：装代码到 `/opt/enroute/telemetry`（先 `--schema-check` 自检，坏文件不装）→
systemd 起 `enroute-telemetry.service`（`MemoryMax=96M`、`NoNewPrivileges`、只监听本地）→
两个站点 include 同一段反代 `/etc/nginx/snippets/enroute-telemetry.conf` → `nginx -t && reload` →
写 `/etc/cron.d/enroute-telemetry`（**每小时** `--aggregate --all`；每天 04:10 `--aggregate --all --prune --days 180`）→ 自查三条 curl。

管理钥匙（`GET /api/telemetry/stats` 用）在首次部署时生成一次，写进 `/etc/enroute-telemetry.env`
（`chmod 600`，24 字节随机 base64），**重跑 `deploy.sh` 不会换**，否则所有查看脚本当场失效。
systemd unit 用 `EnvironmentFile=-` 读它，脚本末尾也会回显一次。

健康检查：

```bash

# → {"ok": true, "version": 1, "events": 18}
curl -s http://47.95.12.198:18081/api/telemetry/health   # 备用端点，同一个后端

看统计（要钥匙；本机 127.0.0.1 直连不要钥匙）：

curl -s -H "X-Admin-Key: $KEY" http://47.95.12.198:18082/api/telemetry/stats      # JSON
curl -s -H "X-Admin-Key: $KEY" http://47.95.12.198:18082/api/telemetry/stats.txt  # 中文表格
```

> **现状（2026-11-21 18:17 实测）**：**已上线**。`enroute-telemetry.service` active，
> `18081` / `18082` 两个入口 `/api/telemetry/health` 均 200，`/api/telemetry/stats` 不带钥匙 403、
> 带钥匙 200；POST 一条合成记录 `{"accepted":1,"dropped":0}`，`--aggregate --all` 能出
> `daily.json` 与 `users.json`，测试数据随后已清空。数据目录当前为空。
>
> 踩过的坑写在这里，重装时别再踩：
> 1. `deploy.sh` 初始版本把 `include` **追加在站点文件末尾**（server 块外）→
>    `nginx: [emerg] "location" directive is not allowed here`。现在插在每个 `server {` 之后。
> 2. `_admin_ok()` 原来只看 `client_address`。藏在 nginx 后面时对端永远是 127.0.0.1，
>    等于**谁都能看统计**、限流也把全网当一台机器。现在读 `X-Forwarded-For`（nginx 用
>    `$remote_addr` 覆盖写，客户端伪造无效）。
> 3. **时间戳单位对不上（2026-11-21 18:33 修）**：客户端 `Telemetry.buildLine` 发的是**秒**
>    （`now / 1000L`），服务端 `clean_line` 校验却是毫秒区间（`1.5e12..4e12`）→ 真机每一条都被判脏丢弃，
>    接口还返回 HTTP 200 + `{"accepted":0,"dropped":1}`，客户端当成成功把队列清空。
>    m40 上线后实际一条真实数据都没收到。现在服务端把 `1e9..1e11` 当秒并 ×1000，毫秒原样收。

数据文件：

- `data/events-YYYY-MM-DD.ndjson` —— 原始记录，一天一个文件，保留 180 天。
- `data/daily.json` —— 日聚合（`dau` 按 `i` 去重、`dau_legacy` 是只带 `d` 的旧包、`events` 计数、
  `versions` / `abis` 分布），最多保留 400 天。
- `data/users.json` —— 跨天累计（`users_total` 总设备数、`active_days` 用龄分布、
  `by_version`、`retention.d1/d7` 留存）。**`--prune` 之前必须先落这份**，
  否则删掉原始记录就再也拼不回来了；每天 04:10 的 cron 里 `--all` 就干这件事。

### 5.1 公开统计页（2026-11-21 加）

地址：**https://wb.dkarbon.cn/enroute/**（同域 API `https://wb.dkarbon.cn/api/telemetry/public`）。
页面是单个 12 KB 的 `server/telemetry/web/index.html`，不引任何外链、不引图表库，
打开就 fetch 一次自己的 JSON，服务端给 60 秒缓存（`PUBLIC_TTL = 60`）。

页面上只有聚合数字：今日日活、累计设备数、记录了多少天、近 30 天每天多少台、
版本分布、用过的天数分布、D1/D7 回访、今日各事件次数。**一个设备标识都不出现在页面上**，
`build_public()` 里只做 len() 与计数，`i` / `d` 连读都不读出来。

挂载方式与 18081/18082 不同，值得记下来：

- 公开页挂在**已有的 TLS 站点** `wb2api`（`server_name wb.dkarbon.cn`，静态根 `/var/www`），
  页面落到 `/var/www/enroute/index.html`，`/enroute` 301 到 `/enroute/`。
- **不能复用同一段 snippet**：`wb2api` 里有一条 `location ~* ^/(v1|api)/` 正则块把 `/api/*`
  转给 workbuddy 网关（`127.0.0.1:7863`）。nginx 的正则 location 优先于普通前缀 location，
  照抄 `location /api/telemetry` 会被它截走。所以另写
  `/etc/nginx/snippets/enroute-telemetry-tls.conf`，用 **`location ^~ /api/telemetry`**（`^~` 抢在正则前）。
- `deploy.sh` 负责：装页面 → 写这份 TLS snippet → 用 python3 在 `    server_name wb.dkarbon.cn;`
  那一行后面插 include（已插过就跳过，幂等）→ `nginx -t && reload`。
- 静态目录带 `X-Robots-Tag: noindex, nofollow` 与 `Cache-Control: no-store`。

> **页面不是实时的**：`build_public()` 只读 `users.json` / `daily.json`，不数原始 `events-*.ndjson`。
> 这两份靠 cron 聚合刷新 —— 现在 cron 是**每小时**一次，所以页面上的「设备总数 / 留存 / 用龄」
> 最多滞后 1 小时；「今日日活 / 今日事件数」同样走日表，不是当场数。要更勤就改 cron。
>
> 这台开发机把 `wb.dkarbon.cn` 解析成了一个假 IP（`28.0.0.84`，代理的 fake-ip 模式），
> 从 Windows 直接 curl 会 `schannel: failed to receive handshake`。**不是服务器的问题** ——
> 在 WSL 里 curl 同一个域名是 200。看页面用浏览器（走系统代理），或在 WSL 里 curl。

## 6. 隐私边界（写死在代码里，不是承诺）

**不收**：学号、姓名、课程名、成绩、搜索词原文、坐标、标注文字、登录凭据、IMEI/ANDROID_ID/MAC、IP（只在内存限速桶）、UA 全串。

**收**：事件名、服务器时间、档位值、版本号、ABI、安装标识 `i`（本机随机 `installId` 的 SHA-256 前 64 bit，
不含学号/姓名/设备号/任何系统标识，也不可反推 `installId`）、当日标识 `d`（每天变）、会话标识（进程内随机 4 位）。

`i` 的存在是为了能算「总设备数 / 留存 / 用龄」——没有它，一组只按天统计的数字回答不了
「这个功能值不值得留」。边界写在明处：**`i` 只与 `i` 自己关联，不与任何校内身份关联**；
App 里没有任何把学号写进遥测的代码路径，`TelemetryTest` 里有一条测锁住「没有安装标识就不写任何身份字段」。

**关掉之后**：本机排队记录立刻删除；已在内存的 `session` 仍在，但不再写盘、不再上传；Worker 取消。

## 9. 2026-11-27：收数口与分发口的两处硬伤

### 9.1 出队只认 `accepted`，不认状态码

服务端对 schema 不认的行**不报错**，仍然回 200，把条数写进 body：`{"accepted":N,"dropped":M}`。
客户端原来 `code in 200..299 -> Result.Ok` 就 `dropFirst(pending.size)` —— 只要服务端丢了一行，
整批在本地也一起蒸发，两头都看不见。m40 以来真机上出现过 `{"accepted": 0, "dropped": 1}`：
本地删了、服务端没留，而界面什么都不说。

现在：

- `post()` 读 body，`countOf(json, "accepted")` / `countOf(json, "dropped")` 取数（取不到返回 -1，
  **不是 0** —— 老服务端没写 body 时退回「整批都收下」的旧口径，别把好数据卡在本地）。
- 出队数量 = `accepted.coerceIn(0, pending.size)`；有行被丢 → 记 `net.fail`（`where=telemetry, kind=parse`）
  + `DebugLog` + 降级成只发 `v`/`e`，下一批必定能过。
- 三次失败**不再 `queue.clear()`**（离线两天一联网就清空 = 白采），改成丢掉最旧的一半。
- 空批不再 413：`do_POST` 里 `n <= 0` 回 `200 {"accepted":0,"dropped":0}`。
  413 会让客户端当「被拒」整批丢弃，而空批本来就是正常的。

### 9.2 更新清单：自建源排第一

国内走 GitHub 靠运气（gh-proxy 时好时坏，raw 域名常被掐）。现在 `/app/` 由自己的服务器发：

| 顺序 | 地址 | telemetry `update.check.channel` |
|---|---|---|
| ① | `http://47.95.12.198:18082/app/latest.json` | `1` |
| ② | `https://gh-proxy.com/https://raw.githubusercontent.com/...` | `2` |
| ③ | `https://raw.githubusercontent.com/...` | `3` |
| ④ | `https://raw.githack.com/...` | `4` |
| ⑤ | `https://cdn.jsdelivr.net/...` | `5` |
| ⑥ | `https://fastly.jsdelivr.net/...` | `6` |

`UpdatePolicy.isAllowedSelfHost(url)` 把自建口钉死：scheme 必须 `http`、host 必须正好
`47.95.12.198`、端口必须 `18082`、path 必须以 `/app/` 开头。三层兜底照旧：地址钉死 → `sha256`
→ Android 包签名；所以自建口是明文也能接。APK 下载候选 = 镜像链 + 自建口（垫底，出口只有约 148 KB/s）。

`/app/` 只挂 18082：18081 那个 server 块早就有自己的 `location ^~ /app/`（speedtest.bin），
同一块里再写一个同名前缀会 `duplicate location`。
