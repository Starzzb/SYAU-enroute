# 计划：调试日志 v2（耗时字段 · 落盘 · 分级）

> 交给主代理执行。现状一句话：`DebugLog` 只有**内存环形缓冲 400 条，进程死即丢**，
> 且**没有任何耗时字段**——两个问题在「抓取优化」开工前必须先解决。
>
> 涉及文件：`data/DebugLog.kt`、`ui/debug/DebugScreen.kt`、`data/Prefs.kt`、
> `ui/user/SettingsScreen.kt`、`data/feed/FeedRepository.kt`（调用点）、新增 `data/DebugLogFile.kt`。

## 0. 现状与缺口（先对齐事实，别凭印象）

**已有的**（不要重复造）：

| 能力 | 位置 | 说明 |
|---|---|---|
| 内存环形缓冲 | `DebugLog.kt:34` | `MAX = 400`，`StateFlow<List<Entry>>` |
| 导出到本机 | `DebugScreen.kt:75-86` | 走 SAF `CreateDocument`，用户选目录，**不需要存储权限** |
| 复制到剪贴板 | `DebugScreen.kt:110`、`:197-199` | `dump()` 拼纯文本 |
| 清空 | `DebugScreen.kt:116` | 只清内存 |
| 分类 tag | 83 个调用点 / 15 个 tag | SESSION 14、FEED 9、CRED 7、HOME 5、URP 5… |

**缺的**（本轮要补）：

1. **耗时** — `http()` 签名（`DebugLog.kt:64-83`）没有时间参数，全仓零耗时记录。
2. **落盘** — 进程死、崩溃、被系统杀 → 日志全丢，而那正是最需要它的时刻。
3. **分级与保底** — 全部塞进同一个 400 条缓冲，FEED 的批量 HTTP 会把登录失败这类关键事件挤出去。
4. **不可事后回看** — 只有"当时点复制"这一条路。

## 1. 任务 D1：耗时字段（**最高优先，抓取优化的前置**）

### 改法

`DebugLog.http()` 增加可选参数：

```kotlin
fun http(
    tag: String, method: String, url: String, status: Int, bytes: Int,
    elapsedMs: Long = -1,          // 新增；< 0 表示未计时，不输出
    preview: String = "", note: String = "",
)
```

输出格式（只在 `elapsedMs >= 0` 时追加）：

```
← 200  12.3KB   820ms  GET jwc.syau.edu.cn/index/jwtz.htm
```

配套：

1. `DebugLog.step` 之外新增 `DebugLog.timed(tag, label) { ... }` 便捷包装，
   用 `System.nanoTime()` 计差值（**不要用 `currentTimeMillis`**，会受系统时间调整影响）。
2. `FeedHttp.get()`（`FeedHttp.kt:24`）内部自计时，回填 `Resp.elapsedMs`。
3. `FeedRepository.kt:105` 的每源日志改为带耗时：`教务通知：820ms · 1 页 · 15 条`。
4. `refresh()` 结束记总计：`刷新总计 8123ms · 14 源（成功 11 / 失败 3 / 未变 0）`。
5. `SyncReport` 增加 `elapsedMs: Long = 0`，供 UI 显示"本次刷新用时"。

### 验收

真机刷一次，调试页能看到每源耗时 + 总计；数字直接填进
`docs/计划-抓取并行与条件请求.md` 末尾的「实测记录」。

> 这一条**零风险、纯增量**，可以单独先合，不要等其它任务。

## 2. 任务 D2：落盘（本机保存）

### 2.1 原则

- **只落本机，永不上传**。没有网络代码，没有遥测，没有崩溃上报 SDK。
- **默认开启，可关**。设置页给开关；关了就连文件都不创建。
- **有上限**：按天分文件，保留 7 天，总大小封顶 **2MB**（约合 2–3 万行），超了就删最旧的一天。
- **不阻塞调用方**：`log()` 可能从主线程调用，写盘必须异步。

### 2.2 新文件 `data/DebugLogFile.kt`

```
filesDir/debug/
  ├── 2026-11-14.log
  ├── 2026-11-13.log
  └── ...
```

- 行格式与 `dump()` 一致：`HH:mm:ss.SSS  [TAG] 消息`，UTF-8，`\n` 结尾。
- **追加写**（`FileOutputStream(file, append = true)`），不做全量重写——崩溃时已写入的行不会丢。
- 写入策略：内存队列 + 单协程消费，**每 500ms 或攒够 20 行 flush 一次**。
  不要每行 open/close（频繁 I/O 反而拖慢）。
- 进程结束时尽力 flush：`Application.onTerminate` 不可靠（Android 常不调用），
  所以靠"频繁 flush"而非"退出时保存"——**这是关键取舍，不要指望 onTerminate**。
- 所有 I/O 包 `runCatching`：写日志失败绝不能影响业务。

### 2.3 轮转与清理

- 每次启动时检查一次：删除超过 7 天的 `.log`；若总大小 > 2MB，从最旧的删到合格。
- 天数与上限写成常量（`MAX_DAYS = 7`、`MAX_BYTES = 2 * 1024 * 1024`），不要散在代码里。

### 2.4 脱敏（**落盘后风险变高，必须做**）

内存里丢就丢了，落盘意味着文件可能被导出、被别的 App 读到。`DebugLog.kt:19-21`
已有"绝不记密码"的铁律，落盘要再加一层**主动脱敏**：

写入前对整行做正则替换，命中以下模式一律替换成 `***`：

| 模式 | 例子 |
|---|---|
| Cookie / Session | `JSESSIONID=...`、`student.urpSoft.cn=...`、`CASTGC=...` |
| CAS 票据 | `lt=...`、`ticket=...`、`execution=...` |
| 密码类字段 | `password=`、`pwd=`、`passwd=` |
| 通用 token | `token=`、`access_token=`、`Authorization: ...` |

> 注意：`DebugLog.kt:19` 说的是"登录 POST 的 body 只记字节数"，那条已经安全；
> 但**响应头里的 Set-Cookie** 和 **URL 里的 query token** 目前会原样进日志，
> 落盘前必须挡住。`UrpHomeApi` 与 `Academic` 的路径里带随机 token（见 `Academic.kt:28-34`），
> 会出现在 `shortUrl()` 输出里，同样要脱敏。

### 2.5 设置页入口

`SettingsScreen` 的调试入口附近加：

- 开关：`保存日志到本机`（默认开，写 `Prefs.debugLogToFile`）
- 一行状态：`已占用 412KB · 保留 7 天`
- 按钮：`清空历史日志`（删目录下全部 `.log`，**不动内存缓冲**）
- 按钮：`全部导出`（把 7 天日志打包成一个 txt，仍走 SAF）

### 2.6 调试页（`DebugScreen.kt`）改动

沿用现有工具条，补：

- **级别过滤**：全部 / 警告+ / 仅错误（chip 或分段控件，保持 0 圆角 token 风格）
- **历史日志入口**：列出 `filesDir/debug/` 下按日期份的文件，点开可读、可导出单日
- **清空**按钮语义拆开：`清空当前`（内存，现有行为）与 `清空历史`（文件）
- 顶部计数补一句 `· 落盘 412KB`（关闭保存时不显示）

## 3. 任务 D3：分级与错误保底

### 改法

1. `Entry` 增加 `level`：`DEBUG / INFO / WARN / ERROR`。
   - 现有 `log()` → INFO；`step()` → DEBUG；`error()` → ERROR；
     `http()` 按状态码自动判（2xx → INFO，4xx/5xx → WARN，异常/`-1` → ERROR）。
2. **错误保底缓冲**：除主环形（400 条）外，另存最近 **50 条 ERROR**，
   独立 `StateFlow`，不被批量 DEBUG 冲掉。调试页"仅错误"直接读它。
3. 过滤在**读取侧**做（`DebugScreen` 里），不要在写入侧丢数据——
   否则用户切了过滤器再切回来，日志已经没了。

### 验收

造 500 条 DEBUG + 3 条 ERROR，确认"仅错误"仍能看到那 3 条。

## 4. 顺序与依赖

```
D1 耗时字段（独立可合）
   ├─→ 服务于「抓取并行与条件请求」的基线测量
   └─→ D2 落盘 / D3 分级
```

- **D1 必须先做**，因为抓取优化计划卡在"没有基线"。
- D2 与 D3 可同一批；D2 的脱敏**不能省**（落盘后风险等级提高）。
- **不要和抓取并行化同一提交**：日志改动面广（牵动 FeedHttp/FeedRepository），
  混在调度改动里出问题难定位。

## 5. 验收标准

| 项 | 要求 |
|---|---|
| 编译 | `compile-check.bat` 通过 |
| 单测 | 既有 **102 条全绿** |
| 新增单测 | 见下，≥ 6 条 |
| 耗时可见 | 真机刷新后能看到每源 ms + 总计 ms |
| 落盘生效 | 杀进程重进，调试页能读到上一次会话的日志文件 |
| 上限生效 | 造 3MB 日志，启动后被裁剪到 ≤ 2MB / ≤ 7 天 |
| 脱敏生效 | 日志里搜不到 `JSESSIONID`、`CASTGC`、`ticket=`、`token=` 的真实值 |
| 关闭开关 | 关掉后 `filesDir/debug/` 不再新增文件 |
| 不阻塞 | 主线程连续 `log()` 1 万次，无 ANR、耗时可接受 |
| release 安全 | 导出的日志不含密码、不含完整 Cookie |

### 新增单测（JVM，不依赖 Android 文件系统的地方用临时目录抽象）

1. **脱敏**：喂含 `JSESSIONID=abc`、`token=xyz`、`password=123` 的行，断言输出全为 `***`。
2. **行格式**：`dump()` 与落盘行格式一致（同一 `formatLine()`，避免两套）。
3. **轮转**：伪造 8 个日期文件，启动后只剩 7 个且删的是最旧的。
4. **大小上限**：伪造超限文件，裁剪后总量 ≤ `MAX_BYTES`。
5. **分级判定**：`http(200)` → INFO；`http(500)` → WARN；`elapsedMs = -1` 的异常 → ERROR。
6. **错误保底**：灌 500 条 DEBUG 后，ERROR 缓冲仍保留最近 50 条且顺序正确。
7. **异步 flush 顺序**：并发调用 `log()`，落盘顺序与内存顺序一致（单消费者保证）。

> 文件系统相关逻辑请把根目录作为构造参数注入（`DebugLogFile(root: File)`），
> 单测传临时目录即可，不要用全局 `filesDir`。

## 6. 红线复述

- **不上传**：本轮不新增任何网络调用。
- **不记密码**：`DebugLog.kt:19-21` 的三条铁律继续有效，落盘额外加脱敏。
- **不影响业务**：任何日志 I/O 失败都必须被 `runCatching` 吞掉。
- **release 也要能关**：开关存在 `Prefs`，release 版同样生效（不要用 `BuildConfig.DEBUG` 写死）。
