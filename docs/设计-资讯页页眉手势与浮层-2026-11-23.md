# 资讯页页眉手势与浮层位置（2026-11-23）

主人报两处：①上滑收页眉正常，下滑之后页眉灵敏度极低、很久才归位甚至再也不回来；
②页头 ⋯ 与「我的」⋯ 弹出的浮层背景糊成一片、位置也比按钮偏一截。

## 一、页眉收不回来：两个叠在一起的真凶

文件：`app/src/main/java/cn/dkarbon/enroute/ui/feed/FeedScreen.kt`

### 1. 吸附动画把自己打断了（「慢慢移动、很久才归位」）

旧写法：

```kotlin
snapshotFlow { collapse.floatValue }.collectLatest { v ->
    delay(140)
    animate(v, target, tween(180)) { value, _ -> collapse.floatValue = value }
}
```

`snapshotFlow` 观察的正是动画自己要写的 `collapse` —— 每写一帧就触发一次新值，
`collectLatest` 立刻取消上一轮并重新 `delay(140)`。净效果是每 140ms 只推进一帧，
180ms 的动画被拉成好几秒，肉眼就是「爬」回去。

改法：另起一根只由手势驱动的心跳。

```kotlin
val touchTick = remember { mutableIntStateOf(0) }          // 手势帧 +1
snapshotFlow { touchTick.intValue }.collectLatest {        // 只被新手指打断
    delay(120); val start = collapse.floatValue
    if (start <= 0f || start >= 1f) return@collectLatest
    animate(start, if (start >= 0.5f) 1f else 0f, tween(Motion.base)) { v, _ -> collapse.floatValue = v }
}
```

### 2. 下滑要「两次手势」才动（「完全不归位」）

旧 `onPreScroll` 要求 `available.y > 0 && atTop`，而 `atTop` 用
`firstVisibleItemIndex == 0 && firstVisibleItemScrollOffset == 0` 精确判等。
第一次下滑把列表送回顶部（页眉一动不动），第二次下滑时偏移量已经不是严格 0，判等失败 ——
页眉彻底不回来，只能重进页面。

改法：

- `atTop()` 放宽到 `firstVisibleItemScrollOffset <= 1`；
- 列表已经到顶还继续下滑时，直接吃掉余量放回页眉（`onPreScroll` 返回 `Offset(0f, 吃掉量)`）；
- 新增 `onPostScroll`：列表把手势吃完后剩下的下滑量也拿来放回页眉。
  于是**一次下滑手势就能「先滚回顶部、再顺势叫回页眉」**。

### 3. 放回给 3 倍增益

`private const val RevealGain = 3f` —— 收起仍 1:1 跟手（页眉跟着内容走，不跳）；
放回只要滑满页眉高度的三分之一（典型页眉 81dp，≈27dp 手指位移）。主人要的是「迅速归位」。

## 二、浮层位置与模糊

文件：`app/src/main/java/cn/dkarbon/enroute/ui/kit/AnchoredCard.kt`

### 位置偏移：右半屏按钮被当成左对齐

旧版一律 `rawLeft = anchor.left`。页头 ⋯ 在 x≈1020/1080，304dp 的卡片从那里往右铺，
必然越界，再被 `coerceIn` 拽回屏幕内几百 px；折角也跟着被挤到 `width - 20` 的钳位点，
读起来就是「先错位再挪过去」。

现在右半屏（`anchorCenterX > screenW / 2`）改为**右对齐**：`left = anchor.right - width`，
卡片右边缘贴按钮右边缘，整块落在屏幕内。`pivotFrac` 钳位从 (0.12, 0.88) 放宽到 (0.06, 0.94)，
折角能真正指到 ⋯ 上。

开口动画删掉 `translationY = (1f - v) * -8.dp`，缩放 0.9→0.94 起，只从折角那个点轻轻张开。

### 模糊：12/20/28dp 在 3 倍屏上是 33–77px

| 档 | 旧 | 新 |
|---|---|---|
| T1 | 12 dp | 6 dp |
| T2（默认） | 20 dp | 9 dp |
| T3 | 28 dp | 14 dp |

卡片自身的 `opaquePaper` 没动 —— 背后还能认出是列表，但字不会跟卡片正文抢对比度。

## 三、真机验证（TYH601M / 1080×2400，0.10.0+m41）

1. 资讯页上滑 → 页眉整块收起，列表顶到状态栏下；
2. **一次**下滑 → 列表回顶、页眉同一次手势里归位（旧版要两次，且第二次常常失败）；
3. 页头 ⋯ → 浮层右对齐贴住按钮，折角在按钮正下方，背景能认出条目文字；
4. 我的 ⋯ → 同上（同一组件，改一处两处都好）。
