# 培养方案页 表格显示 — 现状勘察

> 日期：2026-11-15（真机掉线，本报告为代码推断 + 资产数据实测 + 现有单测对照）
> 页面文件：`app/src/main/java/cn/dkarbon/enroute/ui/curriculum/CurriculumScreen.kt`
> 数据模型：`data/curriculum/CurriculumModels.kt`（`creditTable` / `semesterTable` 为原样行列）
> 解析：`data/curriculum/CurriculumParse.kt`（`table()` 只取第一张表，保持原始单元格文本）
> 锁结构的测试：`app/src/test/java/cn/dkarbon/enroute/CurriculumParseTest.kt`

## 一、页面里实际有几种「表格」

四种展示形态，其中**两张是真表格**，两张不是：

| 展示形态 | 组件 | 是否真表格 |
|---|---|---|
| 学分结构表 | `TableBlock(title, plan.creditTable)` | ✅ 真表格（行列原样） |
| 各学期学分分配表 | `TableBlock(title, plan.semesterTable)` | ✅ 真表格 |
| 课程设置（按学期分组） | `CourseRow` 卡片列表 | ❌ 卡片，非表格 |
| 事实卡（主干学科/核心课程等） | `Row` 键值对 | ❌ 键值对 |

## 二、两张真表格的形状（扫 169 份 plan_*.json 资产实测）

**学分结构表 `creditTable`**
- 列数分布：4 列 ×6 份、6 列 ×45 份、7 列 ×115 份（无参差行，min==max）
- 行数分布：5~18 行，主流 14 行 ×58 份、15 行 ×48 份、18 行 ×30 份
- 表头行数：7/6 列版 = 2 行（首行 `教育环节|课程平台|…`，次行续 `限制性选修课（限修课）`）；
  4 列版（2023 卓越/实验班）= 1 行。**表头行数不固定**。
- 最长单元格：146 字（2023 农学卓越班「要求达到50 学分。其中…」整段塞进一格）
- 数字列：必修课/选修课/限修课/小计等；出现 `—` / `——` / `%`（如 `53.9%`）与小数

**各学期学分分配表 `semesterTable`**
- 列数分布：8 列 ×8 份、10 列 ×152 份、12 列 ×6 份；行数 3~5 行，主流 4 行 ×151 份
- 表头行数：恒 1 行（首格 `学期`，后随 `1..10`、`合计`）
- 第一列是文字标签（必修课/专业方向限修课/拓展必选课/合计），其余列全是数字或空

## 三、现状代码行为（TableBlock）

- 列宽：固定 `j==0 → 96.dp`，其余一律 `82.dp`（列宽确定 ✓，但文字列偏窄、数字列偏宽）
- 表头/数据对齐：同一段 `forEachIndexed` 循环、同一套 `w`，**结构上已经对齐** ✓
- 横向滚动：`Row.horizontalScroll` 包住整个 `Column`，表头随表一起滚 ✓
- 单元格换行：无 `maxLines` → 任意换行，**146 字格会撑出 20 行高的巨格**（问题点）
- 对齐：全部 `TextAlign.Center`，**数字列没有右对齐**（违反硬要求 5）
- 表头样式：`i <= 1` 一律当表头加粗/换底色 → 各学期学分分配表把第一行数据（必修课）误当表头；
  4 列版学分结构表把第一行数据误当表头（违反「表头与数据区分」的观感）
- 空值：原样显示；原表空就是空格，不填 0（✓ 诚实规则无违规）

## 四、结论：要改的点

1. `TableBlock`：数字列右对齐、文字列左对齐；数字列窄列宽、文字列宽列宽
2. `TableBlock`：数据单元格 `maxLines=3 + Ellipsis`（表头放宽到 4 行，防长表头被吃）
3. `TableBlock`：表头行数按首格（`教育环节`/`学期`/空）推断，不再写死 2
4. `CourseRow`：课程名 `maxLines=3 + Ellipsis`（规则 2 的「长课程名设上限」）
5. 横向滚动、表头随表滚、表头数据同源列宽：现状已满足，保持不变
