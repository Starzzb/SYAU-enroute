# 07: 新前端设计方案 —— 要「效果差异」，不是「换套颜色」（只出文档 + HTML 原型）

**What to build:** 一套能让用户一眼看出「这是另一个 App」的前端设计方向，
并给出可直接照做的规格与可交互原型。主人明确否定了当前做法：
> 「红线要求过于苛刻，导致两种风格只有配色变化较明显。可以抛弃设计红线，要的是不同效果对比。」

所以现有第二套「学院纸本 / E-Ink」（只换 token 值、布局与组件完全不变）**不算数**，
这一票要拿出**结构层面就不同**的方案。

**Blocked by:** None (can start immediately)

**Status:** ready-for-human

## 要产出什么

**2~3 个方向**，每个方向必须同时改变这几层（这是「效果差异」的定义）：

1. **布局骨架**：页面分区方式、导航形态、信息密度节奏（例：满屏网格 / 单栏长读 / 分栏报纸 / 卡片瀑布）
2. **组件形态**：卡片形状与边界、圆角、阴影/描边/留白谁承担层级、列表行 vs 卡片行的选择
3. **层级与强调规则**：标题层级、数字的角色、颜色承担什么语义（允许放弃 0 圆角、允许渐变/阴影/纹理）
4. **动效与反馈**：过渡时长与曲线、按压/滚动反馈、加载形态（是否允许 shimmer）
5. **字体与排版**：可换字族、字号阶梯、行高、中英混排策略
6. **色板**：给全（bg/surface/on-surface/text-secondary/border/accent/danger/success/warn），
   并给**实测对比度**（正文 ≥4.5:1、大字 ≥3:1、图标按钮可感知）

每个方向还要写清：**代价**（性能、实现工作量、可读性退化点、与「农学工具」调性的冲突）、
**最适合哪些页面**（课表 / 资讯流 / 考试 / 成绩 / 主页 / 空闲教室），
以及**数据诚实如何继续保证**（空态、暂缺、不编数字 —— 这条不许为了好看而放弃）。

## 验收标准

- [ ] 至少 2 个方向，且每个方向在**布局骨架**和**组件形态**两层都与现状明显不同（不是换色）
- [ ] 每个方向 6 层都写到位，数值具体
- [ ] 色板给全并附对比度实测值（自己算，写出计算依据）
- [ ] 每个方向都写了代价与适用页面，不是只写优点
- [ ] HTML 原型能打开、能切换方向、三屏齐全，且假数据有标注
- [ ] 数据诚实原则在每个方向里都有对应规定（空态/暂缺/不编数字）
- [ ] 本票**不改动任何 app 源码**
