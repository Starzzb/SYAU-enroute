## 2. 版本号规则

`app/build.gradle.kts`：

```kotlin
versionCode = 19          // 必须单调递增，Android 用它判断「是不是更新」
versionName = "0.1.0-m19" // 展示用；mNN 对应里程碑
```

发版时两块都要改，**versionCode 只能加不能减**（装低版本会失败：`INSTALL_FAILED_VERSION_DOWNGRADE`）。

## 3. 签名（**发版前必须处理一次**）

现在 `signingConfig = signingConfigs.getByName("debug")` —— 用的是 Android 通用调试密钥。
后果：**能覆盖安装，但包是可调试的（debudgable），不适合长期分发**。

一次性做一次正式签名（之后所有版本沿用，**换了签名就不能覆盖安装**）：

```powershell
keytool -genkeypair -v -keystore O:\dev\keys\enroute-release.jks `
  -alias enroute -keyalg RSA -keysize 2048 -validity 10950 `
  -storepass <自己定> -keypass <同上>
```

然后把 keystore 放在**仓库外**（`O:\dev\keys\`），`build.gradle.kts` 里从
`local.properties` 或环境变量读密码 —— **`.jks` 与密码永不入库**（`.gitignore` 已忽略 `*.jks`）。

> 现在内测阶段可以先继续用 debug 签名（能覆盖安装），但一旦对外给同学用，先换成 release 签名。
> **换签名那一刻，所有人的旧包必须卸载重装一次**，之后才能持续覆盖更新。

## 4. 怎么发更新包（三条路，按场景选）

### A. 内测直发 APK（现在最合适）

产物：`app\build\outputs\apk\debug\app-debug.apk`（约 22MB）
直接发微信/QQ/网盘，对方点开安装。
**前提**：versionCode 比已装的大，且签名一致。

### B. 自建下载页（推荐，长期）

你已经有服务器、域名、nginx，加一个静态目录即可：

```
/var/www/app/
  latest.json          # {"versionCode":20,"versionName":"0.1.0-m20","url":"...","sha256":"...","size":23000000,"notes":"..."}
  enroute-0.1.0-m20.apk
  enroute-0.1.0-m19.apk   # 留一版回滚
```

nginx（走已开放的 18081 明文口，理由同 cet6：手机链路上 TLS 会被 RST）：

```nginx
location ^~ /app/ {
    alias /var/www/app/;
    autoindex off;
    add_header Cache-Control "no-cache" always;   # latest.json 不能缓存
    add_header X-Robots-Tag "noindex, nofollow" always;
}
```

发版脚本（本机执行）：
1. 改 `versionCode`/`versionName`
2. `build-test.bat`
3. 算 sha256、生成 `latest.json`
4. `scp` 上去

### C. GitHub Releases

可以挂 tag 附件，但**国内下载慢且 GitHub 常被墙**，只作备份存档，不作主渠道。

## 5. App 内「检查更新」（待实现，票 15）

设计要点（避免做成流氓更新）：

- 手动触发为主：设置页「检查更新」；启动时**每天最多静默检查 1 次**，且只提示不打扰
- 流程：`GET latest.json` → 比 `versionCode` → 有新版弹一行动作条「有新版本 m20 · 查看」→
  用户点了才下载 → 下载完提示「安装」
- 下载校验 `sha256`，不匹配就丢弃重下（防劫持/防半截包）
- 安装走 `FileProvider` + `ACTION_VIEW`（`application/vnd.android.package-archive`），
  需要 `REQUEST_INSTALL_PACKAGES` 权限与 `<queries>` 声明
- **不静默安装、不后台自动下大包、不弹全屏广告式弹窗**

## 6. 每次发版的 7 步清单

1. 改 `versionCode` +1，`versionName` 改成 `0.1.0-mNN`
2. `O:\dev\enroute-android\build-test.bat` → 确认 `BUILD SUCCESSFUL` 且单测全绿
3. 真机装一次，跑一遍关键路径（课表 / 空闲教室 / 校园地图 / 登录态）
4. `git add -A && git commit -m "release: mNN …"`
5. `git tag -a v0.1.0-mNN -m "…"` → `git push` + `git push origin --tags`（带代理）
6. 传 APK 与 `latest.json` 到服务器 `/var/www/app/`（路径 B）
7. 内测群里发一句「已更新到 mNN，更新内容：…」

---

## 7. 回滚

- 服务器**保留上一版 APK**，出问题就改 `latest.json` 指回旧版
- 但 `versionCode` 不能降级 → 回滚要**把旧代码重新打一个新 versionCode 的包**
  （`git checkout <旧tag>` → 改 versionCode 更大 → 重新打包）
- 别删 tag，那是唯一可靠的「回到某个可用状态」的锚点
