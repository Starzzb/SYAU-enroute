# 沈阳农业大学（SYAU）信息发布平台与信息渠道清单

> 调研时间：2026-11-10
> 用途：「沈农在途」Android 课表/教务 App 的信息聚合选型
> 方法：直接抓取 `syau.edu.cn` 站群真实 HTML（提取 href）、逐个子域名 HTTP 探测（状态码 + `<title>`）、微信公众号文章页元数据反查。**下文标注「未确认」的条目表示本次未能取得可验证证据，请勿直接写进代码。**

## 总览

沈阳农业大学的信息化是典型的「**一个 CAS 统一身份认证（tpass）+ 一个信息门户（portal）+ 一个站群 CMS**」的三层结构：所有业务系统（本科教务 URP、研究生管理、学工、财务、科研、OA）都是内网 IP 上的独立老系统，靠 `pass.syau.edu.cn` 的 CAS 单点登录串起来，再以卡片形式挂在 `portal.syau.edu.cn` 信息门户里；对外宣传口径则全部由**西安博达（VSB）站群系统**承载，全校 30+ 个二级站点共用同一套 URL 规则（`/info/{栏目ID}/{文章ID}.htm`、`list.jsp?...wbtreeid=XXXX`），这意味着**写一个解析器就能同时吃下几乎所有校级和院级网站**——这对 App 聚合是最大的技术红利。

关键结论（与任务背景的交叉验证）：

- ✅ `10.2.0.47` 确认是**本科教务系统学生端**（URP），响应头 Cookie 为 `student.urpSoft.cn`，登录页最终跳到 `pass.syau.edu.cn` 统一身份认证。`10.2.0.48` 是教师端。
- ⚠️ **`jw.syau.edu.cn` 不是教务系统，是「校纪委（监察专员办）」**（`jw`=纪委）。任务背景里「`jw.syau.edu.cn` → 210.47.162.3 教务」的判断是错的，不要按这个写。
- ✅ 存在一个「校园网址导航」`guide.syau.edu.cn/t1/`，官方维护、无需登录，把全校所有系统和内网地址都列全了——这是摸清家底的最优入口。

## 技术要点：为什么「一个解析器能吃下 30+ 站点」

实测所有校级/院级站点共用**西安博达 VSB 站群系统**，特征与统一规则：

- 静态资源：`index.vsb.css`、`_sitegray/_sitegray_d.css`
- 栏目列表页：`/info/{栏目ID}/{文章ID}.htm`；或 `list.jsp?urltype=tree.TreeTempUrl&wbtreeid={栏目ID}`
- 栏目页常另有美化路径：`index/tzgg.htm`、`index/jwtz.htm`、`tzgg.htm`、`xgdt.htm` 等（本质仍是同一 CMS 输出）
- 文章正文页：`content.jsp?urltype=news.NewsContentUrl&wbtreeid={栏目ID}&wbnewsid={文章ID}`
- 全部列表页都是**服务端渲染的纯 HTML**，无 JS 依赖、无登录、无签名 → 直接 HTTP GET + 正则/HTML 解析即可，不需要无头浏览器

已确认的常用栏目 ID：校级通知公告 `1144`，校内通知 `1295`，教务处通知 `1248/1249/1250/1251`（按科室），学生处通知公告 `1048`，学工日程 `1049`，团委通知 `1053`，信息公开行政文件 `1013`。

HTTPS 情况：`www / news / jwc / grs / xsc / tw / lib / zs / job / xxgk` 均支持 HTTPS（200，HTTP 会 302 跳转到 HTTPS）；`oa.syau.edu.cn` 的 HTTPS 不通，只能走 HTTP。

## 做 App 聚合的 Top 5 建议

### 1️⃣ 本科教务 URP（`http://10.2.0.47/`）—— 产品的地基
**为什么**：课表、成绩、考试、选课，这是「沈农在途」存在的全部理由，其他渠道都是锦上添花。
**怎么拿**：这是 URP 系统（响应头 `Set-Cookie: student.urpSoft.cn=...`），登录入口最终跳 `pass.syau.edu.cn/tpass/login`，走标准 CAS。工程上只有一条正路：**用户在 App 内输入自己的统一认证账号密码 → App 用 OkHttp 会话（持久化 Cookie）登录 CAS → 访问课表/成绩页面并解析 HTML**。注意三个硬约束：(a) 必须校内网或 WebVPN，公网直连不通，需在 UI 上明确提示；(b) `Server: Tengine` 后面可能挂 WAF，请求头要模拟浏览器；(c) **只同步当前登录用户自己的数据**，绝不缓存他人课表——这是合规红线，也是能不能上架的分界线。备选兜底：提供「手动导入/截图识别课表」，让无法连校内网的用户也能用。

### 2️⃣ 教务处通知（`https://jwc.syau.edu.cn/index/jwtz.htm`）—— 性价比之王
**为什么**：选课、补退选、重修班、考试安排、转专业、论文——全是学生会因为「没看到」而吃亏的信息，且**无需登录、公网可达、纯静态 HTML**。
**怎么拿**：GET 列表页 → 正则提 `href="info/{栏目}/{id}.htm"` + 标题 + 日期（列表已是「[科室] 标题 日期」结构）→ 需要正文再 GET 详情页，抽 `.v_news_content` 之类正文容器。约 3–4 条/周，做增量 diff 即可。同法可顺手并进 `index/jwxw.htm`（教务新闻）与 `zhxz/xl.htm`（校历，用来算教学周）。

### 3️⃣ 学校通知公告 + 新闻网（`www.syau.edu.cn/index/tzgg.htm`、`news.syau.edu.cn`）—— 一次解析，全校通吃
**为什么**：这两个是「校级权威口径」，日更 2–3 条，覆盖停水停电、校园限行、体检、评奖、招聘等生活刚需。更关键的是它们和教务处、学生处、16 个学院**共用同一套博达 CMS**，写完一个解析器就等于接入了 30+ 个站点。
**怎么拿**：抽象出 `VSBListParser(baseUrl, columnPath)`，输出统一的 `{title, url, date, column, source}`，用栏目 ID 做路由表。建议给通知打「教务/学工/生活/招聘」的轻量分类标签，做定向推送而不是全量轰炸。

### 4️⃣ 学生处通知公告（`http://xsc.syau.edu.cn/tzgg.htm`）—— 学生最在乎的「钱」和「评优」
**为什么**：国家奖学金/励志奖学金/助学金公示、助学贷款、医保参保、评优表彰——这类信息漏看一次就是真金白银的损失，而它的曝光度远低于教务通知，用户对「帮我盯着」的付费/留存意愿最高。
**怎么拿**：与 #3 同一套解析器（栏目 ID `1048`），约 2 条/周。可额外接 `xsc.syau.edu.cn/mzgz.htm` 的《学生工作日程》（每周 1 条），做成本周的学工事项提醒。学工系统 `210.47.163.44` 涉及个人隐私数据，建议**只在用户主动登录后读取本人信息**，不做后台抓取。

### 5️⃣ 统一身份认证 + 信息门户（`pass.syau.edu.cn`、`portal.syau.edu.cn`）—— 把「一次登录、全校通行」做出来
**为什么**：全校所有业务系统共用 tpass CAS，这是唯一能把你从「一个课表 App」升级成「校园入口」的抓手。做好一次登录，后续接办事大厅（审批/报修/出入校报备）、企业微信通知、研究生系统都只是加卡片。
**怎么拿**：实现标准 CAS 客户端——`GET pass.syau.edu.cn/tpass/login?service={教务或门户地址}` → 取 `execution`/`lt` 隐藏字段 → `POST` 账号密码 + `service` → 跟随 302 拿 `TGT/TGC` Cookie → 用同一 Cookie 访问各业务系统的 `service` 地址。**务必把凭据只存在 Android Keystore/EncryptedSharedPreferences，不上传服务器**；登录态失效时给「一键重登」而不是静默失败。若做服务端聚合，则强烈建议只抓 #2/#3/#4 这类**公开无需登录**的静态页面，私有数据走端上直连，规避合规与封号风险。

**一句话取舍**：MVP 阶段先做 #2 + #3 + #4（零登录、纯静态、一个解析器全覆盖，2 天能出成果），把 #1 作为核心体验单独打磨，把 #5 留到做「校园入口」叙事时再上。
