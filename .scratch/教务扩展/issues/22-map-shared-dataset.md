# 22: 众包数据共享 —— 以服务器为准 + 增量拉取 + 上传者信息

**What to build:** 把地图标注从「单向上报」改成**共享数据集**：
服务端成为信息基准，客户端按版本增量拉取，并把上传者信息（机型/设备标识）一并收集。

**Blocked by:** 无

**Status:** ready-for-agent

---

## 主人决策（2026-11-14，推翻票 21 的 wontfix）

> 「现在阶段就也可以收集上传者信息到服务器，**以服务器为信息基准**，一般只有服务器更新字段才进行拉取，
> 这个信息数据是连接服务器共享的，服务器只做这个上传数据的保存，之后客户端还可以拉取最新的数据，
> **硬件标识、机型都可以收集**，这种属于用户画像识别，不碍事」

四条都要：① 收集上传者信息（含机型/设备标识）② 服务器为基准 ③ 服务器字段更新时才拉取 ④ 数据共享。

**票 21（下行 wontfix）作废**，理由与红线保留在票里作历史记录即可。

## ⚠️ 两个技术现实（不是反对，是实现前必须知道）

### 1. 「硬件标识」在 Android 10+ 拿不到真的

IMEI / 序列号自 Android 10 起对普通应用**完全不可读**（`READ_PHONE_STATE` 也不行，只有设备所有者/运营商应用可以）。
可稳定拿到的是：

| 字段 | 来源 | 稳定性 | 备注 |
|---|---|---|---|
| `manufacturer` / `model` / `device` | `Build.*` | 固定 | `V2301A` 这类 |
| `sdkInt` / `release` | `Build.VERSION.*` | 固定 | Android 16 / API 36 |
| `ssaid` | `Settings.Secure.ANDROID_ID` | **按「应用+签名+用户」派生** | 换应用即变；恢复出厂会变 |
| `installId` | 本地生成的 UUID | 自己控制 | 卸载重装会变 |
| `did` | 现有匿名随机串 | 自己控制 | 可重置 |

**结论**：能收集的是「机型 + 系统版本 + 应用级设备标识」，**不是真正的硬件序列号**。票里按这个实现，别写"采集 IMEI"这种做不到的承诺。

### 2. 服务器为基准，会和「用户自己的改动」打架

如果严格「服务器值覆盖本地」，用户刚填完、还没上传成功，下一次拉取就把它冲掉了 —— 用户会觉得「我填的被吃了」。

**建议的显示优先级**（请按这个实现，并在界面上标清来源）：

```
① 本地待传/刚填的标注   ← 最高（只在你自己机器上，且标「待上传」）
② 服务器共享数据        ← 基准（标「共建」）
③ 安装包内置 asset      ← 兜底（标「内置」）
```

①②③ 都要有**可见的来源标记**。这样"以服务器为基准"成立（别人的数据、以及你上传成功后的数据都以服务器为准），
同时不会把本地刚填的东西吃掉。

## 服务端（要动线上 `server.js`，这次授权动）

新增两个只读端点，都**不需要 admin key**（只读、匿名）：

1. **`GET /map/api/dataset?mapVersion=&since=`**
   返回聚合后的数据集（不是原始补丁流），字段与客户端 `edits.json` 同构，便于直接落地：
   ```json
   {"schema":1,"mapVersion":"2026.11.14-1","rev":42,"updatedAt":"2026-11-14T18:40:00+08:00",
    "features":{"f19":{"字段":"值"}}, "fields":["层数","所属单位"]}
   ```
   - `rev` 每次数据落盘后自增（**这就是「服务器更新了」的判据**）
   - `since=<rev>` 时只返回 `rev > since` 的增量（客户端首次拉全量，之后拉增量）
   - 加 `ETag`/`If-None-Match` 支持，304 直接省流量

2. **`GET /map/api/stats`**（可选，便于排查）
   返回补丁总数、特征数、最近更新时间。

**数据聚合口径**（服务端做，别让客户端猜）：
- 同一 `(featureId, field)` 取 **`ts` 最新**那条
- `op=delete` 视为删除该字段
- 只聚合 `op ∈ set/addField` 的结果，`addField` 只贡献字段名

**上传者信息**：`POST /map/api/patches` 的 `client` 块接受并落盘
`manufacturer/model/device/sdkInt/release/ssaid/installId`。
**`sid`（学号）仍然不传** —— 主人说的是收集机型与设备标识，没说要学号；这条保持不变，除非另行指示。

## 客户端

1. **拉取**：进地图页时若 `距上次检查 > 5 分钟` 或用户手动点「同步」，发 `GET /map/api/dataset?since=<本地rev>`
   - 304 / `rev` 不变 → 什么都不做（这就是「只有服务器更新字段才拉取」）
   - 有变化 → 落 `filesDir/map/server_data.json`（原子写：`.tmp` + rename）
   - **不阻塞界面**，失败静默重试（退避同上传）
2. **显示**：优先级按上面 ①②③，信息卡每个字段标来源
3. **上传**：`client` 块补上机型/设备标识（**必须有开关**，与共建上传同一个开关，且「会传什么」弹窗里逐项列出）
4. **首次确认弹窗要改文案**：现在写的是「不含机型、硬件标识」，改完必须如实列出：
   - ✅ 传：地块 UID、字段名、字段值、时间、机型与系统版本、应用级设备标识（本地随机）
   - ❌ 不传：学号、姓名、定位、通讯录、相册

## 验收

- [ ] 服务端 `GET /map/api/dataset` 返回 `rev`，且每次写入补丁后 `rev` 递增
- [ ] 客户端第二次拉取带 `since` 后，`rev` 未变时**不产生流量**（304 或空增量），且界面无闪烁
- [ ] 别人上传的字段能在本机显示，标「共建」
- [ ] 本机刚填未上传的字段显示为「待上传」，**不会被服务器数据冲掉**
- [ ] 上传成功后再拉取，该字段来源从「待上传」变「共建」，值一致
- [ ] 内置 asset 的字段标「内置」，服务器有同名字段时被服务器覆盖
- [ ] `client` 块含机型与设备标识；**弹窗如实列出这些项**
- [ ] 学号仍然 0 命中（服务端磁盘 grep）
- [ ] 单测：`since` 增量合并、`rev` 比较、来源优先级（三档）、`delete` 生效、304 处理

## 红线

- **来源必须可见**（待上传/共建/内置），不能让用户分不清哪条是谁的
- **`sid` 不传**（除非另行指示）
- 拉取失败**不许阻塞**地图渲染；断网时用本地缓存照常显示
- 服务器只做保存与聚合，不参与任何鉴权外的判断（无账号体系）
- 基线 **454 条 / 36 类 / 0 失败**
