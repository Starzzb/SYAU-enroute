② 项目底层：一张树看完

单 Activity、无 NavHost、无第三方 UI 组件库；主题与状态各自只有一个源头。
MainActivity  ·  setContent { … }
└── EnRouteTheme(themeMode, styleSet, colorSource, customPalette)
    ├── LocalInkTokens / LocalPrimaryInk / LocalForm   ← 设计主题的全部来源
    │   └── MaterialTheme(colorScheme, typography, shapes)
    └── EnRouteRoot(ui, vm)
        └── when (tab) { 今日 / 资讯 / 课表 / 我的 }   ← 切页靠 when，不靠路由

TimetableViewModel (AndroidViewModel)
└── MutableStateFlow<AppState>   ← 一个大数据类装全屏状态，reset() 归零

数据层 · 无 Room / 无 DataStore / 无 Retrofit / 无 UI 组件库
├── SharedPreferences        → 偏好 / 凭据开关 / 更新 / 共建
├── filesDir + kotlinx.serialization → 课表 / 资讯 / 成绩 / 标注 JSON
├── HttpURLConnection        → 教务 URP / 21 个资讯源 / 更新清单
├── assets + BrotliInputStream → 2066 门大纲 + 168 份方案（4.64 MB 离线）
├── AndroidKeyStore AES/GCM  → 凭据加密
└── WorkManager              → 上课提醒 / 桌面小组件
设计主题：黑土 + 农机漆 + 田垄网格。HARD 档 = 全 0 圆角、1dp 实线 #8F7E61、农械橘 #C74E17 只占小面积、纸白 #F5F2EC、系统黑体 + 等宽数字、零纹理零渐变。HARD / SCHOLAR / EDITORIAL 三套 FormSpec 与明暗正交；自定义配色只覆盖 primary / accent 两槽，砖红等语义色固定（数据诚实红线）。

③ Kotlin 到底能做到什么程度

按「效果能否 1:1」分四档，落点只谈渲染，不谈业务。
A像素级一致

布局、色板、字阶、线、圆角、投影、折角、缓动曲线、手势、滚动、Canvas 绘制。dp / sp / tween / spring 都能一对一映射到 CSS，本质是同一套数学。

B换实现但效果能到

真背景模糊：API 31+ 走 RenderEffect；API ≤30 用「快照 → CPU stack-blur → Bitmap 叠遮罩」，约 10ms，可做到全版本一致。噪点已用 ShaderBrush 做到。

CApp 才有、浏览器没有

系统返回键、壁纸取色、通知、Glance 小组件、加密凭据、后台任务、离线 brotli 资产、硬件传感器。这些不是「做得差」，是对面根本没有。

D受系统版本约束的只有一条

在 API ≤30 上让系统合成器实时模糊「别的窗口/背后内容」。这属于 Android 图形栈的版本边界，绕路走 B 档的快照模糊。

结论：「HTML 好看、真机不像」与组件库无关，也与 Kotlin 绘制能力无关 —— 只差 一层模糊的内容来源。原型背后铺的是照片与文字，App 背后是纯纸色列表；即使把 RenderEffect 全打开，糊出来的也只是文字灰雾，与照片雾不同。要根治，两条路：A 快照模糊（把列表渲成 Bitmap 再 CPU 模糊，API 26+ 全版本一致）＋ B 卡片背后铺低饱和校园影像（与模糊解耦也有雾感）。这两条都是纯 Compose 实现，无需引入任何库。
