## 三、验证码机制（实测）

1. `GET download.jsp?...wbfileid=ID` → 返回「请输入验证码下载附件」HTML（约 14 KB），种下 `JSESSIONID`
2. `GET /system/resource/js/filedownload/createimage.jsp?randnum=<ms>` → **60×20 JPEG 四位数字**，无干扰线，仅颜色/倾斜扰动
3. `GET download.jsp?...wbfileid=ID&codeValue=CODE`（同一 Cookie）→ 正确则直出 `%PDF`
4. **一次成功不解锁会话**：同一 cookie jar 拿 11763701 成功后，再请求 11763702/11763705/11763713 仍返回验证码页（3805 B HTML）。即 **1 附件 = 1 验证码**

验证码可由人或模型直接看图识别（本机无可用离线 OCR：`ollama run glm-ocr` 输出空），
识别错会返回 HTML 而非 PDF，重取即可，无锁定/无冷却。

## 四、工作单元 `w.py`（可并行）

每个 wbfileid 独立 cookie jar、独立验证码文件、独立结果 json，**天然并行安全**。

```powershell
cd O:\dev\enroute-android\在途\curriculum\_collect
python w.py get 11763702        # 取验证码 -> captcha_11763702.jpg
python w.py put 11763702 6073   # 提交，成功打印 OK ... 页数 -> 路径
python w.py state               # 已落盘清单
```

- 成功判据：响应体前四字节 `%PDF`；随后用 pymupdf 读页数，写 `done_<fid>.json`
- 失败（验证码错）：退出码 1，打印 `FAIL ...`，重新 `get` 再来
- `reconcile.py`：把已在盘上的 PDF 补录成 `done_*.json`（已用于农学院 985 页）
