## 1. D1 耗时字段

- 整次刷新：`刷新总计 8123ms · 14 源（成功 11 / 失败 3）· 新增 26 条，本地共 380 条`

## 2. D2 落盘

### 位置与命名

```
<filesDir>/debug/2026-11-14.log     ← 按天一个文件，只追加不重写
```

- 行格式与 `dump()` **共用** `DebugLog.formatLine()`：`HH:mm:ss.SSS  [TAG] 消息`，UTF-8。
- flush 策略：**每 20 行或每 500ms**（不指望 `onTerminate`，Android 常不调用）——
  崩溃前最后几行尽量落盘。
- 上限：`MAX_DAYS = 7`、`MAX_BYTES = 2MB`，启动时 `rotate()` 一次，超了从最旧的删。
- 开关：`Prefs.debugLogToFile`（**默认开**，release 同样生效，没用 `BuildConfig.DEBUG` 写死）。
  关掉后 `attachFile(null)`，**连文件都不再创建**。

**JVM 已验证**（`DebugLogFileTest`）：轮转只留 7 天且删最旧、3MB → 裁剪到 ≤2MB、
清空历史、行格式一致性。

**真机实测（待填）**：`ls filesDir/debug` 的文件名与大小、杀进程重开后能否读到上次会话。

## 3. 脱敏（红线）

### 命令级证据

生成器：`DebugLogEvidenceTest` 把 6 行真实形态的敏感日志写进
`app/build/debuglog-evidence/2026-11-14.log`（343B，不自动删除）。

脱敏后的**实际文件内容**（原样粘贴）：

```
11:20:01.100  [URP] ← 302 0B 640ms GET 10.2.0.47/login?ticket=***
11:20:01.200  [URP] ← 200 12.3KB 820ms GET jwc.syau.edu.cn/index/jwtz.htm
11:20:01.300  [SESSION] Set-Cookie: ***
11:20:01.400  [SESSION] Set-Cookie: ***
11:20:01.500  [CRED] POST body password=***&execution=***
11:20:01.600  [API] GET api/score?token=***&access_token=***
```

校验命令与结果：

```powershell
Select-String -Path app\build\debuglog-evidence\*.log `
  -Pattern 'JSESSIONID=[^*.\s]|CASTGC=[^*.\s]|ticket=[^*.\s]|token=[^*.\s]|password=[^*.\s]'
# → NO PLAINTEXT CREDENTIALS FOUND (0 matches)
```

### 覆盖的模式

| 类别 | 例子 | 结果 |
|---|---|---|
| Cookie / Session | `JSESSIONID=…`、`CASTGC=…`、`student.urpSoft.cn=…`、`PHPSESSID=…` | `***` |
| CAS 票据 | `lt=…`、`ticket=…`、`execution=…`、`service_id=…` | `***` |
| 密码字段 | `password=`、`pwd=`、`passwd=`、`pl=` | `***` |
| 通用 token | `token=`、`access_token=`、`refresh_token=`、`secret=`、`api_key=` | `***` |
| 头部形态 | `Authorization: …`、`Cookie: …`（含 `Set-Cookie:`） | 值整体 `***` |

> 头部形态（`Set-Cookie:` / `Cookie:`）会**整段值**替换成 `***`（连 cookie 名一起），
> 这是有意的：cookie 名是数据库里可能新增的，白名单挡不住未知名字，只有整体抹掉才安全。
> 代价是「知道有个 cookie」这条信息丢了 —— 可接受，安全优先。

`DebugLogFileTest` 另覆盖：脱敏保留键名、普通文本不误杀、落盘文件搜不到三个真值。

## 4. D3 分级与错误保底

- `Level = DEBUG / INFO / WARN / ERROR`
- 映射：`log()→INFO`、`step()→DEBUG`、`error()→ERROR`、`http()` 按状态码
  （2xx→INFO、4xx/5xx→WARN、-1/异常→ERROR）。
- **ERROR 保底**：主缓冲 400 条之外，另存最近 **50 条 ERROR**（独立 `StateFlow`）。
- 过滤只在**读取侧**（调试页 chips：全部 / 警告+ / 仅错误），写入侧不丢数据。

**JVM 已验证**：灌 3 条 ERROR + 500 条 DEBUG 后，主缓冲里那 3 条已被冲掉，
但「仅错误」仍能拿到 3 条；灌 60 条只留最近 50 条且顺序正确（e10…e59）。

## 7. 真机复测后的修正（2026-11-14 晚）

真机抓到 **CAS 票据 `ST-277817-…` 明文显示在调试页上** —— 说明「只在落盘那层脱敏」不够。
日志离开设备的机会有**四次**，必须一次覆盖：

| 出口 | 走的路径 | 旧行为 | 现在 |
|---|---|---|---|
| ① 屏幕 | `DebugLog.entries` → 调试页 | ❌ 明文 | ✅ 已脱敏 |
| ② 复制 | `DebugLog.dump()` | ❌ 明文 | ✅ 已脱敏 |
| ③ 导出文档 | `dump()` 经 SAF | ❌ 明文 | ✅ 已脱敏 |
| ④ 落盘 | `DebugLogFile.append()` | ✅ 已脱敏 | ✅ 已脱敏（幂等，纵深防御） |

**改法**：脱敏挪到 `DebugLog.write()` —— **进内存之前**，成为唯一入口；
`DebugLogFile.redact` 保留在落盘层做第二道（幂等）。

### 三条路径的实测产物（`app/build/debuglog-evidence/`，不自动删）

```
① screen.txt（调试页实际渲染的行）
18:06:36.979  [URP] ← 302 0B  GET 10.2.0.47/login?errorCode=invalidSession&ticket=***
18:06:36.987  [SESSION] Set-Cookie: JSESSIONID=***; Path=***; HttpOnly
18:06:36.987  [SESSION] Set-Cookie: CASTGC=***; Path=***
18:06:36.989  [CRED] POST body password=***&execution=***
18:06:36.989  [API] GET api/score?token=***&access_token=***
18:06:36.989  [FEED] ← 200 12.3KB  820ms  GET jwc.syau.edu.cn/index/jwtz.htm?ticket=***

② dump.txt（复制 / 「导出文档」）= 同上 6 行（多三行文件头）
③ 2026-11-14.log（落盘）= 同上 6 行
```

校验命令（三条路径一起搜）：

```powershell
Select-String -Path app\build\debuglog-evidence\* `
  -Pattern 'JSESSIONID=[^*.\s]|CASTGC=[^*.\s]|ticket=[^*.\s]|token=[^*.\s]|password=[^*.\s]|ST-EVIDENCE'
# → NO PLAINTEXT CREDENTIALS IN screen.txt / dump.txt / *.log (0 matches)
```

### cookie 头改成「抹值留名」

`Set-Cookie: ***` → `Set-Cookie: JSESSIONID=***; Path=***; HttpOnly`：
保留 cookie **名**（排查时「有没有这个 cookie」是有用信息），值全部抹掉。
未知的新 cookie 名也能挡住 —— 是**逐对抹**，不是白名单。

### 另外两处真机问题

- **导出文件名同日重复**：`在途日志_2026-11-14_2026-11-14.txt` → 单日时只写一次
  `在途日志_2026-11-14.txt`；多日才 `_起_止`（`DebugLogFile.exportFileName`）。
- **「落盘 xxKB」空白**：改成直接问落盘通道 `usageBytes()`，按日志条数变化重算；
  未启用时明确写 `落盘未启用` —— **留空和 0 一样属于信息缺失**。

### 更新回落的 http 地址：保留（复议结论）

`47.95.12.198` 已在 `network_security_config.xml` 放行明文（地图补丁上报必须走它），
回落**可用**，不是死路。安全性论证仍成立：`PINNED_RELEASE_PREFIX` 把 APK 入口钉死在本仓库
`releases/download/` 下，攻击者没有本仓库写权限就提供不出可安装的包，**最坏只是下载失败**。
`Cleartext HTTP traffic to 47.95.12.198 not permitted` 那条 ERROR **保留当探针** ——
重建后还出现就说明 network config 没生效。
