首页 `https://www.neea.edu.cn/` 200 / 68KB，栏目全部来自首页导航（未猜 URL）：

| 栏目 | 列表页 |
|---|---|

**结论**：`A-`/`B` 级。结构极稳（政府 CMS 模板十年不变），但**要解析 HTML**、且标题在属性里 —— 现有 feed 解析器已支持「属性取标题」这条路（教师抓取同款坑）。

### 3.2 学信网 `chsi.com.cn` —— **B 级（能抓，但相关性弱，建议不接）**

**robots.txt 存在且是"定向禁止"**（不是全站禁）：
```
User-agent:*
Disallow:/xlrz/*?*      ← 学历认证，带参
Disallow:/xlcx/*?*      ← 学历查询，带参
Disallow:/xwcx/*?*      ← 学位查询，带参
Disallow:/report/       ← 报告类，整段禁
Disallow:/xlrz/attachments/  · /mdgs2003~2006/ …
```
→ **查询通道全在禁止之列**（正好符合我们的红线：不碰成绩/学历查询），资讯与静态页未禁。

**资讯频道（实测可抓）**：`https://www.chsi.com.cn/jyzx/` 200 / 38KB / **60 条**
- 条目模式：`/jyzx/YYYYMM/YYYYMMDD/<id>.html`（**`.html` 不是 `.htm`**）
- 详情（`/jyzx/202611/...html`，18.6KB）：`<title>` 即标题；正文里日期写作 **`2026年11月10日`**（中文格式，与 neea 的 `2026-09-28` 不同 → 解析器要两种都认）
- 子频道：`/jyzx/jysp`（教育时评）

**但相关性弱**：这个频道是**教育新闻**（社会实践、职业教育、AI 课堂），**不是证书/考试公告**。我另外探了 `/tzgg/`、`/xlcx/tzgg/` 两条最常见的"通知公告"路径 —— **都是 404**，学信网没有公开的公告列表频道。

**结论**：技术上 **B 级可抓**，但**内容与需求（竞赛/证书报名公告）不匹配**，且核心价值区（查询/认证）被 robots 明确禁止。
**建议：不接入。** 若以后要做"学历认证流程指引"再单独评估（属于静态说明页，与本票无关）。

**证据**：`docs/_probe/chsi/home.html`、`detail-sample.html`

### 3.3 赛氪 `saikr.cn` —— **D 级（robots 明令禁止 /api/，放弃；不找绕过的办法）**

**robots.txt（`www.saikr.com`，实测）**
```
User-agent: *
Allow: /
Disallow: /search      Disallow: /search/
Disallow: /admin/      Disallow: /api/        ← 关键
Disallow: /login       Disallow: /*?*
Crawl-delay: 10
User-agent: bingbot    Disallow: /           ← 还整段封了 Bing
```

**站点是 SPA**：首页 HTML 只有 **4.2KB、0 个 `<a>`**，内容全靠 JS。
用 Playwright 抓到它的数据来源全部指向 **`https://apiv4buffer.saikr.com/api/pc/...`**
（`/api/pc/home/indexData`、`/api/pc/search/info?keyword=&page=1&limit=15` 等，均 200）。

**为什么仍然判 D**：`apiv4buffer.saikr.com` 自己没有 robots.txt（404），
但**同一站群的主域 robots 明确写了 `Disallow: /api/`**，还专门封了 Bing。
拿 API 子域去取，就是绕过站点主写下的明确意愿 —— 本票红线第 4 条：**不找绕过办法**，所以放弃。
（另外首页 HTML 无内容、列表全靠 XHR，即便不看 robots 也属 C。）

**结论**：**D 级放弃**。理由：①robots 明禁 `/api/`；②正文 SPA 渲染无静态内容；③`Crawl-delay: 10` 也说明站点对抓取敏感。
**替代**：现有 15 源里已有「我爱竞赛网 `jingsai`」「挑战杯 `tzb`」「高教学会 `cahe`」覆盖竞赛增量，赛氪的价值可以靠这些 + 赛事官站（蓝桥/CCPC/CUMCM）补。

**证据**：`docs/_probe/saikr/home.html`（4.2KB SPA 骨架）、`docs/_probe/saikr/apiv4-robots.txt`（该子域 robots 不存在的记录）、Playwright 抓包清单（见本节）。

## 5. 抓取预算方案

现状：15 源一次抓取约 **13.7 秒**（串行、每源 1 个列表页）。

**建议接入方式（neea 两页）**：
| 项 | 量 |
|---|---|
| 新增请求 | **2 个列表页**（考试资讯 + 公示公告），**不翻页**（首页 15 条足够，公告是低频信息） |
| 新增耗时 | 约 **+1.5–2.0 秒**（按现有 0.8s/源 上限估）→ 总计约 **15.5 秒** |
| 频率 | **一天一次**，与现有周期同批跑，不新增调度 |
| 详情页 | **不抓**（列表页已有标题+链接+日期线索，点开走系统浏览器/内嵌 WebView），省 30–40 个请求 |

**为什么不做详情抓取**：资讯流只需要「标题 + 时间 + 打开」，详情页 15–20KB × 每源 15 条 = 每轮多 300KB 流量，收益很低。
**证书类频率**：四六级/教资/NCRE 公告是**季度级**低频事件，一天一次已经足够冗余。

### 7.3 两个解析器真 bug（已修，都有回归测试）

**bug 1：主键塌缩（严重）**
`idFromUrl` 取「路径里最长的一串数字」。neea 的路径是 `/html1/report/2610/14-1.htm` ——
**同一个月所有文章的最长数字都是 `2610`**，于是整个月的条目挤成同一个键，只留第一条。
实测 NTCE 15 条只解析出 8 条就是这么丢的。
→ 修法：撞车时补一段地址短哈希（**只在真撞车时补**，没撞车的源主键一个字节不变）。

**bug 2：日期偷下一条（隐蔽）**
fwwb 是「日期在链接之前」。原实现「先正向找 300 字」能找到一个日期 —— 但那是**下一条的日期**。
条目数看起来正常，日期整体错位一格，这种错最难发现。
→ 修法：`FeedSource.dateLookback`，打开后**先回看**（前 200 字取最后一个日期），再回退正向。
反向测试断言的是**具体日期**（663 号文必须是 2026-08-27），不是条数。

**顺带修的坑 3：标题里带编码换行**
neea 部分公告的 `title` 属性写 `&#60;br>`（编码过的 `<br>`），而锚文本是空的。
原 `cleanTitle` 不解实体、不剥标签 → 标题会带一串 `&#60;br>`。
→ 改为「先解实体、再剥标签」（反过来先剥就剥不到，因为 `<br>` 是解完才出现的）。
